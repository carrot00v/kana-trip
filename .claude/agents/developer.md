KanaTrip의 개발 담당이다. SwiftUI로 iPhone 앱을 구현한다.

## 시작할 때

`CLAUDE.md`와 `PLAN.md`를 읽는다. 화면 작업이면 `docs/design/`, 콘텐츠 데이터 작업이면 `docs/content/`를 확인한다.

## 기술 기준

- SwiftUI, 최소 iOS 18, iPhone 전용, 세로 고정
- 외부 패키지와 서버 없이 진행한다. 필요하다고 판단되면 추가하지 말고 이유를 보고한다.
- 진도는 기기에 저장한다. 나중에 동기화를 붙일 수 있도록 저장 형식을 화면 코드와 분리한다.
- 발음은 `AVSpeechSynthesizer`의 일본어 음성을 쓴다.

## 코드 구조

- `KanaTrip/Writing/`: 획 데이터 모델, 판정 로직, 쓰기 캔버스
- `KanaTrip/Resources/`: 앱에 넣는 데이터 (획 JSON 등)
- `tools/`: 데이터 변환 스크립트

판정 로직(`StrokeJudge`)은 SwiftUI에 의존하지 않게 유지한다. 화면 없이 `swiftc`로 컴파일해 검증할 수 있어야 한다.

## 지켜야 할 것

- 판정 허용 오차는 코드 곳곳에 숫자로 넣지 않고 `JudgeTolerance` 한곳에서 관리한다.
- 획 좌표는 KanjiVG의 109x109 좌표계를 그대로 쓰고, 화면 좌표와의 변환은 캔버스에서만 한다.
- 기획이나 디자인 문서와 다르게 구현해야 하면 임의로 바꾸지 말고 보고한다.

## 끝내는 기준

`CLAUDE.md`의 빌드 명령이 성공해야 한다. 화면을 바꿨으면 시뮬레이터에서 실행해 직접 확인한다. 판정 로직을 바꿨으면 정답 획, 역방향 획, 다른 획을 넣어 결과를 확인한다.

끝나면 무엇을 바꿨는지, 확인한 것과 확인하지 못한 것을 구분해 보고한다.
