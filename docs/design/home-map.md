## 1. 지도 구조

### 1.1 칸 종류와 개수

데이터(`hiragana_scenes.json`)와 PLAN.md 4번에서 셌다. 세션은 장면마다 `{장면}-a`, `{장면}-b`, `{장면}-quiz` 3개이고 `ProgressStore.isUnlocked`대로 한 줄로 열린다.

|---|---|---|---|---|

| 종합 퀴즈 칸 (세션) | 원 64pt + 아래 "종합 퀴즈" 알약 | 칸 카드 | 8 | 8 (데이터 없음) |

| 합계 (모든 칸) | | | 34 (+총정리 1) | 34 |

|---|---|---|

| 복습 | 따로 칸을 만들지 않는다. 복습 글자가 섞이는 종합 퀴즈 칸의 알약이 "종합 퀴즈 · 복습 2"가 되고, 칸 카드에 글자를 보여 준다 | PLAN.md 3번 "복습: 별도 메뉴 없이 다음 장면 종합 퀴즈에 섞는다" |
| 총정리 (채택되면) | 히라가나 지역 문 앞에서 갈라진 곁길 끝 칸 하나. 하지 않아도 가타카나 길은 열린다. 기리는 본 길만 따라간다 | quiz-rules.md 6.2 제안이 "진도를 막지 않는다"이다 |

| 열린 아이템 | 지도에 그리지 않는다. 꾸미기 입구(5.2)에 "살 수 있음" 표시 | 단어 그림과 같은 이유로 "배운 것"과 "받은 것"을 한 자리에 섞지 않는다(word-art.md 5번) |
| 히라가나 완료 600엔, 16장면 완료 | 지역 문 그림 카드. 누르는 대상이 아니다 | 마일스톤은 C2가 알린다 |

### 1.3 길의 모양과 간격

```
한 장면 구간 (높이 504pt). 왼쪽 열은 구간 바닥에서 잰 y(위로 커짐)
                                   x 0.24        x 0.5        x 0.76
y 504 ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─   구간 경계
y 456                              (★) 종합 퀴즈 64pt
                                [종합 퀴즈]          ╲
                                                        ╲
y 328                                                  ( ) 단계 b 56pt
                                                     [い か た こ]
                                                     ╱
y 200                              ( ) 단계 a 56pt ╱
                                  [す し]
                                       ╲
y 128                                    ┌──────┐
                                         │ 건물 │  96pt
y  80                                    │ 카드 │  (가운데 y 80)
                                         └──────┘
                                       [1 스시집]
y   0 ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─   구간 경계
```

구간 경계는 앞 장면 종합 퀴즈 칸 가운데 위 48pt에 둔다. 퀴즈 칸 위 끝(32pt)과 건물 알약 아래 끝(66pt) 사이라 칸과 건물이 경계를 넘지 않는다.

위 그림은 홀수 장면(왼쪽 → 오른쪽 → 왼쪽)이다. 세션 칸은 지도 전체에서 왼쪽·오른쪽을 번갈아 밟으므로 짝수 장면은 좌우가 뒤집힌다(a 오른쪽, b 왼쪽, 퀴즈 오른쪽). 건물은 늘 가운데다.

| 값 | 수치 | 이유 |
|---|---|---|
| 세션 칸의 x | 왼쪽 길 0.24, 오른쪽 길 0.76 (지도 폭에 대한 비율) | 375pt에서 왼쪽 칸 가운데 90pt. 기리(96pt)와 말풍선이 반대쪽에 들어가는 폭(2.3) |
| 건물 칸의 x | 0.5 | 두 길 사이. 장면이 바뀌는 굽이에 서서 "다음 가게"로 읽힌다 |
| 세션 칸 사이 (a→b, b→퀴즈) | 세로 128pt | 지금 칸의 말풍선 위 끝(칸 가운데 위 56pt)과 다음 칸 알약 아래 끝 사이 8pt. 다음 칸 알약 아래 끝 = 128 − 64 = 칸 가운데 위 64pt(단계 칸: 반지름 28 + 4 + 알약 32, 퀴즈 칸: 반지름 32 + 4 + 알약 28로 둘 다 64) |
| 퀴즈 → 다음 장면 a | 세로 248pt | 그 사이에 건물 카드(96pt)를 놓고, 퀴즈 칸이 지금일 때의 말풍선, a 칸 알약, a 칸이 지금일 때의 말풍선이 건물과 8pt 이상 떨어지는 최소값(아래) |
| 건물 가운데 | 퀴즈 칸 가운데 위 128pt (= 다음 a 칸 가운데 아래 120pt) | 퀴즈가 지금일 때 말풍선 위 끝(퀴즈 위 56pt)과 건물 알약 아래 끝(128 − 48 − 14 = 66pt) 사이 10pt. a 칸 알약 아래 끝(a 아래 64pt)과 건물 위 끝(a 아래 72pt) 사이 8pt. a가 지금일 때 말풍선 아래 끝(a 아래 24pt)과 건물 위 끝 사이 48pt |
| 장면 구간 높이 | 128 + 128 + 248 = 504pt | 배경 띠 한 장의 높이(6.2)와 같다 |
| 길 띠 | 폭 20pt, `MapRoad`(7.4). 칸 가운데를 지나는 부드러운 곡선 | 길이 보이게. 띠 위에 진행 선(2.4)을 그린다 |
| 굽이 | 칸 가운데를 지나는 Catmull-Rom 곡선을 3차 베지어로 바꿔 데이터에 넣는다(7.1). 지그재그 폭은 0.52W(375pt에서 195pt) | 꺾인 선보다 길로 읽힌다. 곡선 계산을 앱이 하지 않게 미리 만든다 |

- y 간격은 화면 폭에 따라 늘리거나 줄이지 않는다. 칸, 기리, 말풍선 크기가 pt로 고정이라 간격도 고정이어야 375pt에서도 겹치지 않는다. x만 폭에 비례한다. PM 지시의 "0~1 정규화"를 x에만 쓴 이유다(7.1, 9.2의 11).
- 지역 하나의 높이: 출발 구간 176 + 장면 8 × 504 + 지역 문 구간 384 = **4,592pt**. 가타카나 지역까지 붙이면 약 9,000pt다.

### 1.4 기기별 치수

지도 영역 = 화면 높이 − 안전 영역 위 − 내비게이션 바 44 − 아래 고정 영역 72(위 8 + 주 버튼 56 + 아래 8) − 안전 영역 아래. 보이는 세션 칸 = 지도 영역 ÷ 평균 간격 168pt(504 ÷ 3).

| 기기 | 화면 | 안전 영역 위/아래 | 지도 영역 | 쉼 자리(지금 칸 가운데, 화면 y) | 화면 절반 | 보이는 세션 칸 | 말풍선 폭 |
|---|---|---|---|---|---|---|---|
| iPhone SE 2·3 | 375×667 | 20 / 0 | 531 (y 64~595) | 64 + 319 = **383** | 333.5 | 약 3.2 | 209 |
| iPhone 13 mini | 375×812 | 50 / 34 | 612 | 94 + 367 = 461 | 406 | 약 3.6 | 209 |
| iPhone 17 Pro (기준) | 402×874 | 62 / 34 | 662 (y 106~768) | 106 + 397 = **503** | 437 | 약 3.9 | 229 |
| iPhone 17 Pro Max | 440×956 | 62 / 34 | 744 | 106 + 446 = 552 | 478 | 약 4.4 | 258 |

- 쉼 자리 = 지도 영역 위 끝 + 지도 영역 × 0.6. 네 기기 모두 지금 칸이 화면 아래 절반에 온다(엄지로 누를 수 있다).
- 지금 홈 목록(장면 행 3.4개 / 5.1개, 행 하나 = 세션 3개)보다 한눈에 보이는 범위는 좁다. 지도는 "지금 어디고 바로 앞에 뭐가 있나"를 보여 주고, 전체 진도는 바 가운데 숫자(2.5)가 맡는다.
- 말풍선 폭은 왼쪽 길 칸에서 기리 오른쪽 + 12pt부터 화면 오른쪽 여백 16pt까지. 375pt에서 209pt(글 폭 185pt, 띄어쓰기 손실을 빼고 한 줄 약 10자)라 홈 대사 상한 26자가 3줄에 들어간다(giri-companion.md 2.3).

## 2. 상태와 표시

### 2.1 칸의 상태

세션은 한 줄로 열리므로 "열렸지만 지금이 아닌" 칸은 없다. 상태는 셋이다.

| 상태 | 원 | 원 안 | 알약 | 색 밖의 구분 | 누르면 |
|---|---|---|---|---|---|
| 잠김 | `CardBackground`, `Outline` 2pt 점선(6-4) | `lock.fill` 17pt, `InkSecondary` | 글자 `InkSecondary` 보통 굵기 | 점선 테두리, 자물쇠 | 칸 카드(미리 보기, 시작 버튼 없음). 9.2의 5 |
| 지금 (하던 중 포함) | `AccentColor` 바탕 | 단계 번호 `1`/`2`(17pt 굵게, `AccentForeground`), 퀴즈는 `star.fill` | 글자 `Ink` 굵게 | 기리가 서 있음, 채운 원 | 칸 카드 |
| 완료 | `CardBackground`, `Outline` 2pt 실선 | `checkmark` 20pt 굵게, `Correct` | 글자 `Ink` 굵게 | 체크 모양 | 칸 카드("다시 하기") |

- 하던 중은 칸 모양을 바꾸지 않는다. 주 버튼과 칸 카드가 "이어서 하기"라고 말한다(지금 홈 5.2와 같은 원칙: 같은 말을 두 곳에 쓰지 않는다).
- 원 안의 표시는 지금 칸이면 기리 발에 위쪽이 가려진다(2.3). 지금 칸은 기리와 알약으로 알아본다.
- 글자 알약: 높이 32pt, 모서리 16pt, `CardBackground` + `Outline` 2pt, 좌우 안쪽 12pt. 가나는 시스템 글꼴 20pt, 일본어 로캘, 글자 사이 6pt(visual-rules.md 2.2 "목록 속 글자"). 원 아래 4pt. 4자 알약 폭 122pt.
- 종합 퀴즈 알약: "종합 퀴즈"(`.footnote` 굵게), 복습 글자가 섞이면 "종합 퀴즈 · 복습 {r}"(r은 숫자). 폭 최대 약 130pt.
- 칸 하나와 알약을 한 버튼으로 묶는다(누르는 영역 = 원 ∪ 알약, 56×92pt 이상).

### 2.2 건물 칸의 상태

장면 그림의 상태 규칙(scene-art/brief.md 2.2)을 그대로 크게 쓴다.

| 상태 | 그림 | 배지 (지름 28pt, 그림 오른쪽 위에 걸침) | 장면 이름 알약 |
|---|---|---|---|
| 잠김 | 채도 0. 불투명도는 그대로 | `lock.fill`, `InkSecondary` | `InkSecondary` |
| 열림 (진행 중인 장면) | 원래 색 | 없음 | `Ink` |
| 완료 (종합 퀴즈 통과) | 원래 색 | `checkmark.seal.fill`, `Correct` | `Ink` |

- 카드: 96×96pt, 모서리 16pt, `Outline` 2pt. 장면 이름 알약(높이 28pt, `.footnote` 굵게, "{순서} {장면}")은 가운데를 카드 아래 변에 둔다(카드 밖으로 14pt).
- 완료한 장면을 더 꾸미는 표시(단어 그림 스티커)는 3단계 선택안이다(8.3, 9.2의 8). 리워드 아이템은 지도에 쓰지 않는다(1.2).
- 장면 내용이 없는 개발 빌드: 지금처럼 건물은 열림으로 보이고 누르면 "준비 중이에요" 알림, 주 버튼은 숨는다(scene-flow.md 5.2).

### 2.3 지금 칸의 기리와 말풍선

```
왼쪽 길의 지금 칸 (375pt, 말풍선 3줄)             화면 y (칸 가운데 cy 기준)
        ┌────────┐
        │        │  ┌──────────────────────┐       cy − 84  기리 위 끝
        │  기리  │◁ │ 첫 여행지는 스시집이 │       cy − 56  말풍선 띠 위 끝
        │  96pt  │  │ 에요. 같이 가 봐요   │       cy − 33  기리 입 = 꼬리
        │        │  │                      │
        └──( )───┘  └──────────────────────┘       cy + 12  기리 아래 끝
          [す し]                                   cy + 24  말풍선 띠 아래 끝
                                                    cy + 32~64 글자 알약
   x 42~138          x 150 ─────────── 359
```

| 요소 | 값 |
|---|---|
| 기리 크기 | 96pt. giri-companion.md 2.4.1의 H 크기 그대로 |
| 기리 자리 | 가로 가운데 = 칸 가운데. 아래 끝 = 칸 가운데 아래 12pt. 원의 위쪽 3분의 2를 발로 덮어 "칸 위에 선" 모양 |
| 표정 | 말하기(지금 H와 같음). 깡충하는 동안 웃음(4번) |
| 숨쉬기 | 지금 규칙 그대로(지도에 다른 반복 움직임이 없다) |
| 말풍선 쪽 | 칸이 왼쪽 길이면 오른쪽, 오른쪽 길이면 왼쪽. 오른쪽 길에서는 꼬리가 말풍선 오른쪽 변에 붙는다(`BubbleShape` 좌우 뒤집기, 새로 필요) |
| 말풍선 가로 | 기리 쪽 변 + 12pt(꼬리 8pt 포함)부터 화면 여백 16pt까지 |
| 말풍선 세로 | 기리 입 높이(칸 가운데 위 33pt)에 가운데를 맞춘 뒤, 칸 가운데 위 56pt ~ 아래 24pt의 띠(80pt) 안으로 밀어 넣는다. 1줄(40pt)은 cy − 53 ~ cy − 13, 2줄은 cy − 56 ~ cy + 4, 3줄은 cy − 56 ~ cy + 24 |
| 꼬리 | 기리 입 높이. 말풍선 위·아래 끝에서 16pt 안쪽으로 제한(giri-companion.md 2.1) |
| 최대 줄 | 3줄(홈 대사 상한 26자, giri-companion.md 2.3). 문구는 3.11의 H 대사 그대로 |
| 누르기 | 기리와 말풍선 모두 누르는 대상이 아니다(`allowsHitTesting(false)`). 기리 밑의 칸 알약은 눌린다 |

- 화면마다 기리는 하나라는 규칙(giri-companion.md 3.1)을 지키려고 아래 고정 영역의 기리 줄을 없앴다. 지도의 기리가 홈의 유일한 기리다.
- 큰 글자 크기(`accessibility1` 이상): 지도의 기리는 위치 표시라 그대로 두고, 말풍선은 지도에서 빼서 아래 고정 영역 주 버튼 위에 꼬리 없는 전체 폭 카드로 둔다(giri-companion.md 6.2의 H 규칙을 옮긴 것). 글자가 커져도 지도 위 말풍선이 다음 칸을 덮지 않는다.

### 2.4 진행 선

| 구간 | 모양 | 색 |
|---|---|---|
| 지난 길 (출발 ~ 지금 칸) | 6pt 실선, 끝 둥글게 | `AccentColor` |
| 앞길 (지금 칸 ~ 끝) | 6pt 점선(점 0, 간격 12, 끝 둥글게 → 둥근 점) | `InkSecondary` |

- 실선과 점선으로 모양이 달라 색만으로 구분하지 않는다. 대비는 7.4의 표.
- 진행 선은 길 띠(20pt) 위, 칸 아래에 그린다.

### 2.5 진행률

- 내비게이션 바 가운데(`principal`): "히라가나 {끝낸 장면}/8"(`.headline`, `monospacedDigit`). 가타카나 지역에 들어가면 "가타카나 {k}/8".
- 칸별 진행은 지도 자체가 보여 준다. 글자 수, 정답률 같은 통계는 넣지 않는다.
- VoiceOver: "히라가나, 8장면 중 2장면 완료".

## 3. 조작 흐름

### 3.1 앱을 열 때

1. 홈이 뜨면 지도를 지금 칸이 쉼 자리(1.4)에 오도록 움직임 없이 맞춘다(iOS 18 `ScrollPosition.scrollTo(y:)`).
2. 기리가 지금 칸에 서 있고 말풍선이 오늘 할 일을 권한다.
3. 아래 고정 주 버튼 "{장면} · {단계} 시작|이어서 하기"를 누르면 그 세션이 바로 열린다(fullScreenCover). 문구와 숨는 조건은 scene-flow.md 5번 그대로다.

### 3.2 지도를 구경할 때

- 위아래로 자유롭게 스크롤한다. 잠긴 칸과 건물도 보인다(지금 홈처럼 앞으로 갈 길이 보인다).
- 지금 칸의 가운데가 지도 영역 위·아래 끝에서 40pt 안쪽을 벗어나면 "지금 칸으로" 버튼이 0.2초 페이드로 나타난다.

| 요소 | 값 |
|---|---|
| 자리 | 지도 영역 아래 끝에서 12pt 위, 가로 가운데 (아래 고정 영역 바로 위) |
| 모양 | `.bordered` 캡슐, 높이 44pt, 바탕 `CardBackground` + `Outline` 2pt. 지금 칸이 위에 있으면 `arrow.up`, 아래에 있으면 `arrow.down` + "지금 칸으로"(`.subheadline` 굵게) |
| 누르면 | 지금 칸을 쉼 자리로 0.35초 `easeInOut` 스크롤. 동작 줄이기가 켜져 있으면 바로 옮긴다 |
| 사라짐 | 지금 칸이 다시 범위 안에 들어오면 0.2초 페이드 |

### 3.3 칸 카드 (지난 칸 다시 하기, 앞 칸 미리 보기)

칸을 누르면 iOS 기본 시트(`.sheet` + `presentationDetents([.height(276)])`, 드래그 표시 보임)가 뜬다. 지도를 떠나지 않고 한 칸만 본다.

```
┌──────────────────────────────────────┐
│               ───                    │  드래그 표시
│ 스시집 · 간판                        │  제목 .headline
│ ✓ 끝냈어요                           │  상태 줄 .subheadline
│                                      │
│        す       し                   │  글자 줄 34pt (scene-flow.md 와 같은 크기)
│                                      │
│ 읽게 되는 단어  すし                 │  목표 단어 22pt (퀴즈 칸은 "글자 6자 · 단어 3개 · 복습 2자")
│ ┌──────────────────────────────────┐ │
│ │            다시 하기             │ │  주 버튼 56pt
│ └──────────────────────────────────┘ │
│           장면 단어 전체 보기        │  글자 버튼 44pt → S
└──────────────────────────────────────┘
```

| 칸 상태 | 상태 줄 | 주 버튼 | 누르면 |
|---|---|---|---|
| 지금, 처음 | `1.circle.fill` + 할 차례예요 | 시작 | 시트를 닫고 세션 |
| 지금, 하던 중 | `1.circle.fill` + 하던 데부터 이어서 해요 | 이어서 하기 | 시트를 닫고 세션(scene-flow.md 2.5의 자리) |
| 완료 | `checkmark.circle.fill`(`Correct`) + 끝냈어요 | 다시 하기 | 시트를 닫고 세션(진행 저장 안 함, 보상 없음) |
| 잠김 | `lock.fill` + {앞 세션}을/를 끝내면 열려요 | 없음(자리를 비우지 않고 시트 높이를 줄인다) | 없음 |

- 높이: 위 20 + 제목 24 + 4 + 상태 20 + 16 + 글자 40 + 12 + 단어 28 + 16 + 주 버튼 56 + 4 + 글자 버튼 44 + 아래 8 = 292pt에서 시트 위 여백(드래그 표시 자리)을 시스템이 잡으므로 콘텐츠 276pt. 주 버튼은 시트 아래쪽, 엄지 범위다. 큰 글자 크기에서는 `.medium` 감지로 바꾸고 내용만 스크롤한다.
- "장면 단어 전체 보기"는 시트를 닫고 그 장면의 S를 push한다. S는 지금 화면 그대로다.
- 세션을 닫거나 C1의 "여기까지 하기"·"장면으로 돌아가기"를 누르면 세션을 연 화면(지도 또는 S)으로 돌아간다. 지도의 주 버튼이나 칸 카드로 연 세션은 지도로 돌아와 4번의 연출을 본다(9.1의 충돌 3).

### 3.4 탭 수 비교

| 하려는 일 | 지금 홈 (목록) | 지도 | 차이 |
|---|---|---|---|
| 다음 세션 시작 / 이어서 하기 | 1 (주 버튼) | 1 (주 버튼) | 같음 |
| 끝낸 단계·퀴즈 다시 하기 | 2 (장면 행 → S의 단계 행) | 2 (칸 → 칸 카드 "다시 하기") | 같음 |
| 장면 단어 보기 (S) | 1 (장면 행) | 1 (건물) | 같음 |
| 잠긴 단계의 글자·단어 미리 보기 | 2 (장면 행은 잠기면 못 누름. 열린 장면이면 행 → S) | 1 (잠긴 칸 → 칸 카드) | 1 줄거나 새로 생김 |
| 기리 꾸미기 | 1 (꾸미기 행, 목록 맨 위) | 1 (바 왼쪽 버튼) | 같음. 자리가 화면 위쪽으로 고정 |
| 발음 소리 끄기 / 앱 정보 | 2 (메뉴 → 항목) | 2 | 같음 |
| 장면 완료 뒤 홈으로 | 1 (C2 "장면 목록으로") | 1 (C2 같은 버튼, 문구는 9.2의 4) | 같음 |
| 멀리 본 뒤 지금 자리로 | 스크롤 | 1 ("지금 칸으로") 또는 스크롤 | 새로 생김 |

## 4. 연출

PLAN.md 3번과 giri-companion.md 5번의 규칙(기리 움직임 0.35초 이하, 반복 움직임 화면당 하나, 한 번 움직임 동시에 둘까지, 입력을 막지 않음)을 지킨다. 색종이, 화면 흔들림, 확대, 글자 알림 줄은 넣지 않는다.

### 4.1 세션 완료 뒤 (단계 a → b, b → 퀴즈)

세션 덮개가 닫히고 지도가 보인 뒤:

| 순서 | 움직임 | 시간 | 곡선 |
|---|---|---|---|
| 1 | 말풍선 사라짐 | 0.15초 | `easeOut` |
| 2 | 기리 깡충: 지난 칸 → 새 지금 칸. 가로는 곧게, 세로는 두 칸 중 높은 쪽보다 24pt 더 올라가는 포물선. 표정 웃음. 지도도 같은 시간 동안 새 칸이 쉼 자리에 오게 스크롤 | 0.35초 | 진행 `easeInOut` |
| 3 | 착지 뒤 표정 말하기(0.12초 교차 페이드) + 새 말풍선 뜨기 | 0.25초 | `.spring(response: 0.25, dampingFraction: 0.85)` |

- 합계 약 0.75초. 동시에 움직이는 한 번 움직임은 깡충 + 표정, 또는 말풍선 하나다. 스크롤은 기리를 따라가는 화면 이동이라 기리 움직임 수에 넣지 않는다.
- 지난 칸의 상태(완료 체크)와 진행 선(실선)은 연출 전에 이미 바뀌어 있다. 덮개가 닫히는 동안 보이는 것이 결과 상태다.
- 깡충하는 동안에도 주 버튼과 칸은 바로 눌린다. 누르면 연출을 끝 상태로 건너뛴다.
- 햅틱은 없다. 성공 햅틱은 C1·C2가 이미 냈다.

### 4.2 장면 완료 뒤 (퀴즈 통과 → 다음 장면 a)

| 순서 | 움직임 | 시간 |
|---|---|---|
| 1 | 말풍선 사라짐 | 0.15초 |
| 2 | 다음 장면 건물이 열림: 채도 0 → 1, 자물쇠 배지 사라짐(불투명도 1 → 0) | 0.3초 `easeInOut` |
| 3 | 기리 깡충 ①: 퀴즈 칸 → 건물 앞(x 0.5, 건물 가운데 아래 40pt). 지도 스크롤 시작 | 0.3초 |
| 4 | 기리 깡충 ②: 건물 앞 → 다음 장면 a 칸. 스크롤 끝 | 0.3초 |
| 5 | 표정 말하기 + 새 말풍선 ("다음 여행지는 {장면}이에요. {단계 a}부터 봐요") | 0.25초 |

- 합계 약 1.3초, 장면마다 한 번(히라가나 전체에서 8번)이라 반복으로 지치지 않는다고 봤다. 248pt를 한 번에 뛰면 0.35초 안에 너무 멀어 "순간 이동"처럼 보여 두 번으로 나눴다.
- 두 깡충 사이에 멈춤을 두지 않는다. 건물 앞을 "지나간다"로 읽히게 한다.

### 4.3 생략 조건

| 조건 | 결과 |
|---|---|
| "동작 줄이기" 켜짐 | 움직임 없이 결과 상태. 기리는 새 칸에, 건물은 색으로, 스크롤은 바로 옮김. 말풍선은 바로 바뀜 |
| VoiceOver 켜짐 | 움직임 없이 결과 상태. "{장면} {단계} 차례예요"를 알림으로 한 번 읽는다(`AccessibilityNotification.Announcement`) |
| 다시 하기를 끝냄 | 지금 칸이 바뀌지 않으므로 연출 없음 |
| 앱을 새로 열었는데 지금 칸이 지난번에 보여 준 칸의 바로 다음 칸 | 연출을 한다(세션 직후 앱이 종료된 경우). 지난번에 보여 준 칸은 화면 상태로만 저장(`lastShownNodeID`, 진도와 별개) |
| 그 밖에 지난번 칸과 지금 칸이 두 칸 이상 다름(진도 초기화 등) | 연출 없이 결과 상태 |
| 연출 도중 주 버튼·칸·스크롤 | 즉시 끝 상태로 |

### 4.4 반복 움직임

- 지도 화면의 반복 움직임은 기리 숨쉬기 하나다. 바탕 그림과 건물은 움직이지 않는다. 건물에 Lottie(김 등)를 넣으려면 그 화면에서 기리 숨쉬기를 끈다(giri-companion.md 5.3). 이 안에서는 넣지 않는다.

### 5.3 VoiceOver와 큰 글자

- 읽는 순서: 내비게이션(꾸미기, 진행률, 메뉴) → 기리 말풍선 → 주 버튼 → 지도 칸들. 주 버튼까지 칸 34개를 지나지 않게 말풍선과 주 버튼의 `accessibilitySortPriority`를 높인다.
- 지도 칸은 여행 순서(출발 → 위)로 읽는다. 칸 하나 = 버튼 하나.
  - "1번 스시집 간판, す し, 완료, 다시 하기"
  - "1번 스시집 메뉴, い か た こ, 지금 할 차례" / "…, 하던 중"
  - "1번 스시집 종합 퀴즈, 복습 2자, 잠김, 메뉴를 끝내면 열려요"
  - 건물: "2번 돈카츠집, 잠김, 장면 단어 보기" / "1번 스시집, 완료, 장면 단어 보기"
- 칸의 가나 알약, 기리 그림, 바탕 그림, 진행 선은 따로 읽지 않는다.
- 가나 알약과 칸 크기는 Dynamic Type을 따르지 않는다(visual-rules.md 2.4, 배치 계산이 깨진다). 알약 속 한글("종합 퀴즈")과 장면 이름은 `xxxLarge`에서 멈춘다.

### 6.2 바탕 띠: 타일로 잇는다

긴 한 장이 아니라 장면마다 한 장씩 위아래로 쌓는다.

- 긴 한 장을 쓰지 않는 이유: 모델이 세로 9,000pt 비율을 만들지 못하고, 디코딩한 한 장이 메모리를 크게 쓰며(@3x 1320×13,600px ≈ 72MB), 장면 하나를 고치려면 전부 다시 뽑아야 한다. 안드로이드의 `LazyColumn`, iOS의 `LazyVStack`과도 구간 단위가 맞는다.
- 띠 하나 = 장면 구간 하나(1.3의 504pt). 장면마다 주변 풍경이 달라져 "스시집 거리 → 역 → 신사 숲 → 온천 산 → 료칸 정원"으로 걸어가는 느낌을 낸다.
- **이어지는 방법: 바탕을 투명하게 만든다.** 모델에는 단색 바탕(옅은 모래색)으로 그리게 하고, `tools/remove_bg.py`로 가장자리에서 이어진 바탕을 지운다. 띠에는 풍경 조각만 남고, 앱이 그 아래에 `MapGround` 색을 깐다. 그래서 띠끼리의 이음매가 생기지 않고, 스킨이 바탕색을 바꿀 수 있고(7.4), 다크 모드에서 띠만 옅게 할 수 있다.
- 풍경은 좌우 가장자리(각 15%)에 모으고, 두 길이 지나는 가운데 70%는 비워 두거나 바탕과 거의 같은 옅은 무늬만 둔다. 띠의 위·아래 10%에는 아무것도 그리지 않는다(이웃 띠의 풍경과 부딪히지 않게).
- 크기: 생성 1024×1168px(가로 440pt를 덮는 비율 440:504에 가깝게, 16의 배수). 앱 원본은 1320×1512px(@3x, 440pt 폭 기준)으로 Pillow LANCZOS 확대. 평면 그림이라 1.29배 확대가 티 나지 않는다. 화면 폭이 더 좁으면 가운데를 기준으로 좌우를 잘라 낸다(높이 504pt 고정, `scaledToFill`). 출발 띠(176pt)와 지역 문 띠(384pt)는 같은 폭에 높이만 비율대로(1024×416, 1024×896).
- 다크 모드: 띠를 불투명도 0.35로 그린다(7.4의 `MapTileOpacity`). 따로 그리지 않는다.

### 6.3 건물 그림

- 1단계는 장면 그림 8장을 그대로 크게 쓴다. 이미 앱에 52pt로 들어가 있고, 1024px 원본이 있어 96pt(288px)로 다시 내보내기만 하면 된다. 칸 바탕(SKY/SAND)이 있는 정사각 카드라 지도 위에서 "간판 카드"로 읽힌다.
- 건물 정면 그림(2단계 선택)은 "길가에 서 있는 건물"을 더 살리고 싶을 때만 만든다. 리워드 배경 아이템(のれん, えき, とりい, ゆ, reward-system.md 4번)과 겹치지 않게, 가까이서 본 노렌·승강장·참배길이 아니라 **멀리서 본 작은 건물 한 채**로 그린다.
- 단어 그림 재활용: 지도 건물로는 쓰지 않는다. 단어 그림은 "읽기 확인 뒤의 보상"이라 미리 보여 주면 W의 확인 순간이 약해진다. 완료한 장면 옆 스티커(3단계 선택)로만 검토한다(9.2의 8).

### 7.1 지도 정의 데이터: `map.json`

배치 계산(굽이, 칸 좌표, 구간 나누기)을 앱이 아니라 파이썬 도구가 미리 해서 JSON 하나로 내보낸다. iOS와 안드로이드는 같은 파일을 읽어 그리기만 한다. 배치 규칙을 두 플랫폼에서 두 번 짜지 않는다.

- 만드는 도구: `tools/build_map.py`(이름은 developer가 정함). 입력은 장면 데이터(`hiragana_scenes.json`, 가타카나가 생기면 그 파일)와 배치 값(1.3의 수치를 담은 `tools/map_layout.json`). 출력은 `KanaTrip/Resources/map.json`. 안드로이드는 같은 파일을 `assets/`로 복사한다.
- 좌표:
  - x: 지도 폭에 대한 비율 0~1.
  - y: **구간 바닥에서 위로 잰 pt(= dp)**. 0~1로 정규화하지 않은 이유는 1.3과 같다(칸·기리 크기가 고정이라 세로 간격도 고정이어야 겹치지 않는다). 바탕 띠는 노드 위치와 맞출 필요가 없도록 가운데를 비워 그린다(6.2).
  - 위로 커지는 y를 쓰는 이유: 여행 방향이 위다. 안드로이드는 `LazyColumn(reverseLayout = true)`, iOS는 구간을 위에서 아래로 쌓고 화면 y = 구간 높이 − y로 바꿔 그린다.
- 구간(section) 단위: 칸과 건물은 구간 경계를 넘지 않는다. 길 곡선만 경계에서 잘라 구간마다 나눠 넣는다(도구가 자른다). 기리와 말풍선은 구간 밖의 덮개 층에 그린다(구간을 넘어 깡충하므로).
- 문구는 넣지 않는다. 장면·단계 이름과 글자는 장면 데이터에서 id로 찾는다.

```json
{
  "schema": 1,
  "units": { "x": "fraction of map width", "y": "pt=dp from section bottom, upward" },
  "metrics": { "lanes": [0.24, 0.76], "stepGap": 128, "sceneGap": 248, "sectionHeight": 504 },
  "regions": [
    {
      "id": "hiragana",
      "script": "hiragana",
      "sections": [
        {
          "id": "hiragana-start", "height": 176, "tile": "map_tile_start",
          "nodes": [ { "id": "hiragana-start", "kind": "start", "x": 0.5, "y": 72 } ],
          "paths": [ { "from": "hiragana-start", "to": "sushi", "d": [[0.5, 72], [0.5, 120], [0.5, 150], [0.5, 176]] } ]
        },
        {
          "id": "sushi", "height": 504, "tile": "map_tile_sushi",
          "nodes": [
            { "id": "sushi",      "kind": "building", "scene": "sushi",        "x": 0.50, "y": 80 },
            { "id": "sushi-a",    "kind": "step",     "session": "sushi-a",    "x": 0.24, "y": 200, "bubble": "right" },
            { "id": "sushi-b",    "kind": "step",     "session": "sushi-b",    "x": 0.76, "y": 328, "bubble": "left" },
            { "id": "sushi-quiz", "kind": "quiz",     "session": "sushi-quiz", "x": 0.24, "y": 456, "bubble": "right" }
          ],
          "paths": [
            { "from": "hiragana-start", "to": "sushi", "d": [[0.5, 0], [0.5, 30], [0.5, 55], [0.5, 80]] },
            { "from": "sushi", "to": "sushi-a", "d": [[0.5, 80], [0.5, 130], [0.38, 175], [0.24, 200]] }
          ]
        }
      ],
      "end": { "id": "hiragana-gate", "kind": "gate", "art": "map_gate_katakana" }
    }
  ]
}
```

- `d`는 3차 베지어 한 조각(시작점, 제어점 2개, 끝점)을 [x, y] 네 쌍으로 적는다. iOS `Path.addCurve`, 안드로이드 `Path.cubicTo`에 그대로 넣는다. x는 그릴 때 폭을 곱한다.
- `kind`: `start`, `building`, `step`, `quiz`, `gate`, `review`(총정리, 채택되면). `paths`의 `from`/`to`로 연결을 적어 곁길(총정리)도 같은 형식으로 담는다.
- `bubble`은 말풍선 쪽. 칸의 길(x)에서 정해지지만 앱이 계산하지 않게 넣어 둔다.
- 칸 상태(잠김/지금/완료)는 데이터에 없다. 진도에서 계산한다(scene-flow.md 4.3과 같은 규칙, 이미 플랫폼 중립 규칙이다).
- 가타카나 장면이 정해지면 같은 도구에 가타카나 장면 데이터를 넣어 `regions`에 하나를 더한다. 화면 코드는 바뀌지 않는다.

### 7.2 그림 재료의 포맷과 해상도

| 항목 | 규칙 |
|---|---|
| 원본 | PNG(sRGB, 8비트, 알파). `docs/design/map-art/source/{이름}.png`와 같은 이름의 `.json`(프롬프트, 시드). 후보는 커밋하지 않는다 |
| 이름 | 소문자, 숫자, 밑줄만(`map_tile_sushi`). 안드로이드 리소스 이름 규칙에 맞춰 처음부터 이렇게 짓는다. 지금 iOS 에셋 `SceneThumb-sushi` 같은 이름은 안드로이드에서 쓸 수 없으니 새 지도 에셋은 따르지 않는다 |
| 변환 도구 | `tools/build_map_art.py`(이름은 developer가 정함), 파이썬 + Pillow. 원본 → `build/map-art/`에 플랫폼 중립 크기의 PNG → iOS 에셋 카탈로그 / 안드로이드 `res/` 복사. item-art/brief.md의 `build/item-art/` 방식과 같다 |
| 배율 | 1pt = 1dp. iOS @2x = 안드로이드 xhdpi, @3x = xxhdpi. xxxhdpi는 만들지 않는다(바탕 띠와 카드는 xxhdpi를 늘려 써도 흐려 보이지 않는 평면 그림) |
| 바탕 띠 | 1320×1512px(@3x, 440pt 폭) 한 장, 투명 배경. iOS는 배율 없이 한 장(Single Scale)을 `scaledToFill`, 안드로이드는 `drawable-nodpi`에 WebP(손실, 품질 85, 알파 포함) 한 장을 `ContentScale.Crop` |
| 건물·지역 문 카드 | 96pt: 192px / 288px, 120pt: 240px / 360px. iOS PNG, 안드로이드 `drawable-xhdpi`/`drawable-xxhdpi`에 WebP(무손실) |
| 기리, 아이템 | 지금 규칙 그대로(SVG 레이어). 안드로이드는 VectorDrawable 변환 또는 같은 SVG를 렌더링(이 문서 범위 밖) |
| Lottie | 지도에는 쓰지 않는다(4.4) |

### 7.3 토큰

색과 수치는 이름으로 부르고, 값은 한 표(이 문서 1.3, 2.x, 7.4)에 둔다. 두 플랫폼이 같은 이름을 쓴다.

| 종류 | 이름 (예) | iOS | 안드로이드 |
|---|---|---|---|
| 색 | `MapGround`, `MapRoad`, 기존 `AccentColor`, `Outline` … | 에셋 카탈로그 Color Set(라이트·다크) | `colors.xml` + `values-night` |
| 수치 | `map.lanes`, `map.stepGap`, `map.nodeStep 56`, `map.nodeQuiz 64`, `map.building 96`, `map.road 20`, `map.progressLine 6`, `map.restAnchor 0.6`, `map.dock 72` | `map.json`의 `metrics` + 코드 상수 | 같음 |
| 시간 | `motion.hop 0.35`, `motion.hopScene 0.3`, `motion.buildingOpen 0.3`, `motion.bubbleIn 0.25`, `motion.bubbleOut 0.15` | 코드 상수 | 같음 |

- 색 토큰을 JSON 하나에서 두 플랫폼 파일로 만드는 도구는 지금 필요 없다. 안드로이드를 시작할 때 visual-rules.md 1.1 표를 원본으로 `colors.xml`을 만든다(9.2의 12).

### 7.5 스킨이 바꿀 수 있는 것과 고정인 것

`app-skin.md`(작성 중)가 "배경 아이템 = 앱 전체 스킨"을 정하면 지도는 아래 자리만 스킨에서 읽는다. 스킨마다 바탕 띠 10장을 새로 그리면 배경 아이템 4개 × 10장 = 40장이 되므로, 스킨은 색과 작은 장식만 바꾸고 띠는 공유하기를 권한다.

| 자리 | 기본값 (라이트 / 다크) | 스킨이 바꿈 | 지켜야 할 조건 |
|---|---|---|---|
| `MapGround` 지도 바탕색 | `#F3E4C8` / `#2A201B` | 바꿈 | `Outline`(칸 테두리)과 3:1 이상. 기본값은 라이트 12:1, 다크 3.6:1 |
| `MapRoad` 길 띠 | `#FBF3E2` / `#3A2E28` | 바꿈 | 진행 선 `AccentColor`·`InkSecondary`와 3:1 이상. 기본값은 `InkSecondary` 라이트 5.6:1, 다크 5.6:1 |
| `MapTileOpacity` 바탕 띠 불투명도 | 1.0 / 0.35 | 바꿈 | 띠 위 칸 알약 글자는 `CardBackground` 위라 띠와 상관없이 대비가 지켜진다 |
| 바탕 띠 세트 | 기본 띠 10장 | 바꿀 수 있게 슬롯만 둠 (`tile` 이름 앞에 스킨 접두어, 없으면 기본) | 6.2의 가운데 비우기 규칙 |
| 장식 소품 (선택) | 없음 | 스킨당 2~3개, 구간 가장자리에 `map.json`의 `props`로 놓음 | 가운데 70%에 놓지 않음 |
| 아래 고정 영역·내비게이션 바 바탕 | `AppBackground` | 앱 전체 스킨이 정함(app-skin.md) | |

| 건물 카드 | 장면 그림 | **고정** | 장면을 알아보는 표지 |
| 기리, 말풍선 | | **고정** (기리는 입은 머리·속재료·밥을 그대로 그림. 배경 아이템을 기리 뒤에 그리지 않는 규칙은 app-skin.md 결정을 따른다) | |
| 배치와 간격 | 1.3 | **고정** | |

### 8.1 1단계: 코드만으로

| 할 일 | 담당 |

| 칸 카드 시트, 건물 → S, 세션을 닫으면 연 화면으로 돌아가기 | developer |

| 색 토큰 2개(`MapGround`, `MapRoad`) | developer |

- 작업량: 중간(약 4~5일). 연출은 없다(기리가 새 칸에 바로 선다).
- 위험:
  - 긴 스크롤 안의 위치 맞추기. 구간 단위 `LazyVStack` 위에 기리 덮개를 절대 좌표로 얹어야 한다. 화면 하나짜리 Canvas로 9,000pt를 그리면 텍스처 크기 한도를 넘는다.
  - 세션을 닫으면 S가 아니라 지도로 돌아가는 흐름 변경(9.1의 3). `HomeView`가 덮개 전에 S를 push하는 코드를 바꾼다.
  - 지금 홈보다 한 화면에 보이는 범위가 좁다(1.4). 실기기에서 답답한지 본다.

| 할 일 | 담당 |

- 위험: 덮개 닫힘과 연출 시작의 순서(덮개가 닫히는 중에 깡충이 시작되면 안 보인다). 스크롤과 깡충을 같은 시간으로 맞추기.
