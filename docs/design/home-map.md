## 1. 지도 구조

### 1.2 종합 퀴즈, 복습, 리워드가 지도에 나타나는 방법

| 종합 퀴즈 | 장면의 세 번째 세션 칸. 원 64pt로 단계 칸보다 크고 알약이 "종합 퀴즈" | 장면을 닫는 칸이라 한눈에 달라 보여야 한다 |
| 복습 | 따로 칸이나 입구를 만들지 않는다. 복습 글자가 섞이는 종합 퀴즈 칸(완료 전)의 알약이 "종합 퀴즈 · 복습 {r}"가 된다. r = `store.quizSummary(for:).review` | PLAN.md 3번 "복습: 별도 메뉴 없이 다음 장면 종합 퀴즈에 섞는다" |

- 구현 값(2026-11-18, developer): "복습 {r}"은 **지금 차례인 종합 퀴즈 칸 하나**(그 장면의 다음 세션이 퀴즈일 때)에만 적는다. 복습 대기 목록은 다음 퀴즈 하나에 섞이므로, 완료 전인 모든 퀴즈 칸에 적으면 앞의 잠긴 퀴즈들에도 같은 숫자가 붙어 잘못 읽힌다.
| 완료한 장면 | 건물 배지(체크) + 단어 그림 스티커 2장(2.3) | 사용자 결정 4 |

### 1.3 길의 모양과 간격

```
한 장면 구간 (높이 504pt, 홀수 장면). 왼쪽 열은 구간 바닥에서 잰 y(위로 커짐)
                                   x 0.24        x 0.5        x 0.76
y 504 ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┃ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─   구간 경계 (길은 x 0.5, 세로로 지난다)
y 456                              (★) 종합 퀴즈 64pt
                                [종합 퀴즈]          ╲
y 328                                                  ( ) 단계 b 56pt
                                                     [い か た こ]
                                                     ╱
y 200                              ( ) 단계 a 56pt ╱
                                  [す し]
                                       ╲
y 128                                    ┌──────┐
                                         │ 건물 │  96pt
y  80                                    │ 카드 │  (가운데 y 80)
                                         └──────┘
                                       [1 스시집]
y   0 ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┃ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─   구간 경계
```

짝수 장면은 좌우가 뒤집힌다(a 오른쪽, b 왼쪽, 퀴즈 오른쪽). 건물은 늘 가운데다.

| 값 | 수치 | 이유 |
|---|---|---|
| 세션 칸의 x | 왼쪽 길 0.24, 오른쪽 길 0.76 (지도 폭에 대한 비율) | 375pt에서 왼쪽 칸 가운데 90pt. 기리(96pt)와 말풍선이 반대쪽에 들어가는 폭(2.4) |
| 건물 칸의 x | 0.5 | 장면이 바뀌는 굽이에 서서 "다음 가게"로 읽힌다 |
| 세션 칸 사이 (a→b, b→퀴즈) | 세로 128pt | 지금 칸의 말풍선 위 끝(칸 위 56pt)과 다음 칸 알약 아래 끝(칸 위 64pt) 사이 8pt |
| 퀴즈 → 다음 장면 a | 세로 248pt (퀴즈 456 → 경계 504 → 건물 80 → a 200) | 건물 카드를 사이에 두고 말풍선·알약과 8pt 이상 떨어지는 최소값 |
| 건물 가운데 | 퀴즈 칸 위 128pt (다음 a 칸 아래 120pt) | 퀴즈가 지금일 때 말풍선 위 끝과 건물 알약 아래 끝 사이 10pt. a 칸 알약 아래 끝과 건물 위 끝 사이 8pt |
| 건물 앞 자리 (`front`) | 건물 가운데 아래 40pt (x 0.5, y 40) | 장면 완료 연출에서 기리가 지나가는 자리(4.3) |
| 장면 구간 높이 | 504pt | |
| 출발 구간 | 176pt, 출발 표지 y 72 | |
| 지역 끝 구간 | 1단계 176pt, 표지 y 72. 2단계에 그림 카드가 들어오면 384pt | |
| 길 띠 | 폭 20pt `PathFill` + 양쪽 가장자리 2pt `PathEdge`(폭 24pt 선을 먼저 긋고 20pt 선을 위에 긋는다). 끝 둥글게 | 길이 보이게. 띠 위에 진행 선(2.5) |
| 길 곡선 | 칸과 칸 사이 3차 베지어 한 조각. 세로 방향으로 칸을 떠나 세로 방향으로 다음 칸에 닿는다(제어점은 두 칸 y의 가운데) | 꺾인 선보다 길로 읽힌다 |
| 구간 경계 | 길은 늘 x 0.5에서 세로로 경계를 지난다. 퀴즈 → 경계 조각은 `[[L,456],[L,490],[0.5,470],[0.5,504]]`, 경계 → 건물 조각은 `[[0.5,0],[0.5,27],[0.5,53],[0.5,80]]` | 도구가 곡선을 경계에서 자를 필요가 없다. 구간 하나 = 독립된 그림 |
| 맨 위 여백 | 지도 맨 위(지역 끝 구간 위)에 `max(0, 지도 영역 × 0.6 − 224)` | 마지막 퀴즈 칸도 쉼 자리(1.4)에 올 수 있게. 224 = 퀴즈에서 경계 48 + 끝 구간 176 |

- y 간격은 화면 폭에 따라 바꾸지 않는다. 칸, 기리, 말풍선 크기가 pt로 고정이라 간격도 고정이어야 375pt에서 겹치지 않는다. x만 폭에 비례한다.
- 지역 하나의 높이(1단계): 출발 176 + 장면 8 × 504 + 끝 176 = **4,384pt** (+ 맨 위 여백).

### 1.4 기기별 치수

지도 영역 = 화면 높이 − 안전 영역 위 − 내비게이션 바 44 − 아래 고정 영역 72 − 안전 영역 아래. 보이는 세션 칸 = 지도 영역 ÷ 평균 간격 168pt.

| 기기 | 화면 | 안전 영역 위/아래 | 지도 영역 (화면 y) | 쉼 자리 (화면 y) | 화면 절반 | 보이는 세션 칸 | 말풍선 폭 | 주 버튼 폭 |
|---|---|---|---|---|---|---|---|---|
| iPhone SE 2·3 | 375×667 | 20 / 0 | 531 (64~595) | **383** | 333.5 | 약 3.2 | 209 | 279 |
| iPhone 13 mini | 375×812 | 50 / 34 | 612 (94~706) | 461 | 406 | 약 3.6 | 209 | 279 |
| iPhone 17 Pro (기준) | 402×874 | 62 / 34 | 662 (106~768) | **503** | 437 | 약 3.9 | 229 | 306 |
| iPhone 17 Pro Max | 440×956 | 62 / 34 | 744 (106~850) | 552 | 478 | 약 4.4 | 258 | 344 |

- 쉼 자리 = 지도 영역 위 끝 + 지도 영역 × 0.6. 지금 칸(기리가 선 칸)이 이 높이에 오게 스크롤한다. 네 기기 모두 화면 아래 절반이다.
- 말풍선 폭 = 왼쪽 길 칸에서 기리 오른쪽 + 12pt부터 화면 오른쪽 여백 16pt까지(375pt에서 x 150~359).

## 2. 상태와 표시

### 2.1 세션 칸의 상태

세션은 한 줄로 열리므로 "열렸지만 지금이 아닌" 칸은 없다. 상태는 셋이다. 지금 칸 = 기리가 선 칸 = 주 버튼이 시작하는 세션(`store.homeTarget`).

| 상태 | 원 | 원 안 | 알약 | 색 밖의 구분 |
|---|---|---|---|---|
| 잠김 | `CardBackground`, `Outline` 2pt **점선**(6-4) | `lock.fill` 17pt, `InkSecondary` | 글자 `InkSecondary` 보통 굵기 | 점선 테두리, 자물쇠 |
| 지금 (하던 중 포함) | `AccentColor` 채움 | 단계 번호 `1`/`2`(17pt 굵게, `AccentForeground`), 퀴즈는 `star.fill` 20pt | 글자 `Ink` 굵게 | 채운 원, 기리가 서 있음 |
| 완료 | `CardBackground`, `Outline` 2pt 실선 | `checkmark` 20pt 굵게, `Correct` | 글자 `Ink` 굵게 | 체크 모양 |

- 하던 중은 칸 모양을 바꾸지 않는다. 주 버튼과 칸 카드가 "이어서 하기"라고 말한다.
- 지금 칸의 원 위쪽 3분의 2는 기리 발에 가려진다(2.4). 지금 칸은 기리와 알약으로 알아본다.
- 글자 알약: 높이 32pt, 모서리 16pt, `CardBackground` + `Outline` 2pt, 좌우 안쪽 12pt. 가나는 시스템 글꼴 20pt, 일본어 로캘, 글자 사이 6pt. 원 아래 4pt(알약 위 끝 = 칸 가운데 아래 32pt). 4자 알약 폭 122pt.
- 종합 퀴즈 알약: 높이 28pt, "종합 퀴즈" 또는 "종합 퀴즈 · 복습 {r}"(`.footnote` 굵게, `xxxLarge`에서 멈춤). 원 아래 4pt(알약 위 끝 = 칸 가운데 아래 36pt). 폭 최대 약 130pt.
- 칸 하나와 알약을 한 버튼으로 묶는다. 누르는 영역 = 원 ∪ 알약의 둘레 사각형(최소 56×92pt).
- 다른 누르는 대상과 8pt 이상 떨어진다(1.3의 간격으로 지켜진다).

### 2.2 건물 칸의 상태

장면 그림의 상태 규칙(scene-art/brief.md 2.2)을 96pt로 쓴다.

| 상태 | 그림 | 배지 | 장면 이름 알약 |
|---|---|---|---|
| 잠김 | 채도 0, 불투명도는 그대로 | `lock.fill`, `InkSecondary` | 글자 `InkSecondary` |
| 열림 (진행 중인 장면) | 원래 색 | 없음 | 글자 `Ink` |
| 완료 (종합 퀴즈 통과) | 원래 색 | `checkmark.circle.fill`, `Correct` | 글자 `Ink`. 양옆에 스티커 2장(2.3) |

- 카드: 96×96pt, 모서리 16pt, `Outline` 2pt. 그림 에셋 `map_building_{장면 id}`(6.1). 에셋이 없으면 `SceneThumb-{장면 id}`를 늘려 쓰고, 그것도 없으면 `CardBackground` 카드 가운데에 장면 `icon` SF Symbol 40pt.
- 배지: 지름 28pt 원(`CardBackground`, `Outline` 1pt), 안에 17pt 심벌. 원의 중심은 카드 오른쪽 위 꼭짓점에서 왼쪽과 아래로 8pt(카드 밖으로 6pt 걸침). 아래 꼭짓점은 이름 알약에 가려지므로 위에 둔다.
- 장면 이름 알약: 높이 28pt, 모서리 14pt, `CardBackground` + `Outline` 2pt, 좌우 안쪽 12pt, "{순서} {장면}"(`.footnote` 굵게, `xxxLarge`에서 멈춤). 가운데를 카드 아래 변에 둔다(카드 밖으로 14pt).
- 누르는 영역 = 카드 ∪ 알약. 열림·완료는 S push, 잠김은 반응 없음(`allowsHitTesting(false)`, 지금 장면 행과 같다).
- 장면 내용이 없는 개발 빌드: 건물은 열림으로 보이고 누르면 "준비 중이에요" 알림(지금과 같음).

| 항목 | 값 |

| 지금 데이터로 고른 16장 | すし·いか / とんかつ·ひれかつ / うどん·きつね / えき·のりかえ / おまもり·たこやき / やきとり·ささみ / ゆ·ぬる湯 / ようこそ·おふろ (각각 a·b) |
| 크기 | 56×56pt 정사각(테두리 포함). 기리(96)·건물(96)보다 작아 "붙인 장식"으로 읽히고, 안의 대상은 약 46pt라 무엇인지 알아본다 |
| 모양 | 오려 낸 스티커: 그림 둘레에 3pt `#FFFDF7` 테두리, 그 바깥에 0.5pt `#4A2219` 25% 선. 그림자 없음. 이 테두리는 도구가 PNG에 구워 넣는다(6.1). 라이트·다크 같은 그림 한 장(크림 테두리가 다크 바탕에서 진갈색 외곽선을 지켜 준다. word-art.md 2.5의 다크 판이 필요 없다) |
| 기울기 | 스티커 A −6°(반시계), 스티커 B +6°(시계). 장면마다 같다 |
| 자리 (구간 좌표) | a 칸이 왼쪽 길인 장면(홀수): A (x 0.78, y 128), B (x 0.22, y 40). a 칸이 오른쪽 길인 장면(짝수): A (x 0.22, y 128), B (x 0.78, y 40) |
| 길의 어느 쪽 | 길이 지나지 않는 두 쪽. 길은 아래 경계에서 x 0.5로 들어와 건물에서 a 칸 쪽 위로 나가므로, **A는 a 칸 반대쪽 위, B는 a 칸 쪽 아래**가 비어 있다 |
| 떨어진 거리 (기울인 둘레 61.5pt로) | A ↔ 건물 배지: 375pt 20pt, 360dp 16dp. B ↔ 장면 이름 알약(가장 긴 "3 소바·우동집" 약 124pt): 375pt 12pt, 360dp 8dp |
| 겹치지 않는 이유 | 스티커는 완료한 장면에만 있고, 그때 기리는 그 장면보다 위의 칸에 있다. 그래서 기리·말풍선이 스티커 근처에 오지 않는다. 다시 하기는 기리를 옮기지 않는다 |
| 누르기 | 누르는 대상이 아니다(`allowsHitTesting(false)`). 건물 버튼의 영역에도 넣지 않는다 |
| VoiceOver | 읽지 않는다(`accessibilityHidden(true)`, 단어 그림과 같은 장식 취급) |
| 그림이 없는 단어 | 도구가 그림 원본이 있는 다음 단어를 고른다. 단계에 그림 있는 단어가 하나도 없으면 그 자리는 비운다. 앱은 에셋 `map_sticker_{art}`가 없으면 그 자리를 그리지 않는다. 대체 그림, 회색 상자, "준비 중"을 두지 않는다(word-art.md 4.2와 같은 방침) |
| 움직임 | 없다. 장면 완료 뒤 지도로 돌아오면 이미 붙어 있다(그때 건물은 보통 화면 밖이다, 4.3) |
| 스마트 반전 | `accessibilityIgnoresInvertColors(true)` |

- 단어 그림은 W에서 "읽기 확인" 뒤에만 보여 뜻을 미리 알리지 않는다(word-art.md 3.1). 스티커는 그 장면을 다 끝낸 뒤에만 붙으므로 이 원칙과 부딪히지 않는다.
- 리워드 아이템은 지도에 붙이지 않는다. "읽은 단어"(스티커)와 "산 아이템"(꾸미기)을 섞지 않는다.

### 2.4 지금 칸의 기리와 말풍선

```
왼쪽 길의 지금 칸 (375pt, 말풍선 3줄)             화면 y (칸 가운데 cy 기준)
        ┌────────┐
        │        │  ┌──────────────────────┐       cy − 84  기리 위 끝
        │  기리  │◁ │ 첫 여행지는 스시집이 │       cy − 56  말풍선 띠 위 끝
        │  96pt  │  │ 에요. 같이 가 봐요   │       cy − 33  기리 입 = 꼬리
        │        │  │                      │
        └──( )───┘  └──────────────────────┘       cy + 12  기리 아래 끝
          [す し]                                   cy + 24  말풍선 아래 끝 (기본 글자 크기 3줄)
                                                    cy + 32~64 글자 알약
   x 42~138          x 150 ─────────── 359
```

| 요소 | 값 |
|---|---|
| 기리 | 96pt, 하나뿐. 입은 머리·속재료·밥 그대로(`GiriView`). 아래 고정 영역에는 기리가 없다 |
| 기리 자리 | 가로 가운데 = 칸 가운데. 아래 끝 = 칸 가운데 아래 12pt. 원의 위쪽 3분의 2를 발로 덮어 "칸 위에 선" 모양 |
| 표정 | 말하기. 깡충하는 동안 웃음(4번) |
| 숨쉬기 | 켬(giri-companion.md 5.2 값). 지도에는 다른 반복 움직임이 없다. 깡충·말풍선 뜨기 동안 멈춘다 |
| 말풍선 쪽 | 칸이 왼쪽 길이면 오른쪽, 오른쪽 길이면 왼쪽(`map.json`의 `bubble`). 왼쪽 말풍선은 꼬리가 오른쪽 변에 붙는다(`BubbleShape`에 좌우 뒤집기를 더한다) |
| 말풍선 가로 | 기리 쪽 변 + 12pt(꼬리 8pt 포함)부터 화면 여백 16pt까지. 폭은 글에 맞추되 최소 88pt. 왼쪽 말풍선은 오른쪽 끝을 기리 쪽에 맞춘다 |
| 말풍선 세로 | 가운데를 기리 입 높이(cy − 33)에 맞춘 뒤 띠 **cy − 56 ~ cy + 48** 안으로 밀어 넣는다. 기본 글자 크기: 1줄(40pt) cy − 53 ~ cy − 13, 2줄 cy − 56 ~ cy + 4, 3줄 cy − 56 ~ cy + 24. xxxLarge 3줄(104pt)은 cy − 56 ~ cy + 48 |
| 띠 아래 끝 cy + 48의 이유 | 아래쪽 이웃은 반대 길의 앞 칸(cy + 100부터) 또는 열린 건물 카드(cy + 72부터, 진행 중 장면이라 배지 없음). 둘 다 16pt 이상 떨어진다 |
| 꼬리 | 기리 입 높이. 말풍선 위·아래 끝에서 16pt 안쪽으로 제한 |
| 최대 줄 | 3줄, 넘치면 말줄임표(전체 문구는 VoiceOver). 문구는 giri-companion.md 3.11의 H 대사 그대로(`GiriSpeech.home`) |
| 누르기 | 기리와 말풍선 모두 누르는 대상이 아니다(`allowsHitTesting(false)`) |
| 그리는 층 | 구간들 위의 덮개 층 하나(지도 콘텐츠 전체 높이, 기리·말풍선만 절대 좌표로 놓음). 구간을 넘어 깡충하기 때문이다 |

- 모든 히라가나 장면을 끝냈을 때: 기리는 지역 끝 표지(x 0.5)에 서고 말풍선은 오른쪽. 대사 "히라가나 여행을 다 마쳤어요". 주 버튼은 숨는다.
- 다음 장면 내용이 없는 개발 빌드: 기리는 그 장면의 a 칸에 서고 대사 "다음 여행지는 아직 준비 중이에요". 주 버튼은 숨는다.
- 큰 글자 크기(`accessibility1` 이상): 기리는 지도에 그대로 두고 말풍선만 아래 고정 영역의 카드로 옮긴다(5.1).

### 2.5 진행 선

| 구간 | 모양 | 색 |
|---|---|---|
| 지난 길 (출발 ~ 지금 칸) | 6pt 실선, 끝 둥글게 | `AccentColor` |
| 앞길 (지금 칸 ~ 끝) | 6pt 점선(점 0, 간격 12, 끝 둥글게 → 둥근 점) | `InkSecondary` |

- 실선과 점선으로 모양이 달라 색만으로 구분하지 않는다. 대비는 7.3.
- 길 조각은 칸과 칸 사이에서 나뉘므로 조각마다 "지난"/"앞" 하나로 칠한다. 조각 중간에서 끊지 않는다.
- 그리는 순서: 바탕 → 길 띠 → 진행 선 → 스티커 → 칸·건물·알약 → 기리 덮개 층.

### 2.6 진행률

- 내비게이션 바 가운데(`principal`): "히라가나 {끝낸 장면}/8"(`.headline`, `monospacedDigit`). 가타카나 지역이 생기면 "가타카나 {k}/8".
- 칸별 진행은 지도가 보여 준다. 글자 수, 정답률 같은 통계는 넣지 않는다.

## 3. 조작 흐름

### 3.1 앱을 열 때

1. 홈이 뜨면 지금 칸이 쉼 자리(1.4)에 오도록 움직임 없이 스크롤을 맞춘다(iOS 18 `ScrollPosition.scrollTo(y:)`). 칸의 콘텐츠 y는 `map.json`의 구간 높이와 칸 y로 계산한다(7.1).
2. 지난번에 보여 준 칸(`lastShownNodeID`, 4.5)과 지금 칸이 다르면 4번의 연출을 한다. 같으면 기리가 지금 칸에 서 있고 말풍선이 권한다.
3. 아래 시작 버튼을 누르면 그 세션이 바로 열린다(`fullScreenCover`). S를 먼저 push하지 않는다.

### 3.2 지도를 구경할 때

- 위아래로 자유롭게 스크롤한다. 잠긴 칸과 건물도 보인다.
- 지금 칸의 가운데가 지도 영역 위·아래 끝에서 40pt 안쪽을 벗어나면 "지금 칸으로" 버튼이 0.2초 페이드로 나타난다.

| 요소 | 값 |
|---|---|
| 자리 | 지도 영역 아래 끝에서 12pt 위, 가로 가운데 |
| 모양 | `.bordered` 캡슐, 높이 44pt, 좌우 안쪽 16pt. 지금 칸이 위에 있으면 `arrow.up`, 아래에 있으면 `arrow.down` + 4pt + "지금 칸으로"(`.subheadline` 굵게) |
| 누르면 | 지금 칸을 쉼 자리로 0.35초 `easeInOut` 스크롤. 동작 줄이기에서는 바로 옮긴다 |
| 사라짐 | 지금 칸이 다시 범위 안에 들어오면 0.2초 페이드 |

### 3.3 칸 카드 (지난 칸 다시 하기, 앞 칸 미리 보기)

칸을 누르면 iOS 기본 시트(`.sheet` + `presentationDetents([.height(276)])`, 드래그 표시 보임)가 뜬다.

```
┌──────────────────────────────────────┐
│               ───                    │  드래그 표시
│ 스시집 · 간판                        │  제목 .headline
│ ✓ 끝냈어요                           │  상태 줄 .subheadline
│                                      │
│        す       し                   │  글자 줄 34pt, 일본어 로캘
│                                      │
│ 읽게 되는 단어  すし                 │  목표 단어 22pt (퀴즈 칸은 "글자 6자 · 단어 3개 · 복습 2자")
│ ┌──────────────────────────────────┐ │
│ │            다시 하기             │ │  주 버튼 56pt
│ └──────────────────────────────────┘ │
│           장면 단어 전체 보기        │  글자 버튼 44pt → S
└──────────────────────────────────────┘
```

| 칸 상태 | 상태 줄 | 주 버튼 | 누르면 |
|---|---|---|---|
| 지금, 처음 | `{n}.circle.fill` + 할 차례예요 | 시작 | 시트를 닫고 세션 |
| 지금, 하던 중 | `{n}.circle.fill` + 하던 데부터 이어서 해요 | 이어서 하기 | 시트를 닫고 세션(scene-flow.md 2.5의 자리) |
| 완료 | `checkmark.circle.fill`(`Correct`) + 끝냈어요 | 다시 하기 | 시트를 닫고 세션(진행 저장 안 함, 보상 없음) |
| 잠김 | `lock.fill` + {앞 세션}을/를 끝내면 열려요 | 없음. 시트 높이를 주 버튼 + 간격(60pt)만큼 줄인다(216pt) | 없음 |

- 제목: 단계 칸 "{장면} · {단계}", 퀴즈 칸 "{장면} · 종합 퀴즈". {n}은 단계 순서, 퀴즈는 `star.circle.fill`.
- {앞 세션}: 같은 장면이면 단계 이름 또는 "종합 퀴즈", a 칸이면 "{앞 장면} 종합 퀴즈".
- 높이: 위 20 + 제목 24 + 4 + 상태 20 + 16 + 글자 40 + 12 + 단어 28 + 16 + 주 버튼 56 + 4 + 글자 버튼 44 + 아래 8 = 292pt에서 시스템이 드래그 표시 자리를 잡으므로 콘텐츠 276pt. 큰 글자 크기(`xLarge` 이상)에서는 `.medium`으로 바꾸고 내용만 스크롤한다.
- 세션은 시트가 다 닫힌 뒤 띄운다(`onDismiss`에서 덮개). 시트와 덮개를 겹쳐 띄우지 않는다.
- "장면 단어 전체 보기"는 시트를 닫고 그 장면의 S를 push한다.
- 내용이 없는 장면의 칸은 카드 대신 "준비 중이에요" 알림.
- 구현 값(2026-11-18, developer): 장면 자체가 잠긴 칸(건물이 잠김)의 카드에는 "장면 단어 전체 보기"를 두지 않는다(잠긴 건물은 S로 가지 않는 것과 맞춤). 시트 높이 216 − 48 = 168pt. 장면이 열린 장면의 잠긴 칸(예: 지금 a일 때 b)은 216pt 그대로 글자 버튼이 있다.

### 3.4 세션을 닫았을 때 돌아가는 곳

사용자 결정(2026-11-17): 세션을 닫으면 장면 진입 화면이 아니라 지도로 돌아간다.

| 세션을 연 곳 | 닫는 방법 | 돌아가는 곳 |
|---|---|---|
| 지도의 시작 버튼, 칸 카드 | 닫기(`xmark`), C1 "여기까지 하기", C1 "지도로 돌아가기", C2 "지도로 돌아가기" | 지도 |
| S(건물 → S의 행·주 버튼) | 같음 | **지도.** 덮개가 닫히기 전에(덮개에 가려 보이지 않을 때) 스택을 비운다(`path = []`) |
| 어디든 | C2 "기리 꾸미기" | 지도 위에 K(`path = [.customize]`). K에서 뒤로 가면 지도가 보이고 그때 연출(4.5) |

- 문구 변경: C1의 "장면으로 돌아가기" → **"지도로 돌아가기"**, C2의 "장면 목록으로" → **"지도로 돌아가기"**, S(완료한 장면)의 "장면 목록으로" → **"지도로 돌아가기"**. `L.backToSceneList` 하나를 바꾸면 된다(PM 기본값, 9.2의 4).
- C1의 "{단계 b} 시작", "종합 퀴즈 시작"은 지금처럼 같은 덮개 안에서 이어 간다. 여러 세션을 이어 하고 닫으면 4.4의 연이은 깡충으로 보여 준다.

## 4. 연출: 세션을 닫고 지도로 돌아왔을 때

PLAN.md 3번과 giri-companion.md 5번의 규칙(기리 움직임 하나는 0.35초 이하, 반복 움직임 화면당 하나, 기리의 한 번 움직임은 동시에 둘까지, 입력을 막지 않음)을 지킨다. 색종이, 화면 흔들림, 확대, 햅틱은 넣지 않는다(성공 햅틱은 C1·C2가 이미 냈다).

### 4.1 무엇을 비교하나

- **보여 준 칸**(`lastShownNodeID`): 지도가 마지막으로 기리를 세워 보여 준 칸. 진도와 따로 화면 상태로 저장한다(4.5).
- **지금 칸**: 진도에서 계산한 칸(`homeTarget`의 세션, 모두 끝냈으면 지역 끝 표지).
- 지도가 화면에 보이게 되는 순간(덮개가 다 닫힌 뒤 `fullScreenCover`의 `onDismiss`, K·S에서 뒤로 온 뒤, 앱을 연 뒤 첫 배치) 둘을 비교한다.

| 비교 결과 | 연출 |
|---|---|
| 같음 | 없음. 스크롤 위치도 그대로 둔다(다시 하기를 닫았을 때 등) |
| 지금 칸이 보여 준 칸보다 세션 칸 1~3개 앞 | 4.2~4.4의 연출 |
| 그 밖(4개 이상 앞, 뒤로 감, 보여 준 칸이 없음) | 연출 없이 결과 상태, 지금 칸을 쉼 자리에. 첫 실행, 진도 초기화, 데이터 교체가 여기에 든다 |

### 4.2 덮개가 닫히기 전 (보이지 않는 준비)

세션 화면이 닫기를 요청하면 덮개를 내리기 **전에**:

1. 지도를 **보여 준 칸 기준으로** 그린다: 기리는 보여 준 칸에, 새로 끝낸 칸은 "지금"(보여 준 칸) 또는 "잠김" 모양 그대로, 다음 장면 건물은 잠김 그대로, 진행 선은 보여 준 칸까지, 말풍선과 시작 버튼 문구는 보여 준 칸의 것.
2. 스크롤을 움직임 없이 맞춰 보여 준 칸을 쉼 자리에 둔다.
3. 연 화면이 S면 스택을 비운다.

그래서 덮개가 내려가는 동안 사용자는 "떠날 때 그 자리"의 지도를 본다. 완료한 장면의 건물 배지와 스티커만은 이 때 이미 결과 상태다(보통 화면 밖이고, 움직임을 늘리지 않기 위해서다).

### 4.3 한 칸 깡충 (단계 a → b, b → 퀴즈)

덮개가 다 닫힌 순간(`onDismiss`)을 0초로 센다.

| 순서 | 시각 | 움직임 | 시간 | 곡선 |
|---|---|---|---|---|
| 1 스크롤 위치 | 0 전 | 4.2에서 이미 맞춤 | | |
| 2 칸 완료 표시 | 0.00 | 끝낸 칸: 지금 모양 → 완료 모양 교차 페이드. 그 칸에서 새 칸까지의 진행 선 조각: 점선 → 실선(같은 페이드). 동시에 말풍선 사라짐(0.15초 `easeOut`) | 0.2초 | `easeInOut` |
| 3 기리 깡충 | 0.20 | 기리: 지난 칸 → 새 칸. 가로는 곧게, 세로는 직선 보간 위에 32pt 솟는 포물선(`위치 = 보간(t) − (0, 32 × 4t(1−t))`). 표정 말하기 → 웃음(0.12초 교차 페이드, 깡충과 함께 시작). 지도도 같은 시간·같은 곡선으로 새 칸이 쉼 자리에 오게 스크롤 | **0.35초** | 진행 `easeInOut` |
| 4 시작 버튼 문구 갱신 | 0.55 | 착지. 표정 웃음 → 말하기(0.12초) + 새 말풍선 뜨기(0.25초 `.spring(response: 0.25, dampingFraction: 0.85)`). 새 칸: 잠김 → 지금 모양 교차 페이드(0.2초). 시작 버튼 문구 교차 페이드(`contentTransition(.opacity)`, 0.2초) | 0.25초 | |
| 끝 | 0.80 | `lastShownNodeID` = 새 칸 저장 | | |

- 스크롤이 기리를 같은 곡선으로 따라가므로 화면에서 보이는 모습은 "기리가 옆 길로 건너뛰며 32pt 솟았다 내려앉고, 지도가 한 칸 내려온다"이다. 스크롤은 화면 이동이라 기리 움직임 수에 넣지 않는다.
- 동시에 움직이는 기리의 한 번 움직임: 3번은 깡충 + 표정, 4번은 표정 + 말풍선. 둘을 넘지 않는다.
- 지도 끝 근처라 스크롤이 쉼 자리까지 갈 수 없으면 갈 수 있는 끝까지만 스크롤한다(맨 위 여백, 1.3 때문에 히라가나 지역에서는 생기지 않는다).

### 4.4 장면 완료와 연이은 깡충

**장면 완료 (퀴즈 통과 → 다음 장면 a)**:

| 시각 | 움직임 | 시간 |
|---|---|---|
| 0.00 | 칸 완료 표시(퀴즈 칸 체크, 진행 선) + 말풍선 사라짐 | 0.2초 |
| 0.20 | 다음 장면 건물 열림: 채도 0 → 1, 자물쇠 배지 불투명도 1 → 0(`easeInOut`). 같은 순간 깡충 ①: 퀴즈 칸 → 건물 앞(`front`, 건물 가운데 아래 40pt), 표정 웃음 | 0.3초 |
| 0.50 | 깡충 ②: 건물 앞 → 다음 장면 a 칸. 두 깡충 사이에 멈춤이 없다 | 0.3초 |
| 0.20~0.80 | 지도 스크롤: 퀴즈 칸 → a 칸이 쉼 자리에(한 번의 `easeInOut` 0.6초) | |
| 0.80 | 착지: 표정 말하기 + 새 말풍선 "다음 여행지는 {장면}이에요. {단계 a}부터 봐요" + a 칸 지금 모양 + 시작 버튼 문구 | 0.25초 |
| 1.05 | 끝 | |

- 248pt를 한 번에 뛰면 0.35초 안에 "순간 이동"처럼 보여 두 번으로 나눴다. 각 깡충은 0.3초로 0.35초 상한 안이다. 장면마다 한 번(히라가나에서 8번)이다.

**연이은 깡충** (C1에서 다음 세션으로 이어 하고 닫은 경우. 예: a를 끝내고 b까지 끝낸 뒤 "여기까지 하기"):

- 2번(칸 완료 표시)에서 새로 끝낸 칸을 모두 한꺼번에 바꾼다.
- 깡충을 칸마다 차례로 이어 한다(단계 칸 사이 0.35초, 장면을 넘을 때는 위의 두 번 0.3초). 사이에 멈춤이 없다. 스크롤은 깡충마다 따라간다. 표정은 처음에 웃음, 마지막 착지에서 말하기.
- 가장 긴 경우(a → b → 퀴즈 → 다음 a): 0.2 + 0.35 + 0.35 + 0.3 + 0.3 + 0.25 = 약 1.75초.

### 4.5 생략과 건너뛰기

| 조건 | 결과 |
|---|---|
| "동작 줄이기" 켜짐 | 위치가 움직이는 것을 모두 없앤다. 2번의 칸 완료 표시는 바로 바뀐다. 기리는 **불투명도로만** 옮긴다: 지난 칸에서 0.15초 사라짐 → 그 사이 스크롤을 바로 옮김 → 새 칸에서 0.15초 나타남. 건물은 바로 색으로. 말풍선·시작 버튼 문구는 바로 바뀐다. 합계 0.3초. "닫자마자 기리가 다음 칸으로 가는 것"이 위치 이동 없이 보인다 |
| VoiceOver 켜짐 | 움직임 없이 결과 상태. "{장면} {단계 또는 '종합 퀴즈'} 차례예요"를 알림(`AccessibilityNotification.Announcement`)으로 한 번 읽는다. 장면 완료면 "다음 여행지는 {장면}이에요. {단계 a} 차례예요" |
| 다시 하기를 끝냄 | 지금 칸이 그대로라 연출 없음 |
| 연출 도중 스크롤 끌기, 칸·건물·꾸미기 입구 누름 | 연출을 즉시 끝 상태로 만들고, 그 조작은 그대로 받는다 |
| 연출 도중 시작 버튼 누름 | **첫 번째 탭은 연출을 끝 상태로 만들기만 한다**(문구가 새 세션으로 바뀐다). 세션은 열지 않는다. 문구가 바뀌기 전의 버튼으로 다른 세션이 열리지 않게 하기 위해서다. 연출은 1초 안팎이라 실제로 걸릴 일은 적다 |
| 앱이 연출 도중 백그라운드로 감 | 끝 상태로 저장(`lastShownNodeID` = 지금 칸) |

- 구현 값(2026-11-18, developer): 앱을 새로 열어 연출을 기다릴 때(세션을 열 때 붙잡은 문구가 없음)는 착지 전까지 말풍선을 숨긴다. 새 문구가 옛 칸에 비치지 않게 하기 위해서다. 시작 버튼은 그동안 새 세션 문구를 보인다. 연출 중에는 "지금 칸으로" 버튼을 숨긴다. 장면을 넘는 깡충의 스크롤은 다음 a 칸을 목표로 0.6초 한 번이고, 연이은 깡충에서도 장면을 넘는 구간마다 같다.
- `lastShownNodeID`는 `UserDefaults`에 노드 id 문자열로 둔다(예: 키 `map.lastShownNodeID`). 진도 저장 형식과 별개라 진도 형식이 바뀌어도 영향이 없다. 연출이 끝나거나 건너뛰어질 때, 연출이 없을 때는 지도가 보일 때마다 지금 칸으로 갱신한다.
- 세션 직후 앱이 종료돼 연출을 못 본 경우, 다음 실행에서 4.1의 비교로 연출을 한다.

### 4.6 반복 움직임

지도 화면의 반복 움직임은 기리 숨쉬기 하나다. 바탕, 건물, 스티커는 움직이지 않는다. 지도에 Lottie를 쓰지 않는다.

### 6.3 바탕 띠: 타일로 잇는다 (2단계)

- 긴 한 장이 아니라 장면마다 한 장씩 위아래로 쌓는다. 모델이 세로 9,000pt 비율을 만들지 못하고, 디코딩한 한 장이 메모리를 크게 쓰며(@3x 1320×13,600px ≈ 72MB), 장면 하나를 고치려면 전부 다시 뽑아야 하기 때문이다. 구간 단위가 `LazyVStack`/`LazyColumn`과도 맞는다.
- 띠 하나 = 장면 구간 하나(504pt). "스시집 거리 → 역 → 신사 숲 → 온천 산 → 료칸 정원"으로 걸어가는 느낌을 낸다.
- 이어지는 방법: 모델에는 단색 바탕(옅은 모래색)으로 그리게 하고 `tools/remove_bg.py`로 바탕을 지운다. 띠에는 풍경 조각만 남고 앱이 그 아래에 화면 바탕색을 깐다. 이음매가 생기지 않고 스킨이 바탕색을 바꿀 수 있다.
- 풍경은 좌우 가장자리(각 15%)에 모으고, 가운데 70%와 위·아래 10%는 비운다.
- 크기: 생성 1024×1168px, 앱 원본 1320×1512px(@3x, 440pt 폭)으로 LANCZOS 확대. 좁은 화면은 가운데 기준으로 좌우를 자른다(높이 504pt 고정). 출발·끝 띠는 1024×416, 1024×896.
- 다크 모드: app-skin.md의 `sceneryScrimDark` 방식(다크 `AppBackground`를 0.45로 덮음)을 띠에도 쓴다.
- 스킨마다 띠를 따로 그리지 않는다(스킨 4개 × 10장 = 40장이 되므로). 띠는 모든 스킨이 같이 쓴다.

### 7.1 지도 정의 데이터: `map.json`

배치 계산(칸 좌표, 길 곡선, 스티커 고르기와 자리)을 앱이 아니라 파이썬 도구가 미리 해서 JSON 하나로 내보낸다. iOS와 안드로이드는 같은 파일을 읽어 그리기만 한다.

- 도구: `tools/build_map.py`(이름은 developer가 정함). 입력: `KanaTrip/Resources/hiragana_scenes.json`, 배치 값 `tools/map_layout.json`(1.3의 수치, `stickerOverride`), 단어 그림 원본 목록. 출력: `KanaTrip/Resources/map.json`. 안드로이드는 같은 파일을 `assets/`로 복사한다.
- 좌표:
  - x: 지도 폭에 대한 비율 0~1. 그릴 때 지도 폭을 곱한다.
  - y: **구간 바닥에서 위로 잰 pt(= dp)**. 칸·기리 크기가 고정이라 세로 간격도 고정이어야 375pt에서 겹치지 않는다.
  - iOS: 구간을 위에서 아래로 쌓고(배열을 뒤집어) 구간 안 화면 y = 구간 높이 − y. 안드로이드: `LazyColumn(reverseLayout = true)`에 배열 순서 그대로.
  - 콘텐츠 전체에서 노드의 위치 = 그 구간 아래에 있는 구간들의 높이 합 + y. 스크롤 위치와 기리 덮개 층은 이 값으로 계산한다.
- 구간(`sections`)은 **아래에서 위 순서**로 적는다. 칸·건물·스티커는 구간 경계를 넘지 않는다. 길은 경계에서 x 0.5로 끊긴다(1.3).
- 문구는 넣지 않는다. 장면·단계 이름, 글자, 알약 문구는 장면 데이터와 앱 문자열에서 id·`kind`로 찾는다.
- 칸 상태(잠김/지금/완료)는 데이터에 없다. 진도에서 계산한다(scene-flow.md 4.3).
- `metrics`는 두 플랫폼이 상수 대신 읽는 값이다. 앱 코드에 같은 숫자를 다시 쓰지 않는다.

  - 구간은 `LazyVStack`이 아니라 `VStack`으로 쌓는다. 기리 덮개 층과 겹친 ZStack 안의 `LazyVStack`은 시뮬레이터에서 구간을 그리지 않았다. 구간이 10개뿐이고 높이가 고정이라 문제없다.
  - `metrics`에 `topMarginBase`(224), `edgeMargin`(40), `motion`에 `jumpScroll`(0.35)을 더했다. 앱 코드에 같은 숫자를 다시 쓰지 않기 위해서다.
  - 큰 글자 크기에서도 시작 버튼은 0.85배 규칙으로 긴/짧은 문구를 고른다(accessibility-medium에서 긴 문구가 들어갔다).
  - 375pt 확인은 iPhone SE 시뮬레이터 대신 DEBUG 실행 인자 `-mapDebugCanvas 375x667`(앱을 375×667 틀 안에 그림, 위 20pt는 상태 바 흉내)로 했다. 실제 SE의 안전 영역과 조금 다르다.
- 작업량: 약 6~7일(지도 4~5일 + 연출 1~1.5일 + 도구 0.5일).
- 끝난 상태의 기준: 402×874와 375×667 시뮬레이터에서 (1) 처음 실행, (2) 간판 세션을 닫은 직후의 깡충, (3) 스시집 종합 퀴즈 통과 뒤 지도로 돌아온 장면 완료 연출과 스시집 스티커 2장, (4) 동작 줄이기 켜짐, (5) `accessibility1` 글자 크기, (6) 다크 모드의 스크린샷.
- 위험:
  - 긴 스크롤 안의 위치 맞추기. 구간 `LazyVStack` 위에 기리 덮개를 절대 좌표로 얹는다. 화면 하나짜리 Canvas로 4,400pt를 그리지 않는다(텍스처 크기 한도).
  - 덮개 닫힘과 연출 시작의 순서. 연출은 `onDismiss` 뒤에 시작해야 보인다. 그 전의 준비(4.2)는 덮개에 가려 있을 때 끝낸다.
  - 스크롤과 깡충을 같은 시간·곡선으로 맞추기. `ScrollPosition`의 애니메이션 스크롤과 기리 위치를 한 `withAnimation`으로 묶거나, 진행 값 하나로 둘을 그린다.
  - 한 화면에 보이는 범위가 지금 홈보다 좁다(1.4).

| 시작 버튼 | 긴 문구 그대로 "스시집 · 메뉴 시작" (짧은 문구가 보일 때도) | 버튼 |
| 꾸미기 입구 | "기리 꾸미기, 가진 엔 {n}엔" + 살 수 있으면 ", 살 수 있는 아이템이 있어요" | 버튼 |
| 지금 칸으로 | "지금 칸으로 이동" | 버튼 |
| 단계 칸 | "{N}번 {장면} {단계}, {글자}, {상태}". 상태: "지금 할 차례" / "하던 중" / "완료, 다시 하기" / "잠김, {앞 세션}을 끝내면 열려요". 예: "1번 스시집 간판, す し, 완료, 다시 하기" | 버튼. 글자는 일본어로 읽게 언어 지정 |
| 종합 퀴즈 칸 | "{N}번 {장면} 종합 퀴즈[, 복습 {r}자], {상태}" | 버튼 |
| 건물 | "{N}번 {장면}, {잠김 \| 진행 중 \| 완료}, 장면 단어 보기". 잠김이면 "…, 잠김" | 열림·완료는 버튼 |
| 출발·끝 표지 | "히라가나 여행 출발" / "가타카나 여행, 준비 중" | 정적 글 |
| 칸 카드 | 제목 → 상태 줄 → 글자 줄(일본어) → 단어 줄 → 주 버튼 → 글자 버튼 | |

**읽는 순서**: 바(진행률, 메뉴) → 기리 말풍선 → 시작 버튼 → 꾸미기 입구 → 지도 칸들(출발에서 위로 여행 순서). 시작 버튼까지 칸 34개를 지나지 않게 말풍선·시작 버튼·꾸미기 입구의 `accessibilitySortPriority`를 높인다. 지도는 `accessibilityElement(children: .contain)` 하나로 묶고 레이블 "여행 지도".

**큰 글자 크기**

| 크기 | 처리 |
|---|---|
| xLarge ~ xxxLarge | 지도 말풍선 줄이 커진다. 최대 3줄, 세로 띠 cy − 56 ~ cy + 48 안(2.4). 넘치면 말줄임표. 시작 버튼은 0.85배로 안 들어가면 짧은 문구. 칸 카드는 `.medium` + 스크롤 |
| `accessibility1` 이상 | 지도 말풍선을 빼고 아래 고정 영역에 말풍선 카드(5.1). 꾸미기 입구는 아이콘만 |
| 따르지 않는 것 | 칸 원·글자 알약의 가나(20pt)·건물 카드·스티커·기리 크기(배치 계산이 깨진다, visual-rules.md 2.4). 한글 알약 문구("종합 퀴즈", 장면 이름)와 꾸미기 글자는 `xxxLarge`/`xxLarge`에서 멈춘다 |

**색만으로 구분하지 않기**: 칸 상태는 채운 원/실선 원/점선 원과 번호·체크·자물쇠 모양, 진행 선은 실선/점선, 건물은 배지 모양과 흑백, 살 수 있음은 ¥ 모양과 레이블 글자.

**동작 줄이기**: 4.5.
