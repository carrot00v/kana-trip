## 1. 역할과 말투

### 1.1 역할

- 기리는 사용자보다 일본 여행을 한발 먼저 해 본 친구다. 같은 가게에 같이 들어가서, 간판과 메뉴를 같이 읽고, 어디서 봤는지 귀띔해 준다.
- 선생님이 아니다. 지시하고 채점하는 말은 화면의 정해진 자리(판정 줄, 부 머리 줄, 버튼)가 하고, 기리는 같이 보는 말만 한다. 판정 줄은 그대로 두고, 기리의 말은 판정 줄에 없는 내용(왜 헷갈렸는지, 어디에 쓰여 있는지)을 더한다.
- 사용자보다 많이 알지만 아는 척하지 않는다. "~예요"로 알려 주고 "~해 봐요"로 권한다.

### 1.2 말투 규칙

| 항목 | 규칙 |
|---|---|
| 높임 | 해요체 존댓말만. 반말, 합쇼체("~합니다"), 해라체를 섞지 않는다. 앱의 다른 문구(visual-rules.md 6.3)와 같은 높임이다 |
| 끝맺음 | 알려 줄 때 "~예요/이에요", "~어요". 권할 때 "~해 봐요", "~볼까요?", "같이 ~". 지시형 "~하세요"는 쓰지 않는다(화면의 안내 문구에만 남는다) |
| 한 문장 길이 | 22자 이하 (공백과 문장부호 포함) |
| 한 말풍선 | 2문장 이하. 자리마다 글자 수 상한이 따로 있다(2.3) |
| 가나 | 단어나 글자를 가리킬 때만 그대로 쓴다("か는 ka예요"). 일본어 문장, 일본어 감탄사(すごい 등)는 쓰지 않는다 |
| 부르기 | 사용자를 부르는 말(당신, 여러분, 이름)을 쓰지 않는다. 기리가 자기를 "기리는"이라고 부르지 않는다. 함께하는 느낌은 "같이"로 낸다 |
| 조사 | 장면·단계 이름, 글자, 로마자가 들어가는 자리의 조사는 scene-flow.md 15번의 받침 판별 함수로 고른다 |

쓰지 않을 표현:

| 종류 | 예 | 이유 |
|---|---|---|
| 평가 | 틀렸어요, 실패, 오답, 잘했어요, 훌륭해요, 대단해요, 천재 | 선생님 말투다. 틀림은 판정 줄이 아이콘과 문구로 알린다(visual-rules.md 6.3) |
| 시험 말 | 시험, 점수, 합격, 문제, 정답률 | 같이 여행하는 친구의 말이 아니다 |
| 재촉·죄책감 | 빨리, 서둘러, 오랜만이네요, 기다렸어요, 오늘 안 했어요 | 이동 중 짧게 쓰는 앱이다. 쉬어도 탓하지 않는다 |
| 기호 | 느낌표, 물결표, 이모지, ㅋㅋ·ㅎㅎ, 말줄임표 | visual-rules.md 6.3과 같다. 물음표는 권유("볼까요?")에만 쓴다 |
| 공부 말 | 공부, 학습, 숙제, 외우세요 | "읽어 봐요", "써 봐요"로 바꾼다. 예외: 붙여 쓴 한자의 "외우지 않아도 돼요"(PLAN.md 3번) |
| 확인 안 된 사실 | "모든 가게가 ~로 써요" | 단어 설명은 hiragana-allocation.md의 현지 표기 근거 안에서만 쓴다 |

### 1.3 차림

- 모든 화면의 기리는 지금 입은 모자·두건·손 아이템을 그린다. 기본 차림(요리사 모자, 빨간 두건)도 아이템이다.
- 배경 아이템은 K에서만 그린다(지금 규칙, reward-flow.md 7번). 작은 기리 뒤에 장면 그림이 깔리면 외곽선이 묻히고, 말풍선 옆에 그림 사각형이 하나 더 생겨 화면이 복잡해진다. PM 지시문에는 배경도 "모든 화면"으로 적혀 있어 9번 1에 남긴다.
- 표정과 팔 자세는 화면과 상태에 따라 바뀐다(4번). 아이템은 바뀌지 않는다.

## 2. 말풍선 부품

모든 화면이 같은 부품 하나(`GiriSpeechRow`, 이름은 개발 담당이 정함)를 쓴다. 기리와 말풍선을 가로로 놓는다.

```
┌──────┐  ┌────────────────────────────┐
│      │ ◁│ 1획 끝을 왼쪽으로 살짝      │
│ 기리 │  │ 올려요. 3획은 오른쪽에      │
│      │  │ 짧게 써요.                  │
└──────┘  └────────────────────────────┘
 G pt  4 8  ← 몸통: 안쪽 여백 좌우 12, 위아래 10
```

### 2.1 모양과 치수

| 요소 | 값 |
|---|---|
| 줄 전체 | 좌우 여백 16pt(화면 기준). 왼쪽 기리, 오른쪽 말풍선. 세로 가운데 정렬. 줄 높이 = max(기리 크기 G, 말풍선 높이) |
| 기리 | G×G pt 정사각형. G는 화면마다 다르다(3.1). `accessibilityHidden(true)` |
| 꼬리 | 말풍선 몸통 왼쪽 변에 붙은 삼각형. 밑변 14pt(세로), 왼쪽으로 8pt 튀어나옴. 끝은 기리 오른쪽 변에서 4pt 떨어진다. 몸통과 한 경로로 그려 외곽선이 이어진다 |
| 꼬리 높이 | 기리의 입 높이(기리 위 끝 + 0.53G, 360 좌표계의 y 190). 말풍선 위·아래 끝에서 16pt 안쪽으로 제한 |
| 몸통 | 기리 오른쪽 변 + 12pt에서 시작. 폭은 글자에 맞추고(최소 88pt) 남은 폭까지 넓어진다. 모서리 14pt |
| 바탕, 외곽선 | `CardBackground`, `Outline` 2pt. 판정 색(`Correct`, `Wrong`)과 노랑(`Highlight`)을 말풍선에 쓰지 않는다 |
| 안쪽 여백 | 좌우 12pt, 위아래 10pt |
| 글자 | `.subheadline`(15pt), `Ink`, 왼쪽 정렬, 줄 높이 20pt. 가나는 일본어 로캘로 같은 크기 |
| 높이 | 줄 수 n일 때 20n + 20pt (1줄 40, 2줄 60, 3줄 80, 4줄 100) |
| 줄 제한 | 자리마다 최대 줄 수(2.3)를 `lineLimit`으로 둔다. 넘치면 끝을 말줄임표로 자르고, 전체 문구는 VoiceOver 레이블에 남긴다 |
| 누르기 | 없음. 기리와 말풍선 모두 누르는 대상이 아니다 |

- 말풍선이 없는 상태(퀴즈 정답 뒤 등)에도 줄의 높이를 그대로 비워 둔다. 말풍선이 생기고 사라질 때 아래 내용이 움직이지 않게 한다.
- 다크 모드: 말풍선은 `CardBackground`(다크 `#2E2420`)와 `Outline`(다크 `#8C7366`)이라 토큰만으로 바뀐다. 기리 그림은 한 장으로 두 모드에 쓴다(visual-rules.md 9번에서 확인).

### 2.2 한 줄에 들어가는 글자 수

15pt 한글은 공백을 포함해 한 글자 약 15.5pt로 센다(scene-flow.md 8.4와 같은 기준). iOS는 한글을 낱말 단위로 줄바꿈하므로 한 줄에서 약 2자를 잃는다고 보고 "실제 글자 수"를 잡았다. 글자 수 상한은 가장 좁은 375pt 폭으로 정했다.

| 자리 | G | 글 폭 (375pt) | 한 줄 (375 / 402pt) | 실제 한 줄 |
|---|---|---|---|---|
| H, S (아래 고정 줄) | 64 | 343 − 64 − 12 − 24 = 243pt | 15 / 17자 | 13자 |
| L1, L2, W, QA, QD, QC | 56 | 343 − 56 − 12 − 24 = 251pt | 16 / 17자 | 14자 |
| QI | 80 | 343 − 80 − 12 − 24 = 227pt | 14 / 16자 | 12자 |
| C1, C2 | 120 | 343 − 120 − 12 − 24 = 187pt | 12 / 13자 | 10자 |

### 2.3 대사 자리별 상한 (planner용)

글자 수는 공백과 문장부호를 포함한다. "쓰는 사람"이 planner인 자리는 문구를 데이터에 넣고, designer인 자리는 3.11의 고정 대사를 쓴다(planner가 상한 안에서 다듬어도 된다).

| 자리 | 화면 | 최대 줄 | 글자 수 상한 | 쓰는 사람 | 데이터 |
|---|---|---|---|---|---|
| 권유 | H | 2 | 26자 | designer (3.11) | 없음 |
| 장면 소개 | S | 2 | 26자 | designer 기본 문구, 장면별로 바꿀 때 planner | 장면의 `giriIntro` (선택) |
| 쓰기 포인트 | L1, L2, QC | L1 4, L2 4, QC 2~4 | 48자. 앞 28자 안에 가장 중요한 점을 둔다(QC 375×667pt에서 2줄로 잘림, 3.8) | planner | 지금의 `hiragana_tips.json` 그대로 |
| 읽기 전 안내 | W | 2 | 28자 | designer (3.11) | 없음 |
| **단어 설명** | W | 3 | **40자, 2문장 이하** | **planner** | 단어의 설명 필드 (7번) |
| 퀴즈 안내 | QI | 3 | 36자 | designer (3.11) | 없음 |
| 질문, 부 바뀜, 다시 풀기 | QA, QD, QC | 2 | 28자 | designer (3.11) | 없음 |

- 지금 쓰기 포인트 가운데 48자를 넘는 것: と(61자), そ(58자), ん(52자), お(52자). L2와 QC에서 잘린다. planner가 줄인다.
- 단어 설명은 단어 읽기의 단어 60개 모두에 쓴다(못 읽는 단어 포함). 빈 단어는 3.11의 대체 문구가 나온다.

## 3. 화면별 등장

### 3.1 한눈에 보기

| 화면 | 기리 크기 | 자리 | 말풍선 | 기본 표정 | 반응 |
|---|---|---|---|---|---|
| H | 64pt | 아래 고정 줄, 주 버튼 바로 위 | 있음, 2줄 | 말하기 | 없음 |
| S | 64pt | 아래 고정 줄, 주 버튼 바로 위 | 있음, 2줄 | 말하기 | 없음 |
| L1 | 56pt | 단어 카드 아래 (쓰기 포인트 상자 자리) | 있음, 4줄 | 손 들기 | 없음 |
| L2 | 56pt | 글자 정보 줄 아래 (쓰기 포인트 상자 자리) | 있음, 4줄 | 말하기 | 글자 완성: 웃음 + 깡충 |
| W | 56pt | 뜻 줄 아래 (보조 설명 줄 자리) | 있음, 읽기 전 2줄 / 확인 후 3줄 | 읽기 전 생각, 확인 후 손 들기 | 확인: 말풍선이 설명으로 바뀜 |
| QI | 80pt | 상단 바 아래 (지금 가운데 96pt 자리) | 있음, 3줄 | 말하기 | 없음 |
| QA, QD | 56pt | 부 머리 줄 아래 (질문 줄 자리) | 있음, 2줄 | 생각 | 정답: 웃음 + 깡충, 말풍선 사라짐. 오답: 아쉬움 + 짚는 말 |
| QC | 56pt | 부 머리 줄 아래 (질문 줄 자리) | 있음, 2줄(작은 화면) | 생각 | 가이드 켜짐: 말하기 + 쓰기 포인트. 완성: 웃음 + 깡충 또는 기본 |
| C1, C2 | 120pt (큰 글자 80pt) | 지금 자리, 가운데에서 왼쪽으로 옮김 | 있음, 3줄 | 웃음 | 등장(지금 움직임 그대로) |
| K | 200~260pt | 미리보기 (그대로) | 없음 | 기본 | 없음 (그대로) |

- 화면마다 기리는 하나다. H의 꾸미기 행에서 기리 그림을 뺀다(3.2).
- 쓰기 캔버스와 선택지 위에 기리나 말풍선이 겹치지 않는다. 엄지 범위(화면 아래 절반)의 누르는 대상을 가리지 않는다. 모든 화면에서 기리 줄은 누르는 대상 사이가 아니라 보기만 하는 정보 사이에 있다.
- 판정이 나오는 화면(L2, QA, QD, QC)에서도 판정 줄은 지금처럼 아이콘 + 문구로 따로 있다. 기리의 표정은 답한 뒤에만 바뀌어 답을 미리 알려 주지 않는다.

말풍선 문구(3.11의 H): 주 버튼이 시작하는 세션에 맞춰 바뀐다. 주 버튼이 숨는 상태(다음 장면 준비 중, 모두 끝냄)에도 기리 줄은 남는다.

### 3.3 S 장면 진입

목적: 장면에 들어서면 기리가 장면을 소개하고 다음 할 일을 권한다.

- 배치는 H와 같다. 아래 고정 영역(144pt)에 기리 줄(64pt)과 주 버튼을 둔다. 목록(단계 섹션, 퀴즈 섹션)은 그대로다.
- 장면 그림(main 체크아웃의 Lottie 시제품, 목록 첫 섹션)과 기리를 겹치지 않는다. 그림은 목록 맨 위에 있고 기리는 아래 고정 영역에 있다.
- 장면 그림이 움직이는 화면에서는 기리의 숨쉬기를 멈춘다(5.3, 반복 움직임은 화면당 하나).
- 375×667pt: 목록이 보이는 높이는 667 − 116 − 144 = 407pt(지금 479pt). 6.8의 "할 차례인 행이 안 보이면 맨 위로 스크롤" 규칙은 그대로다. 기리 줄은 고정이라 스크롤과 상관없이 보인다.
- 말풍선 문구(3.11의 S): 진도에 따라 바뀐다. 단계 a가 할 차례일 때만 장면 데이터의 `giriIntro`가 있으면 그것을 쓴다.

### 3.4 L1 글자 소개

목적: 기리가 쓰기 포인트를 말해 준다.

- 지금의 쓰기 포인트 상자(전구 아이콘, 노랑 옅은 바탕)를 기리 줄로 바꾼다. 자리는 같다(단어 카드 아래 8pt).
- 기리 56pt, 손 들기(위의 글자를 가리키는 손). 말풍선은 그 글자의 쓰기 포인트, 최대 4줄. 쓰기 포인트가 없는 글자(13자)는 대체 문구 "번호 순서대로 따라 써 봐요".
- 375×667pt 세로(scene-flow.md 8.3): 쓰기 포인트 상자 92pt(8 + 84)가 기리 줄 8 + 100(4줄) = 108pt로 바뀌어 합계 634pt(사용 가능 647). 3줄이면 618pt. 넘치는 글자 크기에서는 지금처럼 내용만 스크롤한다.

### 3.5 L2 따라 쓰기

목적: 쓰는 동안 기리가 쓰기 포인트를 옆에서 계속 말해 준다.

- 쓰기 포인트 상자를 기리 줄로 바꾼다. 자리는 글자 정보 줄 아래 8pt, 판정 줄 위 8pt.
- 기리 56pt, 말하기. 말풍선은 L1과 같은 문구.
- 획마다 반응하지 않는다. 획의 맞음·틀림은 판정 줄과 캔버스가 알린다. 글자를 완성하면 웃음으로 바뀌며 깡충 뛴다(5.2). 말풍선 문구는 바뀌지 않는다.
- 다음 회차(따라 쓰기 2/2)로 넘어가면 표정이 말하기로 돌아온다.
- 375×667pt 세로(scene-flow.md 3번 표): 쓰기 포인트 64pt가 기리 줄로 바뀐다.

| 말풍선 줄 수 | 기리 줄 | 캔버스 | 엄지 범위 |
|---|---|---|---|
| 1~2줄 | 60pt | 343pt (지금과 같음) | 지금과 같음 |
| 3줄 | 80pt | 335pt | 캔버스 위 끝 y 256, 아래 77%가 엄지 범위 |
| 4줄 | 100pt | 315pt | 캔버스 위 끝 y 276, 아래 82%가 엄지 범위 |

- 캔버스 한 변 = min(화면 폭 − 32, 남는 높이)는 그대로다. 300pt보다 작아지면 말풍선 줄 수를 줄인다(4 → 3 → 2). 375×667pt에서는 4줄까지 300pt를 지킨다.
- 같은 글자 안에서는 문구가 바뀌지 않으므로 캔버스 크기도 바뀌지 않는다.

### 3.8 퀴즈 문항 QA, QD, QC

공통:

- 지금의 질문 줄(22pt, 부 머리 줄 아래 8pt)을 기리 줄로 바꾼다. 기리 56pt. 기리 줄의 높이는 **60pt로 고정**한다(말풍선 2줄 자리). 말풍선이 바뀌거나 사라져도 아래 문제·판정 줄·선택지·캔버스가 움직이지 않는다.
- 질문은 기리가 말한다. 부 머리 줄("여기부터 기억으로 쓰기 6문항", "다시 풀기 · 2개 남음")은 그대로 따로 있다.
- 답하기 전에는 생각 표정이다. 정답 쪽을 보지도, 웃지도 않는다.

| 상태 | 표정 | 말풍선 |
|---|---|---|
| 처음 | 생각 | 질문 (3.11) |
| 부의 첫 문항 (2부, 3부) | 생각 | 부 바뀜 문구 (3.11) |
| 다시 내는 문항 | 생각 | 다시 풀기 문구 (3.11) |
| 정답 (QA, QD) | 웃음 + 깡충 | 사라진다(0.15초). 판정 줄의 "맞아요"와 같은 말을 되풀이하지 않는다 |
| 오답 (QA, QD) | 아쉬움 | 헷갈린 점을 짚는 말 (아래) |
| QC 획 맞음·틀림 | 바뀌지 않음 | 바뀌지 않음 |
| QC 가이드 켜짐 ("가이드 보기", 획 3번 틀림) | 말하기 | 그 글자의 쓰기 포인트. 없으면 "가이드를 따라 같이 써 봐요" |
| QC 완성 (가이드 없이) | 웃음 + 깡충 | 사라진다 |
| QC 완성 (가이드를 봄) | 기본 | 사라진다. "뒤에 한 번 더 나와요"는 판정 줄이 말한다 |

오답 때 짚는 말 (문항이 만들어질 때 정해지는 값으로 고른다):

| 유형 | 조건 | 말풍선 | 예 |
|---|---|---|---|
| QA | 고른 로마자의 글자 k와 정답 글자 c가 헷갈리는 쌍(quiz-rules.md 4.1) | 그 쌍의 짚는 말 (planner, 28자 이하) | い/こ: "い는 세로, こ는 가로로 놓인 두 획이에요" |

| QD | 오답이 바꿔 넣은 글자 s와 원래 글자 k가 헷갈리는 쌍 | 그 쌍의 짚는 말 | |
| QD | 그 밖 | "이 단어의 {k}는 {k의 로마자}예요" | "이 단어의 か는 ka예요" |

- QD의 k와 s는 quiz-rules.md 4.3의 "바꿀 칸"과 "바꿔 넣을 글자"다. 문항 목록을 만들 때 오답마다 저장해 둔다(quiz-rules.md 5.2에 이미 "각 오답이 바꾼 칸"이 있다).
- 쌍의 짚는 말은 쌍 하나에 한 줄이고 양방향에 같이 쓴다. 비어 있으면 "그 밖" 문구를 쓴다.

## 4. 표정과 자세

### 4.1 세트

동행 역할에 필요한 최소 세트는 6가지다. 얼굴 레이어 3장만 새로 그리고, 팔은 지금 있는 두 자세(내림, 듦)를 다시 쓴다.

| 표정 | 쓰는 때 | 얼굴 레이어 | 본체(팔) 레이어 | 반짝임 | 손 아이템 파일 |
|---|---|---|---|---|---|
| 기본 | 말없이 있을 때, K, QC 가이드 본 완성 | `GiriFaceDefault` (있음) | `GiriBaseDefault` (팔 내림, 있음) | 없음 | `-default` |
| 웃음 | 정답, 글자 완성, C1·C2 | `GiriFaceHappy` (있음) | `GiriBaseHappy` (오른팔 듦, 있음) | 있음 | `-happy` |
| 말하기 | 말풍선으로 알려 주거나 권할 때 | `GiriFaceTalk` (새로) | `GiriBaseDefault` | 없음 | `-default` |
| 손 들기 | 위의 글자·단어를 두고 설명할 때 (L1, W 확인 후) | `GiriFaceTalk` (새로) | `GiriBaseHappy` | 없음 | `-happy` |
| 생각 | 같이 읽는 중, 답을 기다릴 때 (W 읽기 전, 퀴즈 답하기 전) | `GiriFaceThink` (새로) | `GiriBaseDefault` | 없음 | `-default` |
| 아쉬움 | 퀴즈 오답 | `GiriFaceSorry` (새로) | `GiriBaseDefault` | 없음 | `-default` |

- "가리키기"는 손 들기로 대신한다. 특정 방향을 가리키는 팔을 새로 그리면 손 아이템의 기준점이 하나 더 생겨 손 아이템마다 그림 파일을 하나씩 더 만들어야 한다(reward-flow.md 8.2). 오른팔을 든 자세는 말풍선 쪽으로 손을 든 모양이라 "여기 봐요"로 읽힌다.
- 손 아이템 파일은 표정이 아니라 **팔 자세**로 고른다: 팔 내림이면 `Item-{id}-default`(기준점 278, 284), 오른팔 듦이면 `Item-{id}-happy`(기준점 290, 164). 새 기준점은 없다.
- 반짝임은 웃음에만 있다. 손 들기에는 없다(웃음과 구분하는 표시다). 손 아이템이 있을 때 반짝임을 왼쪽으로 뒤집는 규칙은 그대로다.
- 슬픈 얼굴, 우는 얼굴, 화난 얼굴, 놀란 얼굴은 만들지 않는다. 아쉬움은 "앗차" 정도의 가벼운 얼굴이다.

### 4.2 새 얼굴 레이어

`tools/make_onigiri_svg.py`의 `FACES`에 세 개를 더한다. 좌표는 지금 그림과 같은 360 좌표계(viewBox `-30 0 360 360`)다. 볼(`face()`의 볼 타원 두 개)은 모든 표정에 그대로 있다. 색 상수는 스크립트의 것(`LINE`, `TONGUE`)을 쓴다.

지금 얼굴(비교용): 기본은 눈 타원 두 개(114, 170)·(186, 170), rx 7, ry 10과 입 `M140 186 Q150 196 160 186`(선 5.5). 웃음은 오른눈을 `>` 모양 꺾은선으로, 입을 혀가 보이는 큰 입(가로 30, 세로 27)으로 바꾼 것이다.

| 키 | 눈 | 입 | 읽히는 느낌 |
|---|---|---|---|
| `talk` 말하기 | 기본과 같음 (`EYE_L`, `EYE_R`) | 작게 벌린 입: `<path d="M140 184 Q150 181 160 184 Q160 200 150 200 Q140 200 140 184Z" fill=LINE stroke=LINE stroke-width="3" stroke-linejoin="round"/>` + 혀 `<path d="M143 194 Q150 189 157 194 Q155 199 150 199 Q145 199 143 194Z" fill=TONGUE/>` | 웃음보다 작은 입(가로 20, 세로 16)으로 말하는 중 |
| `think` 생각 | 오른쪽 위를 보는 눈: `<ellipse cx="118" cy="167" rx="6" ry="9" fill=LINE/>`, `<ellipse cx="190" cy="167" rx="6" ry="9" fill=LINE/>` | 오른쪽으로 비낀 작은 입: `<path d="M145 191 Q152 187 160 189" fill="none" stroke=LINE stroke-width="5.5" stroke-linecap="round"/>` | 같이 생각하는 중. 눈 위 끝 y 158로 모자 범위(y 158 이하)에 닿지 않는다 |
| `sorry` 아쉬움 | 두 눈을 꺾은선으로: 왼눈 `<path d="M104 161 L120 170 L104 179"/>`, 오른눈 `<path d="M196 161 L180 170 L196 179"/>` (둘 다 fill none, stroke LINE, 굵기 6, 끝·이음 둥글게) | 물결 입: `<path d="M139 193 Q144.5 187 150 193 Q155.5 199 161 193" fill="none" stroke=LINE stroke-width="5" stroke-linecap="round"/>` | 질끈 감은 눈과 물결 입의 "앗차". 오른눈은 웃음 얼굴의 오른눈과 같은 선이다 |

- 세 얼굴 모두 눈썹, 땀방울, 물음표 같은 덧붙임 표시를 넣지 않는다. 눈썹 자리(y 150 근처)는 모자 아이템 범위(y 158 이하)와 겹치고, 새 색이 생기지 않게 하기 위해서다.
- 56pt에서 입은 약 3pt 폭이 된다. 말하기와 기본의 차이(벌린 입과 닫은 입)가 보이는지는 8번에서 확인한다.

### 4.3 스크립트에서 바꿀 곳 (developer)

1. `FACES`에 `talk`, `think`, `sorry`를 4.2대로 더한다.
2. `ARMS`는 `default`, `happy` 두 개 그대로 둔다. 본체 레이어는 팔 자세마다 하나라 새로 생기지 않는다.
3. `layer_files()`의 반복을 나눈다: 본체는 `for kind in ARMS`(`giri-base-{kind}.svg`), 얼굴은 `for kind in FACES`(`giri-face-{kind}.svg` → `GiriFaceTalk`, `GiriFaceThink`, `GiriFaceSorry`). 지금은 얼굴 키로 본체도 만들어 새 얼굴마다 본체가 생겨 버린다.
4. 확인용 완성 그림: 4.1 표의 6가지를 `EXPRESSIONS = {이름: (얼굴, 팔, 반짝임)}`으로 두고 `onigiri-{이름}.svg`를 모두 만든다(기본 차림). `check_layers_match()`는 지금처럼 `default`, `happy` 두 개만 본다.
5. 앱 코드: `GiriFace`를 얼굴(5종)과 팔(2종)을 함께 갖는 값(예: `GiriPose`)으로 바꾸고, 손 아이템 파일 키를 팔에서 고른다(4.1).

## 5. 움직임

### 5.1 SwiftUI와 Lottie의 경계

| 대상 | 방법 | 이유 |
|---|---|---|
| 기리(표정, 팔, 깡충, 숨쉬기, 등장) | SwiftUI 애니메이션 | 기리는 입은 아이템(모자 × 두건 × 손)과 표정·팔 레이어를 실행 중에 겹쳐 그린다. Lottie로 만들면 조합마다 파일이 필요하다. 움직임은 위치·크기·불투명도 몇 개뿐이라 이 문서의 값으로 안드로이드에서도 다시 만들 수 있다 |
| 말풍선, 화면 전환, 버튼·선택지 변화 | SwiftUI 애니메이션 | UI 부품이다 |
| 장면 그림의 김·불빛·흔들림 | Lottie (lottie-ios, main의 PLAN.md 3번 "그림 움직임") | 생성 그림 위에 움직이는 벡터 레이어를 얹은 파일 하나로 두 플랫폼이 같이 쓴다 |

- Lottie 파일에 기리를 넣지 않는다. 기리를 Lottie 그림 위에 겹치지 않는다(S에서도 따로 놓는다, 3.3).
- 기리의 움직임에 새 패키지를 쓰지 않는다. iOS 18 기본 API(`withAnimation`, `keyframeAnimator`, `phaseAnimator`, `contentTransition`)로 된다.

### 5.2 움직임 목록

| 이름 | 언제 | 값 | 동작 줄이기 켜짐 |
|---|---|---|---|
| 등장 | C1, C2가 나타날 때만 (지금 규칙) | 크기 0.85 → 1.0, 불투명도 0 → 1, `.spring(response: 0.35, dampingFraction: 0.7)` | 처음부터 제자리 |

| 종류 | 상한 | 우선 |

| 한 번 움직임 (등장, 말풍선 뜨기·사라짐, 표정 바뀜, 깡충) | 동시에 2개 | 깡충 + 말풍선 사라짐(정답), 표정 바뀜 + 말풍선 뜨기(오답) 같은 짝까지. 화면 전환 페이드(0.2초) 중에는 기리 움직임을 시작하지 않고, 페이드가 끝나면 시작한다 |

### 5.4 진행을 막지 않기

- 말풍선은 탭하지 않아도 끝까지 보인다. 넘기기 버튼, "탭해서 계속", 글자를 하나씩 찍는 효과가 없다.
- 모든 움직임은 0.35초 이하이고, 움직이는 동안에도 버튼, 선택지, 캔버스는 바로 누를 수 있다. 상태 저장과 다음 문항으로 넘어가는 조건은 움직임의 끝을 기다리지 않는다.
- 기리가 화면을 넘기거나 시간을 정해 무언가를 하지 않는다(자동 넘김 없음, scene-flow.md 13.1).
- 이동 중 2~3분 세션에서 기리 때문에 늘어나는 시간은 없다. 읽는 시간은 지금 있던 안내·쓰기 포인트·보조 설명을 읽던 시간과 같다.

### 5.5 동작 줄이기

"동작 줄이기"가 켜져 있으면 5.2의 모든 움직임을 없애고 결과 상태만 바로 보여 준다. 표정과 말풍선은 바뀐다(정보다). 지금 규칙(visual-rules.md 6.2)과 같은 방식이다.

## 6. 접근성

### 6.1 VoiceOver

- 기리 그림은 읽지 않는다(`accessibilityHidden(true)`). 표정은 정보를 싣지 않는다. 판정은 판정 줄이 전한다.
- 말풍선은 읽는 정적 글 요소 하나다. 레이블은 대사 그대로이고 "기리"를 앞에 붙이지 않는다. 퀴즈 20문항 안팎에서 같은 이름을 되풀이하지 않기 위해서다. 잘린 말풍선(2.1)도 레이블에는 전체 문구를 넣는다.
- 읽는 순서는 화면의 위에서 아래 순서를 따른다. 화면별로:

| 화면 | 순서 |
|---|---|
| H, S | 내비게이션 → 목록 행들 → 기리 말풍선 → 주 버튼 |
| L1 | 상단 바 → "새 글자" → 글자 → 단어 카드 → 기리 말풍선(쓰기 포인트) → "써 보기" |
| L2 | 상단 바 → 글자 정보 줄 → 기리 말풍선(쓰기 포인트) → 판정 줄 → 캔버스 → 버튼 |
| W | 상단 바 → 단어 → (확인 후) 읽기, 뜻 → 기리 말풍선 → 주 버튼 |
| QI | 상단 바 → 기리 말풍선 → 제목 → 글자 줄 → 부 목록 → 복습 줄 → 이어 하기 → 주 버튼 |
| QA, QD, QC | 상단 바 → 부 머리 줄 → 기리 말풍선(질문) → 문제 → 판정 줄 → 선택지 또는 캔버스 → 버튼 |
| C1, C2 | 기리 말풍선 → 제목 → 요약 → … (scene-flow.md 11·14번 순서) → 버튼 |

- 화면 내용이 바뀔 때 초점을 옮기는 자리(visual-rules.md 8.2): 퀴즈 문항이 바뀌면 지금의 "질문" 대신 기리 말풍선으로 옮긴다. 다른 화면은 지금 규칙 그대로다.
- 알림(`AccessibilityNotification.Announcement`)은 하나로 묶어 읽는다. 연달아 보내면 앞의 것이 끊긴다.
  - W 확인: "{읽기}, {뜻}. {기리 설명}"
  - 퀴즈 오답: "정답은 ta예요. {기리의 짚는 말}"
  - QC 가이드 켜짐: "가이드를 보고 따라 쓰세요. {쓰기 포인트}"
  - 퀴즈 정답, 글자 완성: 지금 알림 그대로(기리 말풍선이 사라지거나 바뀌지 않으므로 더하지 않는다).

### 6.2 큰 글자 크기

- 말풍선 글자는 `.subheadline`이라 Dynamic Type을 따른다.
- `accessibility1` 이상에서는 모든 화면에서 기리 그림을 숨기고 말풍선만 남긴다. 말풍선은 꼬리 없는 카드(모서리 14pt, 같은 바탕·외곽선)가 되어 좌우 여백 16pt의 전체 폭을 쓴다. 글 폭이 375pt에서 251pt → 319pt로 넓어진다. C1·C2는 지금 규칙대로 기리 80pt를 남기고 말풍선을 그 아래 8pt에 전체 폭으로 둔다.
- H, S: `accessibility1` 이상에서는 기리 줄을 아래 고정 영역에서 빼고 목록 맨 위 섹션의 행 하나(말풍선 카드)로 옮긴다. 아래 고정 영역은 주 버튼만 남는다(72pt). 글자가 커져도 아래 고정 영역이 목록을 덮지 않게 하기 위해서다.
- L1, W, QI, QA, QD, C1, C2: 내용 영역이 스크롤되므로 말풍선 줄 제한을 풀고 전체를 보여 준다.
- L2, QC: 지금처럼 `accessibility1`에서 글자 크기가 멈춘다. 말풍선은 캔버스 300pt를 지키는 줄 수까지만 보이고(3.5, 3.8) 나머지는 잘린다. 전체 문구는 VoiceOver와 L1에서 읽을 수 있다.

### 6.3 색

- 기리의 반응은 표정 모양으로만 다르다. 판정 색(`Correct`, `Wrong`)을 기리와 말풍선에 쓰지 않는다. 맞음·틀림은 판정 줄의 아이콘 모양과 문구가 전한다.
- 판정이 나오는 화면(L2, QA, QD, QC)에 빨간 두건이 들어오게 됐다. 기리는 56pt라 두건 띠가 약 4pt 높이이고, 두건 빨강(`#E2533F`)과 `Wrong`(`#B8233F`)은 색상과 밝기가 모두 다르다(visual-rules.md 1.2). 판정 줄은 L2에서 기리 줄 바로 아래 8pt, QC에서 74pt, QA·QD에서 237pt 떨어져 있다(375×667pt). 화면의 빨강은 여전히 "틀림"만 뜻하도록, 기리 그림 밖의 UI에 두건 빨강을 쓰지 않는 규칙은 그대로다.
