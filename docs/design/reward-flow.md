## 1. 전체 흐름에서 바뀌는 곳

```
[H] 홈
  ├─ 기리 행 탭 ─────────────────► [K] 기리 꾸미기 (push)
  ├─ 장면 행 탭 ─────────────────► [S] 장면 진입 (그대로)
  └─ 아래 주 버튼 ───────────────► 세션 (그대로)

[C1] 세션 완료 ── 받은 엔 한 줄만 더함. 버튼과 전환은 그대로
[C2] 장면 완료
  ├─ 주 버튼 "장면 목록으로" ────► [H] (그대로)
  └─ 글자 버튼 "기리 꾸미기" ────► 덮개를 닫고 [H] 위에 [K] push

[K] 기리 꾸미기
  └─ 뒤로(왼쪽 위 버튼, 가장자리 스와이프) ─► [H]
```

- 사고 입는 일은 K 한 곳에서만 한다(reward-system.md 2.3, 5.1). 세션 화면(L1~W)에는 아무것도 더하지 않는다.
- K에서 세션으로 바로 가는 길은 두지 않는다. 학습 흐름과 꾸미기를 섞지 않는다.

## 2. 들어가는 길

### 2.1 홈의 어디를 누르나 (reward-system.md 13번의 1에 대한 답)

**결정: 홈 목록 맨 위에 "기리 행"을 둔다. 지금 "히라가나" 섹션 머리글 오른쪽의 64pt 기리를 이 행의 왼쪽으로 옮긴다.**

| 후보 | 판단 |
|---|---|
| 머리글의 기리 그림을 누르게 한다 | 글자가 없어 누를 수 있는지 알 수 없다. VoiceOver에서도 숨겨진 그림이라 레이블을 새로 붙여야 하고, visual-rules.md 7.2의 "캐릭터를 버튼으로 쓰지 않는다"를 정면으로 깬다 |
| 오른쪽 위 툴바에 버튼을 더한다 | 엄지가 닿지 않는 자리에 세 번째 버튼이 생긴다. 메뉴(`ellipsis.circle`)와 붙어 잘못 누르기 쉽다. 잔액을 함께 보여 줄 자리가 없다 |
| 아래 주 버튼 옆에 보조 버튼을 둔다 | 홈의 주 버튼 문구("밥집 간판 · 단어 읽기 이어서 하기", 약 280pt)가 375pt 폭에서 112pt 보조 버튼과 함께 들어가지 않는다. 학습 시작 버튼 옆에 꾸미기가 있으면 시선이 나뉜다 |
| 목록 맨 아래에 행을 둔다 | 장면 행 8개(608pt) 아래라 스크롤해야 보인다. 장면을 끝내고 돌아왔을 때 "살 것이 있음"이 보이지 않는다 |
| **목록 맨 위에 기리 행 (채택)** | 글자("기리 꾸미기")와 잔액이 있어 무엇을 하는 행인지 바로 보인다. 목록 행은 행 전체가 누르는 영역이라는 기존 규칙(visual-rules.md 4.2)을 그대로 쓴다. 기리 그림은 행 안의 장식으로 남고 따로 누르는 대상이 되지 않는다. 장면을 끝내고 홈에 오면 첫눈에 보인다 |

- 위쪽 절반에 누르는 대상이 생기는 점: 장면 행도 이미 목록 위쪽에 있다. 기리 행은 하루 몇 번 쓰는 조작이고, 세션을 시작하는 조작(아래 주 버튼)은 그대로 아래에 있다.
- 바뀌는 규칙: visual-rules.md 4.2 "캐릭터 그림은 누를 수 없다"를 "캐릭터 그림만 따로 누르는 대상이 되지 않는다. 캐릭터가 든 목록 행은 행 전체가 누르는 영역이다"로 고친다(12번 절).

### 2.2 띄우는 방식

**결정: push (`NavigationStack`).**

- K는 할 일을 마치고 닫는 작업 창이 아니라 언제든 둘러보는 장소다. 장면 진입(S)과 같은 단계의 화면이라 같은 방식으로 띄운다.
- K에는 획을 긋는 캔버스가 없어 가장자리 스와이프와 겹칠 동작이 없다(scene-flow.md 2.1이 세션을 덮개로 띄운 이유가 해당하지 않는다).
- sheet로 띄우면 아이템 격자를 위로 스크롤하다가 시트가 끌려 내려가는 일이 생기고, C2에서 열 때 덮개 위에 시트가 겹쳐 닫은 뒤 다시 C2로 돌아온다.
- 홈의 `path`가 지금은 장면 id 문자열 배열이다. K로 가는 값을 하나 더해야 한다(예: `enum HomeRoute: Hashable { case scene(String), customize }`). 이름은 개발 담당이 정한다.

C2에서 들어갈 때: "기리 꾸미기"를 누르면 ① 덮개를 닫고 ② `path = [.customize]`로 바꾼다. 장면 진입(S)은 쌓지 않는다. K에서 뒤로 가면 홈이 나오고, 홈에는 장면 완료와 다음 장면 열림이 이미 반영돼 있다.

## 3. K 기리 꾸미기

목적: 모은 엔으로 열린 아이템을 사고, 가진 아이템으로 기리를 꾸민다. 한 화면에서 하는 일은 "기리 꾸미기" 하나다.

### 3.0 꾸미기 4종류 개편 (2026-11-16 확정)

사용자 요청("돈까스를 머리에 올린다거나 삼각김밥 사이로 토핑이 삐져나오는 등, 아니면 야끼오니기리처럼 색상이 변한다거나")으로 슬롯이 **머리·속재료·밥·배경 4개**가 됐다. 같은 날 잠시 거친 머리·배경 2슬롯 안은 쓰지 않는다. 그림 기준은 item-art/brief.md 2.0~2.6.

**원칙: 탭 하나 = 슬롯 하나 = "없음"(또는 기본) 칸 하나.** 탭 안을 다시 머리글로 나누지 않는다. 머리 탭 안에서 모자류와 토핑도 나누지 않는다.

2026-11-13의 4슬롯(모자·두건·손·배경)에서 바뀐 곳:

| 자리 | 전 (모자·두건·손·배경) | 지금 (머리·속재료·밥·배경) | 절 |
|---|---|---|---|
| 슬롯 탭 | 버튼 4개 | 버튼 4개 **머리 · 속재료 · 밥 · 배경**. 모양·높이는 같고 글자 규격이 정해졌다 | 3.2, 9.2 |
| 탭 순서 | 모자, 두건, 손, 배경 | 기리를 **작게 바꾸는 것에서 크게 바꾸는 것** 순서: 머리(얹기, 아이템이 가장 많고 처음 고른 탭) → 속재료(옆의 작은 덧붙임) → 밥(몸 전체 색) → 배경(뒤 전체, K에서만 보임) | 3.2 |
| 칸 | 슬롯마다 없음 + 아이템 | 머리: 없음 → 요리사 모자 → 장면 순서(모자류·토핑 섞임). 속재료: 없음 → 장면 순서. **밥: 흰 밥 → 장면 순서, "없음" 칸이 없다**(밥은 비울 수 없다). 배경: 없음 → 장면 순서 | 3.5 |
| 기본 차림 | 모자 + 두건 두 슬롯을 되돌리고 손·배경 비우기 | 머리 = 요리사 모자, 속재료 = 비움, 밥 = 흰 밥, 배경 = 비움. 빨간 두건과 김은 고정이라 건드리지 않는다. **"기본 차림으로" 버튼은 남긴다**(손으로 되돌리면 탭 4번 + 칸 4번) | 3.7 |
| 처음 고른 탭 | 살 수 있는 아이템 중 가장 늦은 장면의 아이템 슬롯 | 같은 규칙에 "같은 장면이면 탭 순서가 앞인 것"을 더함. 살 것이 없으면 머리 | 3.6 |
| 상태 문구의 동사 | 입는 중, 입었어요, 입어 보는 중, 사서 입었어요 | **쓰는 중, 바꿨어요, 미리 보는 중, 사서 바꿨어요.** 토핑·밥·배경을 "입는다"고 하지 않기 위해서다 | 3.5, 3.7, 3.8, 10 |
| 미리보기 | 아이템 레이어를 더하거나 뺌 | 밥 칸을 누르면 기리의 몸 색이 바뀐다(본체 레이어 교체, 0.2초 페이드 그대로). 속재료는 몸 왼쪽에 나타난다 | 3.7 |
| 기리 그림 | 손 아이템을 표정마다 다른 파일로, 손이 있으면 반짝임을 왼쪽으로 뒤집기 | 머리·속재료 아이템은 표정과 상관없이 한 장. 밥은 본체 레이어 자체가 밥마다 다르다. 볼은 본체로 옮김. 두건은 본체에 합친 고정 그림. 반짝임은 늘 오른쪽 위 | 7, 8 |
| 실기기 확인 | 두건 썸네일(띠 6pt), 64pt 손 아이템, 왼쪽 반짝임 | 셋 다 없어짐. 대신 탭 4개 글자, 작은 기리에서 토핑·속재료가 알아보이는지, やきおにぎり 몸에서 표정이 읽히는지 | 13 |

바꾸지 않은 것: 들어가는 길(홈의 꾸미기 행), push, 미리보기 크기 규칙, 안내 줄, 화면 구조(미리보기 → 안내 줄 → 탭 줄 → 격자)와 세로 계산, 칸 크기·상태 표시 방식, 사기 확인 창, C1·C2의 리워드 줄.

- 탭을 3개(머리 / 몸 / 배경)로 줄이고 "몸" 탭 안에 밥과 속재료를 머리글로 나누는 안도 봤다. 밥과 속재료는 동시에 쓰는 별개의 슬롯이라 한 격자에 "없음"과 "흰 밥" 두 기본 칸, 쓰는 중 표시 두 개가 섞인다. 탭이 하나 늘어도 "탭 = 바꾸는 자리"가 한 가지 규칙으로 남는 4개를 골랐다.
- 산만함을 줄이는 장치는 화면이 아니라 그림 쪽에 있다: 종류마다 크기·색 상한을 두어 넷을 다 써도 채움 색 10가지 이하, 실루엣을 바꾸는 면적은 몸의 약 41% 이하다(item-art/brief.md 2.5.2). 밥은 실루엣을 바꾸지 않고, 속재료는 왼쪽 한 자리에 머리 아이템보다 작게만 나온다.
- 빈 탭: 어떤 슬롯에 아이템이 하나도 없는 버전(가타카나만 따로 내는 경우 등)이면 그 탭을 숨기고 남은 탭이 폭을 나눈다. 지금 목록은 네 슬롯 모두 아이템이 있다.

### 3.1 와이어프레임 (375×667pt)

### 3.3 미리보기 크기

`S = min(260, max(200, 화면 높이 ÷ 2 − 내용 위 끝 − 70))`

- 내용 위 끝 = 위 안전 영역 + 내비게이션 바 44pt. 70 = 위 여백 8 + 간격 8 + 안내 줄 42 + 간격 12.
- 뜻: 슬롯 탭의 위 끝이 화면 절반선에 오도록 미리보기를 가능한 한 크게 잡되, 200~260pt 안에서.
- 기리 외곽선(360 좌표계 6)은 200pt에서 3.3pt, 260pt에서 4.3pt다. 홈(64pt)이나 완료(120pt)보다 굵지만 미리보기 카드 외곽선(2pt)과 겹치지 않는 안쪽 그림이라 그대로 둔다.

| 화면 | 위 안전 영역 | 내용 위 끝 | 계산 | S |
|---|---|---|---|---|
| 375×667 | 20 | 64 | 333.5 − 64 − 70 = 199.5 | 200 |
| 393×852 | 59 | 103 | 426 − 103 − 70 = 253 | 253 |
| 402×874 | 62 | 106 | 437 − 106 − 70 = 261 | 260 |

| 기본 차림 아이템 (요리사 모자, 흰 밥) | 썸네일 (흰 밥은 흰 밥의 밥 썸네일, 8.4) | 한국어 이름("요리사 모자", "흰 밥", 15pt). 가나 이름은 없다(reward-system.md 1.4) | "쓰는 중" 또는 "가짐" |

- 머리 썸네일은 모자류와 토핑이 같은 viewBox(8.4)로 잘린다. 토핑은 칸에서 모자보다 작게(60pt 칸에서 폭 약 43pt 이하) 보이며, 기리 위에 올렸을 때의 크기 차이와 같다.
- 밥 썸네일은 얼굴 없는 "밥 덩어리"(몸 바탕 + 무늬 + 김 + 외곽선)라 세 칸이 같은 모양이고 색과 무늬로 갈린다. 잠긴 칸의 실루엣은 모두 같은 오니기리 모양이 되지만 장면 이름과 "잠김"이 구분을 맡는다.

- 잠긴 칸에서 가나 이름을 숨기는 이유: 앞으로 배울 글자가 든 이름(예: 7 온천의 てぬぐい)을 미리 보여 주지 않고, 이름이 열리는 순간을 C2에 남긴다. 장면 이름으로 "어디서 열리는지"는 알린다.
- 엔 부족 칸의 썸네일을 흐리게 하지 않는 이유: 무엇을 모으는지 보여야 엔을 모을 이유가 된다. 흐리게(불투명도 0.4)는 비활성 버튼의 규칙(visual-rules.md 1.3)인데, 이 칸은 눌러서 미리 볼 수 있다.
- K에는 `Correct`, `Wrong` 색을 쓰지 않는다. 쓰는 중 표시도 `AccentColor`다. 판정 화면이 아니고, 아이템 그림 안의 빨강·초록과 판정 색이 같은 화면에서 만나지 않게 한다.
- 1차 버전에는 장면 데이터가 있는 히라가나 아이템 16개만 칸으로 둔다. 가타카나 아이템은 그 장면이 앱에 들어올 때 함께 나타난다.

### 3.6 처음 들어왔을 때 고른 슬롯

저장하지 않고 들어올 때마다 정한다. (2026-11-16 개정)

1. 살 수 있는 아이템이 있으면: 그 가운데 **가장 늦은 장면의 아이템이 든 탭**. 같은 장면에 살 수 있는 아이템이 둘이면 탭 순서(머리 → 속재료 → 밥 → 배경)가 앞인 탭.
2. 살 수 있는 아이템이 없으면: 머리.

예: 소바·우동집을 막 끝내 ちくわ(머리)와 えび天(속재료)을 살 수 있으면 머리. 그중 하나를 사고 나서 다시 들어오면 남은 쪽의 탭.

스크롤 위치: 고른 탭에 살 수 있는 아이템이 있으면 그중 가장 늦은 장면의 아이템(같은 장면이면 데이터 순서가 앞인 것) 칸이 격자 안에 다 보이도록 스크롤한 상태로 시작한다(`ScrollViewReader.scrollTo(id, anchor: .bottom)`, 움직임 없이). 그 칸이 처음 2행 안에 있으면 맨 위 그대로다. 살 수 있는 아이템이 없으면 맨 위. C2에서 바로 들어오면 방금 열린 아이템이 보이게 된다. 지금 목록에서 스크롤이 생기는 것은 머리 탭 3행(はちまき, てぬぐい, まんじゅう)뿐이다(3.4).

안내 줄은 고른 슬롯의 "처음" 문구(3.8)다.

### 3.7 조작과 사기 흐름

칸 하나를 누르면 그 칸의 상태에 따라 아래 중 하나가 일어난다.

| 누른 칸 | 미리보기 | 저장 | 안내 줄 (1줄 / 2줄) | 확인 창 | 햅틱 |
|---|---|---|---|---|---|
| 쓰는 중 | 그대로 | 없음 | {이름} / 지금 쓰고 있어요 | 없음 | 없음 |
| 가짐 | 그 슬롯을 이 아이템으로 바꿈 | `equipped` 갱신 | {이름} / 바꿨어요 | 없음 | `.impact(weight: .light)` |
| 없음 (밥 탭에는 없음) | 그 슬롯을 비움 | `equipped`에서 그 슬롯 키 삭제 | 없음 / 머리를·속재료를·배경을 비웠어요 | 없음 | `.impact(weight: .light)` |
| 살 수 있음 | **올려 봄** (임시) | 없음 | {이름} / 미리 보는 중이에요 · {값}엔 | **뜸** (아래) | 없음 |
| 엔 부족 | **올려 봄** (임시) | 없음 | {이름} / {모자란 엔}엔이 더 있으면 살 수 있어요 | 없음 | 없음 |
| 잠김 | 그대로 (실루엣은 올려 보지 않음) | 없음 | {장면} 장면 아이템 / {장면} 장면을 끝내면 열려요 | 없음 | 없음 |

**확인 창** (`confirmationDialog`, `titleVisibility: .visible`):

- 제목: "{가나}({한국어})를 {값}엔에 살까요?" (예: "{가나}({한국어 이름})을/를 300엔에 살까요?". 조사 을/를은 한국어 이름의 받침으로 고른다)
- 메시지: "산 아이템은 되돌릴 수 없어요"
- 버튼: "{값}엔으로 사기", "취소"(`role: .cancel`)
- iPhone에서 화면 아래쪽에 뜨므로 엄지가 닿고, 위쪽의 미리보기(올려 본 모습)를 가리지 않는다.

확인 단계를 두는 이유: 산 아이템은 되팔 수 없다(reward-system.md 2.3). 흔들리는 환경에서 칸을 잘못 눌러 300엔을 쓰는 일을 막는다. 대신 확인 창이 뜨는 동안 미리보기에 올려 보여 주므로, 창 한 번이 "미리 보기"와 "확인"을 함께 한다. 사기는 2탭(칸, 사기)이다.

사기의 갈래:

| 갈래 | 일어나는 일 |
|---|---|
| 성공 ("{값}엔으로 사기") | 한 번의 저장으로 잔액 차감, `owned`에 추가, 그 슬롯에 착용(reward-system.md 5.1, 6.2). 칸은 "쓰는 중"으로, 미리 보기 점선은 사라진다. 가진 엔 숫자가 바뀐다. 안내 줄: {이름} / 사서 바꿨어요. 햅틱 `.success`. 슬롯 탭의 엔 아이콘과 다른 칸의 "살 수 있음 / 엔 부족"을 새 잔액으로 다시 계산한다 |
| 취소 ("취소", 창 밖 탭, 아래로 쓸어 닫기) | 미리보기를 원래 차림으로 되돌린다. 칸의 점선이 사라진다. 안내 줄은 그 슬롯의 "처음" 문구. 저장 없음 |
| 엔 부족 | 창을 띄우지 않는다(사기 버튼을 비활성으로 보여 주는 창은 누를 것이 "취소"뿐이라 탭만 는다). 올려 보기만 하고 안내 줄로 모자란 엔을 알린다. 미리 보기는 다른 칸을 누르거나, 같은 칸을 다시 누르거나, 슬롯을 바꾸거나, 화면을 나가면 끝난다 |
| 잠김 | 아무것도 올리지 않는다. 안내 줄로 열리는 장면을 알린다 |
| 창이 떠 있는 동안 앱이 백그라운드로 감 | 창이 닫히면 취소와 같다. 아무것도 저장하지 않는다 |
| 저장 도중 앱이 꺼짐 | reward-system.md 6.2대로 셋을 한 번에 저장하므로 일부만 남지 않는다 |

**바꾸기·비우기**: 가진 아이템은 칸을 한 번 누르면 바로 쓴다(되돌릴 수 있어 확인 없음). 비우기는 "없음" 칸으로 한다. 쓰는 중인 칸을 다시 눌러 비우는 토글은 두지 않는다. 흔들려서 두 번 눌리면 올렸다 내리는 일이 생기기 때문이다.

**기본 차림으로**: 오른쪽 위 "기본 차림으로"를 누르면 확인 없이 바로 머리 = 요리사 모자, 속재료 = 비움, 밥 = 흰 밥, 배경 = 비움으로 바꾸고 저장한다. 빨간 두건과 김은 고정이라 바뀌지 않는다. 안내 줄: 기본 차림 / 기본 차림으로 돌아왔어요. 햅틱 `.impact(weight: .light)`. 확인을 두지 않는 이유: 가진 아이템은 하나도 잃지 않고, 되돌리는 데 칸 누르기 몇 번이면 된다. 엄지가 쉽게 닿지 않는 자리라 잘못 누를 일도 적다. 미리 보는 중이었다면 미리 보기도 끝낸다. 지금 차림이 기본 차림이면 버튼은 `disabled`.
- 버튼을 남기는 이유(2026-11-16 확정): 네 슬롯을 손으로 되돌리면 탭 4번 + 칸 4번이다.

**밥 탭**: 밥은 비울 수 없어 "없음" 칸이 없다. 흰 밥 칸이 그 자리를 맡는다. 밥 칸을 누르면 미리보기 기리의 본체 레이어가 그 밥의 것으로 바뀐다(0.2초 페이드).

**슬롯 바꾸기**: 슬롯 탭을 누르면 격자를 그 슬롯의 칸으로 바꾸고 3.6의 스크롤 위치 규칙으로 시작한다. 미리 보는 중이었다면 끝낸다. 안내 줄은 새 슬롯의 "처음" 문구.

**움직임**: 미리보기의 레이어가 바뀔 때 0.2초 페이드, 가진 엔 숫자는 `.contentTransition(.numericText())`. 산 뒤에 기리가 웃거나 커지는 연출은 없다(reward-system.md 5.2, visual-rules.md 6.2). "동작 줄이기"에서는 둘 다 없이 바로 바꾼다.

### 3.8 안내 줄의 문구

1줄 = 아이템 이름(가나 + 한국어), 2줄 = 상태. 가나 이름이 없는 칸(없음, 기본 차림, 잠김)은 한국어만.

| 경우 | 1줄 | 2줄 |
|---|---|---|
| 처음 (머리를 고름, 아이템이 있음) | {쓰는 아이템 이름} | 머리에 쓰고 있어요 |
| 처음 (속재료를 고름, 아이템이 있음) | {쓰는 아이템 이름} | 속재료로 쓰고 있어요 |
| 처음 (밥을 고름) | {쓰는 아이템 이름} (흰 밥이면 "흰 밥") | 이 밥으로 쓰고 있어요 |
| 처음 (배경을 고름, 아이템이 있음) | {쓰는 아이템 이름} | 배경으로 쓰고 있어요 |
| 처음 (슬롯이 비어 있음) | 없음 | 머리가 비어 있어요 / 속재료가 비어 있어요 / 배경이 비어 있어요 |
| 그 밖 | 3.7 표 | 3.7 표 |

슬롯 이름의 조사는 받침 판별 없이 슬롯마다 문구를 따로 둔다: 머리가·머리를·머리에, 속재료가·속재료를·속재료로, 배경이·배경을·배경으로. 밥은 비어 있는 상태와 비우기 문구가 없다.

### 3.9 전환

- 뒤로 버튼, 왼쪽 가장자리 스와이프 → H 홈. 미리 보던 것은 버린다.
- 다른 화면으로 가는 길은 없다.

### 3.10 처음 써 볼 때 (아무 장면도 끝내지 않음)

가진 엔 0엔. 머리 탭은 "없음 / 요리사 모자(쓰는 중)" 2칸 + 잠긴 칸 7개, 속재료는 "없음(쓰는 중)" + 잠긴 칸 3개, 밥은 "흰 밥(쓰는 중)" + 잠긴 칸 2개, 배경은 "없음(쓰는 중)" + 잠긴 칸 4개. 고른 탭은 머리(살 수 있는 것이 없으므로, 3.6). 안내 줄은 "요리사 모자 / 머리에 쓰고 있어요". 따로 빈 상태 화면이나 안내 그림은 두지 않는다. 잠긴 칸의 "잠김"과 장면 이름이 무엇을 하면 열리는지 알린다.

열린 아이템을 모두 산 뒤에도 빈 상태는 없다(칸은 늘 있다). 엔이 0이고 열린 것을 다 샀으면 칸은 "쓰는 중 / 가짐 / 잠김"만 보인다.

### 8.5 배경 아이템

- 360×360 전체를 채운다(K 미리보기에서만 쓰이고 미리보기 모서리 20pt로 잘린다).
- 기리 뒤 영역(x 20~280, y 40~350)은 밝고(라이트니스 높게) 세부가 적게 그린다. 기리 외곽선 `#4A2219`가 바탕에 묻히지 않게 하기 위해서다. 세부와 물건은 가장자리에 둔다.
- 그림 속 가나(のれん의 すし, ゆ의 노렌, えき의 역명판)는 x −30~60 또는 x 240~330, y 0~150 안에 둔다. 머리 아이템(x 64~236)과 기리 몸에 가리지 않는 자리다.
- 그림 속 가나는 시스템 글꼴이 아니라 경로로 그린다(SVG 안의 글꼴은 기기마다 다르게 그려질 수 있다). 모양은 교과서체에 가까운 KanjiVG 획을 굵게 그리는 방식을 권장한다.

### 9.2 큰 글자 크기

- K: 텍스트 스타일 글자는 모두 설정을 따른다. 가나(칸 15pt, 안내 줄 17pt, 발음 표기 10pt)는 고정 크기다(visual-rules.md 2.4).

  - 슬롯 탭 문구는 `minimumScaleFactor(0.75)`(3.2와 같음).
- H 기리 행: 접근성 크기에서 기리를 숨긴다. 글자는 줄을 바꾼다.
- C1·C2: 지금처럼 내용 영역이 스크롤된다. 받은 엔 줄은 `ViewThatFits`로 두 줄이 된다. C2 썸네일 44pt는 고정.

## 11. 저장 상태와 화면이 넘겨받는 값

### 11.1 더 저장할 것

**reward-system.md 7번의 `RewardState`(coins, paid, owned, equipped) 말고 화면 때문에 더 저장하는 값은 없다.**

| 화면 상태 | 저장하지 않는 이유 |
|---|---|
| K에서 고른 슬롯 | 들어올 때마다 3.6 규칙으로 정한다 |
| 미리 보는 중인 아이템 | 화면을 나가면 버린다 |
| 홈의 "살 수 있는 아이템이 있어요", K 슬롯 탭의 엔 아이콘 | 잔액, 열린 아이템(`paid`), `owned`로 계산 |
| "새로 열린 아이템을 봤는지" (NEW 표시) | 두지 않는다. 살 수 있는지만 알린다 |

4종류 개편(2026-11-16)으로도 화면이 더 저장하는 값은 없다. `equipped`의 키는 슬롯 id `top`, `filling`, `rice`, `background`다(reward-system.md "꾸미기 개편" 1번). `rice` 키가 없으면 흰 밥(`plain_rice`)으로 본다. 사용자가 아직 없어 옛 진도(`hat`, `scarf`, `hand` 키와 빠진 아이템)는 옮기지 않고 읽을 때 버린다(PLAN.md 9번 2026-11-16).

### 11.2 세션 완료가 넘겨주는 값 (저장하지 않음)

C1·C2는 "이번에 받은 것"을 보여 줘야 한다. 세션을 완료로 바꾸는 저장(`completeSession`)이 그 순간의 지급 결과를 돌려주고, 완료 화면이 그 값으로 그린다. 앱을 닫으면 사라지며 완료 화면은 다시 나오지 않는다(지금 규칙과 같음).

```swift
struct RewardGrant {
    var coins: Int                 // 이번에 받은 엔. 다시 한 세션이면 0 → 받은 엔 줄을 그리지 않는다
    var milestoneCoins: Int        // 히라가나 완료 600, 그 밖 0
    var unlockedItemIDs: [String]  // 이번에 열린 아이템 (장면 완료 때)
    var grantedItemIDs: [String]   // 16장면 완료로 받은 아이템
    var balance: Int               // 지급 뒤 잔액
}
```

- 앱을 켤 때의 맞추기 지급(reward-system.md 6.2 마지막 줄)은 화면에 따로 알리지 않는다. 홈의 가진 엔이 바뀌어 보인다.

### 11.3 데이터에 더할 것

- 아이템 데이터(`rewards.json`, reward-system.md 7번)에 이름의 글자별 발음 `units`(단어 데이터의 `units`와 같은 꼴: `kana`, `romaji`)를 더한다. 칸과 C2의 발음 표기 줄에 필요하다. planner가 채운다.
- 한국어 이름(`nameKo`)은 안내 줄 1줄에 가나 이름과 함께 들어간다. 375pt에서 "{가나} {한국어}"와 가진 엔(약 90pt)이 한 줄에 들어가려면 한국어 이름은 10자 안팎이 좋다. 지금 목록에서 가장 긴 것은 "머리 옆에 건 축제 가면"(11자), "노렌이 걸린 가게 앞"(10자)이다. 화면 이름은 "축제 가면", "노렌 가게 앞"처럼 짧게 쓴다(14번 절의 11). 데이터를 채우는 일은 planner 몫이다.
