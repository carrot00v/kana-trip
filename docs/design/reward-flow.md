## 1. 전체 흐름에서 바뀌는 곳

```
[H] 홈
  ├─ 기리 행 탭 ─────────────────► [K] 기리 꾸미기 (push)
  ├─ 장면 행 탭 ─────────────────► [S] 장면 진입 (그대로)
  └─ 아래 주 버튼 ───────────────► 세션 (그대로)

[C1] 세션 완료 ── 받은 엔 한 줄만 더함. 버튼과 전환은 그대로
[C2] 장면 완료
  ├─ 주 버튼 "장면 목록으로" ────► [H] (그대로)
  └─ 글자 버튼 "기리 꾸미기" ────► 덮개를 닫고 [H] 위에 [K] push

[K] 기리 꾸미기
  └─ 뒤로(왼쪽 위 버튼, 가장자리 스와이프) ─► [H]
```

- 사고 입는 일은 K 한 곳에서만 한다(reward-system.md 2.3, 5.1). 세션 화면(L1~W)에는 아무것도 더하지 않는다.
- K에서 세션으로 바로 가는 길은 두지 않는다. 학습 흐름과 꾸미기를 섞지 않는다.

## 2. 들어가는 길

### 2.1 홈의 어디를 누르나 (reward-system.md 13번의 1에 대한 답)

**결정: 홈 목록 맨 위에 "기리 행"을 둔다. 지금 "히라가나" 섹션 머리글 오른쪽의 64pt 기리를 이 행의 왼쪽으로 옮긴다.**

| 후보 | 판단 |
|---|---|
| 머리글의 기리 그림을 누르게 한다 | 글자가 없어 누를 수 있는지 알 수 없다. VoiceOver에서도 숨겨진 그림이라 레이블을 새로 붙여야 하고, visual-rules.md 7.2의 "캐릭터를 버튼으로 쓰지 않는다"를 정면으로 깬다 |
| 오른쪽 위 툴바에 버튼을 더한다 | 엄지가 닿지 않는 자리에 세 번째 버튼이 생긴다. 메뉴(`ellipsis.circle`)와 붙어 잘못 누르기 쉽다. 잔액을 함께 보여 줄 자리가 없다 |
| 아래 주 버튼 옆에 보조 버튼을 둔다 | 홈의 주 버튼 문구("밥집 간판 · 단어 읽기 이어서 하기", 약 280pt)가 375pt 폭에서 112pt 보조 버튼과 함께 들어가지 않는다. 학습 시작 버튼 옆에 꾸미기가 있으면 시선이 나뉜다 |
| 목록 맨 아래에 행을 둔다 | 장면 행 8개(608pt) 아래라 스크롤해야 보인다. 장면을 끝내고 돌아왔을 때 "살 것이 있음"이 보이지 않는다 |
| **목록 맨 위에 기리 행 (채택)** | 글자("기리 꾸미기")와 잔액이 있어 무엇을 하는 행인지 바로 보인다. 목록 행은 행 전체가 누르는 영역이라는 기존 규칙(visual-rules.md 4.2)을 그대로 쓴다. 기리 그림은 행 안의 장식으로 남고 따로 누르는 대상이 되지 않는다. 장면을 끝내고 홈에 오면 첫눈에 보인다 |

- 위쪽 절반에 누르는 대상이 생기는 점: 장면 행도 이미 목록 위쪽에 있다. 기리 행은 하루 몇 번 쓰는 조작이고, 세션을 시작하는 조작(아래 주 버튼)은 그대로 아래에 있다.
- 바뀌는 규칙: visual-rules.md 4.2 "캐릭터 그림은 누를 수 없다"를 "캐릭터 그림만 따로 누르는 대상이 되지 않는다. 캐릭터가 든 목록 행은 행 전체가 누르는 영역이다"로 고친다(12번 절).

### 2.2 띄우는 방식

**결정: push (`NavigationStack`).**

- K는 할 일을 마치고 닫는 작업 창이 아니라 언제든 둘러보는 장소다. 장면 진입(S)과 같은 단계의 화면이라 같은 방식으로 띄운다.
- K에는 획을 긋는 캔버스가 없어 가장자리 스와이프와 겹칠 동작이 없다(scene-flow.md 2.1이 세션을 덮개로 띄운 이유가 해당하지 않는다).
- sheet로 띄우면 아이템 격자를 위로 스크롤하다가 시트가 끌려 내려가는 일이 생기고, C2에서 열 때 덮개 위에 시트가 겹쳐 닫은 뒤 다시 C2로 돌아온다.
- 홈의 `path`가 지금은 장면 id 문자열 배열이다. K로 가는 값을 하나 더해야 한다(예: `enum HomeRoute: Hashable { case scene(String), customize }`). 이름은 개발 담당이 정한다.

C2에서 들어갈 때: "기리 꾸미기"를 누르면 ① 덮개를 닫고 ② `path = [.customize]`로 바꾼다. 장면 진입(S)은 쌓지 않는다. K에서 뒤로 가면 홈이 나오고, 홈에는 장면 완료와 다음 장면 열림이 이미 반영돼 있다.

### 3.3 미리보기 크기

`S = min(260, max(200, 화면 높이 ÷ 2 − 내용 위 끝 − 70))`

- 내용 위 끝 = 위 안전 영역 + 내비게이션 바 44pt. 70 = 위 여백 8 + 간격 8 + 안내 줄 42 + 간격 12.
- 뜻: 슬롯 버튼의 위 끝이 화면 절반선에 오도록 미리보기를 가능한 한 크게 잡되, 200~260pt 안에서.
- 기리 외곽선(360 좌표계 6)은 200pt에서 3.3pt, 260pt에서 4.3pt다. 홈(64pt)이나 완료(120pt)보다 굵지만 미리보기 카드 외곽선(2pt)과 겹치지 않는 안쪽 그림이라 그대로 둔다.

| 화면 | 위 안전 영역 | 내용 위 끝 | 계산 | S |
|---|---|---|---|---|
| 375×667 | 20 | 64 | 333.5 − 64 − 70 = 199.5 | 200 |
| 393×852 | 59 | 103 | 426 − 103 − 70 = 253 | 253 |
| 402×874 | 62 | 106 | 437 − 106 − 70 = 261 | 260 |

- 아이템이 장면당 3개로 늘면 히라가나 한 슬롯이 최대 9칸(3행)이 된다. 375×667pt에서 3행 위쪽 1pt만 보이고 스크롤로 본다. 구조는 바뀌지 않는다. 가타카나까지 들어가면 손 슬롯이 11칸(4행)이다.

### 3.5 아이템 칸

크기: 폭은 격자 열 폭(375pt에서 (343 − 16) ÷ 3 = 109pt, 393pt에서 115pt), 높이 126pt.

칸의 순서(슬롯마다): ① "없음" ② 기본 차림 아이템(모자: 요리사 모자, 두건: 빨간 두건. 손·배경에는 없음) ③ 나머지 아이템을 장면 순서대로. 상태가 바뀌어도 칸의 순서는 움직이지 않는다.

**상태별 모습** (색만으로 구분하지 않는다. "색 밖의 표시" 열이 구분을 맡는다):

특수 칸:

| 칸 | 썸네일 자리 | 이름 줄 | 상태 줄 |
|---|---|---|---|
| 없음 | `circle.slash` 28pt, `InkSecondary` | "없음"(15pt) | 그 슬롯이 비어 있으면 "입는 중" 모양(외곽선 3pt, 체크 배지 포함). 아니면 비움 |
| 기본 차림 아이템 | 썸네일 | 한국어 이름("요리사 모자", "빨간 두건", 15pt). 가나 이름은 없다(reward-system.md 1.4) | "입는 중" 또는 "가짐" |

- 잠긴 칸에서 가나 이름을 숨기는 이유: 앞으로 배울 글자가 든 이름(예: 7 온천의 てぬぐい)을 미리 보여 주지 않고, 이름이 열리는 순간을 C2에 남긴다. 장면 이름으로 "어디서 열리는지"는 알린다.
- 엔 부족 칸의 썸네일을 흐리게 하지 않는 이유: 무엇을 모으는지 보여야 엔을 모을 이유가 된다. 흐리게(불투명도 0.4)는 비활성 버튼의 규칙(visual-rules.md 1.3)인데, 이 칸은 눌러서 입어 볼 수 있다.
- K에는 `Correct`, `Wrong` 색을 쓰지 않는다. 입은 표시도 `AccentColor`다. 판정 화면이 아니고, 아이템 그림 안의 빨강·초록과 판정 색이 같은 화면에서 만나지 않게 한다.
- 1차 버전에는 장면 데이터가 있는 히라가나 아이템 16개만 칸으로 둔다. 가타카나 아이템은 그 장면이 앱에 들어올 때 함께 나타난다.

### 3.6 처음 들어왔을 때 고른 슬롯

저장하지 않고 들어올 때마다 정한다.

1. 살 수 있는 아이템이 있으면: 그중 가장 늦은 장면의 아이템 가운데 데이터 순서가 앞인 아이템의 슬롯. C2에서 바로 들어오면 방금 열린 아이템의 슬롯이 된다.
2. 없으면: 모자.

격자는 맨 위로 스크롤한 상태로 시작한다. 안내 줄은 고른 슬롯의 "처음" 문구(3.8)다.

### 3.7 조작과 사기 흐름

칸 하나를 누르면 그 칸의 상태에 따라 아래 중 하나가 일어난다.

| 누른 칸 | 미리보기 | 저장 | 안내 줄 (1줄 / 2줄) | 확인 창 | 햅틱 |
|---|---|---|---|---|---|
| 입는 중 | 그대로 | 없음 | {이름} / 지금 입고 있어요 | 없음 | 없음 |
| 가짐 | 그 슬롯을 이 아이템으로 바꿈 | `equipped` 갱신 | {이름} / 입었어요 | 없음 | `.impact(weight: .light)` |
| 없음 | 그 슬롯을 비움 | `equipped`에서 그 슬롯 키 삭제 | 없음 / {슬롯} 자리를 비웠어요 | 없음 | `.impact(weight: .light)` |
| 살 수 있음 | **입혀 봄** (임시) | 없음 | {이름} / 입어 보는 중이에요 · {값}엔 | **뜸** (아래) | 없음 |
| 엔 부족 | **입혀 봄** (임시) | 없음 | {이름} / {모자란 엔}엔이 더 있으면 살 수 있어요 | 없음 | 없음 |
| 잠김 | 그대로 (실루엣은 입혀 보지 않음) | 없음 | {장면} 장면 아이템 / {장면} 장면을 끝내면 열려요 | 없음 | 없음 |

**확인 창** (`confirmationDialog`, `titleVisibility: .visible`):

- 제목: "{가나}({한국어})를 {값}엔에 살까요?" (예: "おめん(축제 가면)을 300엔에 살까요?". 조사 을/를은 한국어 이름의 받침으로 고른다)
- 메시지: "산 아이템은 되돌릴 수 없어요"
- 버튼: "{값}엔으로 사기", "취소"(`role: .cancel`)
- iPhone에서 화면 아래쪽에 뜨므로 엄지가 닿고, 위쪽의 미리보기(입혀 본 모습)를 가리지 않는다.

확인 단계를 두는 이유: 산 아이템은 되팔 수 없다(reward-system.md 2.3). 흔들리는 환경에서 칸을 잘못 눌러 300엔을 쓰는 일을 막는다. 대신 확인 창이 뜨는 동안 미리보기에 입혀 보여 주므로, 창 한 번이 "입어 보기"와 "확인"을 함께 한다. 사기는 2탭(칸, 사기)이다.

사기의 갈래:

| 갈래 | 일어나는 일 |
|---|---|
| 성공 ("{값}엔으로 사기") | 한 번의 저장으로 잔액 차감, `owned`에 추가, 그 슬롯에 착용(reward-system.md 5.1, 6.2). 칸은 "입는 중"으로, 입어 보기 점선은 사라진다. 가진 엔 숫자가 바뀐다. 안내 줄: {이름} / 사서 입었어요. 햅틱 `.success`. 슬롯 버튼의 엔 아이콘과 다른 칸의 "살 수 있음 / 엔 부족"을 새 잔액으로 다시 계산한다 |
| 취소 ("취소", 창 밖 탭, 아래로 쓸어 닫기) | 미리보기를 입고 있던 차림으로 되돌린다. 칸의 점선이 사라진다. 안내 줄은 그 슬롯의 "처음" 문구. 저장 없음 |
| 엔 부족 | 창을 띄우지 않는다(사기 버튼을 비활성으로 보여 주는 창은 누를 것이 "취소"뿐이라 탭만 는다). 입혀 보기만 하고 안내 줄로 모자란 엔을 알린다. 입어 보기는 다른 칸을 누르거나, 같은 칸을 다시 누르거나, 슬롯을 바꾸거나, 화면을 나가면 끝난다 |
| 잠김 | 아무것도 입히지 않는다. 안내 줄로 열리는 장면을 알린다 |
| 창이 떠 있는 동안 앱이 백그라운드로 감 | 창이 닫히면 취소와 같다. 아무것도 저장하지 않는다 |
| 저장 도중 앱이 꺼짐 | reward-system.md 6.2대로 셋을 한 번에 저장하므로 일부만 남지 않는다 |

**입기·벗기**: 가진 아이템은 칸을 한 번 누르면 바로 입는다(되돌릴 수 있어 확인 없음). 벗기는 "없음" 칸으로 한다. 입는 중인 칸을 다시 눌러 벗기는 토글은 두지 않는다. 흔들려서 두 번 눌리면 입었다 벗는 일이 생기기 때문이다.

**기본 차림으로**: 오른쪽 위 "기본 차림으로"를 누르면 확인 없이 바로 모자 = 요리사 모자, 두건 = 빨간 두건, 손·배경 = 비움으로 바꾸고 저장한다. 안내 줄: 기본 차림 / 기본 차림으로 돌아왔어요. 햅틱 `.impact(weight: .light)`. 확인을 두지 않는 이유: 가진 아이템은 하나도 잃지 않고, 되돌리는 데 칸 누르기 몇 번이면 된다. 엄지가 쉽게 닿지 않는 자리라 잘못 누를 일도 적다. 입어 보는 중이었다면 입어 보기도 끝낸다.

**슬롯 바꾸기**: 슬롯 버튼을 누르면 격자를 그 슬롯의 칸으로 바꾸고 맨 위로 스크롤한다. 입어 보는 중이었다면 끝낸다. 안내 줄은 새 슬롯의 "처음" 문구.

**움직임**: 미리보기의 레이어가 바뀔 때 0.2초 페이드, 가진 엔 숫자는 `.contentTransition(.numericText())`. 산 뒤에 기리가 웃거나 커지는 연출은 없다(reward-system.md 5.2, visual-rules.md 6.2). "동작 줄이기"에서는 둘 다 없이 바로 바꾼다.

### 3.8 안내 줄의 문구

1줄 = 아이템 이름(가나 + 한국어), 2줄 = 상태. 가나 이름이 없는 칸(없음, 기본 차림, 잠김)은 한국어만.

| 경우 | 1줄 | 2줄 |
|---|---|---|
| 처음 (슬롯에 아이템을 입음) | {입은 아이템 이름} | {슬롯}에 입고 있어요 |
| 처음 (슬롯이 비어 있음) | 없음 | {슬롯}이/가 비어 있어요 |
| 그 밖 | 3.7 표 | 3.7 표 |

슬롯 이름의 조사: 모자가, 두건이, 손이, 배경이.

### 3.9 전환

- 뒤로 버튼, 왼쪽 가장자리 스와이프 → H 홈. 입어 보던 것은 버린다.
- 다른 화면으로 가는 길은 없다.

### 3.10 처음 써 볼 때 (아무 장면도 끝내지 않음)

가진 엔 0엔. 모자·두건 슬롯은 "없음 / 기본(입는 중)" 2칸 + 잠긴 칸, 손·배경은 "없음(입는 중)" + 잠긴 칸 5개. 안내 줄은 "요리사 모자 / 모자에 입고 있어요". 따로 빈 상태 화면이나 안내 그림은 두지 않는다. 잠긴 칸의 "잠김"과 장면 이름이 무엇을 하면 열리는지 알린다.

### 4.1 기리 행

```
┌──────────────────────────────────────┐
│                                  (…) │
│ 니혼go                               │
│ ┌──────────────────────────────────┐ │
```

구성 (왼쪽에서 오른쪽):

| 요소 | 값 |
|---|---|
| 자리 | 목록의 첫 섹션(머리글 없음), 행 하나. `insetGrouped`, 바탕 `CardBackground` |
| 행 높이 | 80pt 이상 (기리 64 + 위아래 8) |
| 기리 | 64×64pt, 기본 표정, 입은 아이템(배경 제외, 7번 절). 행 안의 장식이라 따로 누를 수 없고 VoiceOver에서 읽지 않는다 |
| 간격 | 12pt |
| 1줄 | "기리 꾸미기" `.headline`, `Ink` |
| 2줄 | "가진 엔 {n}엔" `.subheadline.monospacedDigit()`, `InkSecondary` |
| 3줄 (살 수 있을 때만) | `yensign.circle.fill`(`HighlightStrong`) + 4pt + "살 수 있는 아이템이 있어요" `.footnote`, `Ink` |
| 오른쪽 끝 | `chevron.right` (장면 행과 같은 모양) |
| 누르기 | 행 전체 → K push |

- "살 수 있는 아이템이 있음" = 가진 엔 ≥ 어떤 열린·안 가진 아이템의 값. 저장하지 않고 계산한다(reward-system.md 3.2). 열린 것을 다 샀거나 엔이 모자라면 3줄은 없다(행 높이는 80pt 그대로).
- 숫자 배지(`.badge`)나 빨간 점을 쓰지 않는 이유: 숫자는 무엇의 개수인지 알 수 없고, 빨간 점은 `Wrong`과 섞인다. 글자로 알린다.
- "히라가나" 섹션 머리글은 기리가 빠지므로 기본 높이(약 28pt)로 돌아간다.
- 접근성 글자 크기(`accessibility1` 이상): 기리를 숨긴다(지금 규칙과 같음). 글자는 줄을 바꿔 행이 높아진다.

### 6.2 구성 요소 (위에서 아래)

1. 위 여백: `min(내용 영역 ÷ 3 − 120, 내용 영역 − 나머지 합계)`, 최소 24pt. 지금 규칙(기리 아래 끝을 위에서 3분의 1)을 지키되, 모자라면 위 여백부터 줄인다. 24pt까지 줄여도 넘치면 내용 영역이 스크롤된다(지금 구현의 `ScrollView` 그대로).

3. 제목, 요약. 그대로.
4. ~~배운 글자 줄(34pt)~~ **뺀다.** 요약 문구("히라가나 6자를 읽고 쓸 수 있어요")가 글자 수를 말하고, 아래 목표 단어가 그 글자들로 이뤄진 단어를 보여 준다. 배운 글자는 C1(배우기 완료)과 홈의 장면 행에서 볼 수 있다. 자리를 만들려면 뺄 것이 필요했고, 이 화면에서만 볼 수 있는 목표 단어보다 다른 화면에도 있는 글자 줄을 골랐다(14번 절의 5).
5. 목표 단어 묶음. 그대로(간격 24 + 20 + 8 + 28 = 80pt).
6. 리워드 묶음 (새로, 간격 24pt 아래):
   - 받은 엔 줄(5번 절의 부품). 22pt.
   - (히라가나 전체 완료 때만) 4pt 아래 마일스톤 줄. 6.3.
   - 8pt 아래 "새 아이템 {n}개가 열렸어요"(`.subheadline`, `InkSecondary`, 20pt).
   - 8pt 아래 열린 아이템 줄(78pt): 아이템마다 세로 묶음 [썸네일 44×44pt, 바탕 `CardBackground`, 모서리 10pt, `Outline` 2pt / 간격 2 / 발음 표기 줄 12 / 가나 이름 15pt 20]. 묶음 사이 16pt, 가운데 정렬. 누를 수 없다. 가격·상태는 싣지 않는다(고르는 곳은 K).
7. 다음 장면 줄 (간격 24pt 아래): "다음 장면 '{장면}'이/가 열렸어요"(`.body`, 22pt). 그 아래의 새 글자 줄(20pt)과 그 위 24pt 여백은 **뺀다**. 새 글자는 홈의 장면 행이 보여 주고, 주 버튼이 바로 그 홈으로 간다.

## 7. 작은 크기의 기리 (reward-system.md 13번의 8, 9에 대한 답)

| 자리 | 크기 | 표정 | 입은 아이템 | 배경 | 반짝임 |
|---|---|---|---|---|---|
| H 기리 행 | 64pt | 기본 | 그린다 | 안 그림 | 없음 (기본 표정) |
| C1, C2 | 120pt (접근성 크기 80pt) | 웃는 | 그린다 | 안 그림 | 손 아이템이 없으면 원래 자리(오른쪽 위), 있으면 **왼쪽 위로 뒤집어** 그림 |
| K 미리보기 | 200~260pt | 기본 | 그린다 | 그린다 | 없음 |

판단:

- **입은 아이템을 그대로 보여 준다.** 꾸민 기리를 학습 화면 밖에서 다시 보는 것이 꾸미기의 보상이다. 홈에만 보이고 완료 화면에서 기본 차림으로 돌아가면 사용자가 고른 것이 무시된 것처럼 보인다.
- **64pt 가독성**: 외곽선이 약 1.1pt, 손 아이템(기준 상자 80×100, 8.2)은 약 14×18pt가 된다. きっぷ, おまもり처럼 작은 손 아이템은 "무언가 들고 있음" 정도로만 보인다. 이름은 K에서 확인할 수 있으므로 받아들인다. 모자·두건은 기본 차림과 같은 크기라 문제없다.
- **배경은 K에서만**(reward-system.md 13번의 8에 동의). 64pt·120pt 정사각형에 장면 그림이 깔리면 기리 외곽선이 묻히고, C1·C2의 체크 배지(바깥 `AppBackground` 테두리)가 그림 위에 떠 보인다.
- **체크 배지와 손 아이템**: 배지는 C1·C2에만 있고 C1·C2는 웃는 표정이다. 배지가 덮는 범위는 360 좌표계로 원의 중심 (282, 312), 반지름 57(= (16 + 3)pt × 3)이라 x 225~339, y 255~369다. 웃는 표정의 손 아이템 범위는 x 250~330, y 84~184(8.2)라 **겹치지 않는다**. 기본 표정의 손 자리(278, 284)는 배지 범위 안이지만 기본 표정은 배지가 없는 홈과 K에서만 쓴다.
- **반짝임과 손 아이템**: 웃는 표정의 손 범위(x 250~330, y 84~184)가 노랑 반짝임(x 284~318, y 112~157)을 완전히 덮는다. reward-system.md의 권장(반짝임을 빼기) 대신 **x = 150을 축으로 좌우를 뒤집어 왼쪽 위에 그린다**로 정했다(2026-11-13 사용자 확정).
  - 이유: 반짝임은 완료 화면의 유일한 축하 표시다(visual-rules.md 6.2). 손 아이템을 산 사람만 축하 표시를 잃으면 "아이템을 들면 덜 축하받는다"가 된다.
  - 뒤집은 자리: 세 선이 (16,130)–(14,112), (2,140)–(−11,127), (−3,157)–(−18,154). 360 좌표계(x −30~330) 안이고, 모자(x 82 이상), 몸 왼쪽 끝(이 높이에서 x 약 76), 두건 매듭(y 238 이상)과 겹치지 않는다. 웃는 표정에는 왼팔이 없어 비어 있는 자리다.
  - 만드는 법: 반짝임을 따로 레이어로 내보낼 때 `transform="translate(300 0) scale(-1 1)"`을 씌운 두 번째 파일을 함께 만든다. 확정된 웃는 표정 그림 자체는 바꾸지 않는다(손 아이템이 없으면 지금과 똑같다).
  - 다른 선택지: 손 아이템이 있으면 반짝임을 그리지 않는다(reward-system.md 권장). 그림이 하나 덜 들지만 위 문제가 남는다.

- 그리는 함수를 하나의 뷰(예: `GiriView(face:, outfit:, showsBackground:)`)로 두어 H, C1, C2, K가 같이 쓴다.

### 8.4 썸네일

- 썸네일은 같은 아이템 그림을 슬롯별 정사각형 viewBox로 잘라 낸 별도 파일 `items/{id}-thumb.svg`(에셋 `ItemThumb-{id}`)로 스크립트가 함께 만든다. 아이템만 그리고 기리는 넣지 않는다(reward-system.md 5.2).

| 슬롯 | 썸네일 viewBox | 비고 |
|---|---|---|
| 모자 | `57 -16 190 190` | 8.2 범위의 가운데 |
| 두건 | `-30 104 310 310` | 띠가 가늘어 60pt에서 약 6pt 높이. 13번 절에서 확인 |
| 손 | `-50 -80 100 100` (아이템 자체 좌표) | 옮기기 전 그림 |
| 배경 | `-30 0 360 360` | 전체 |

- 크기: K 칸 60pt, C2 44pt.
- 잠긴 칸의 실루엣: 같은 썸네일을 `.renderingMode(.template)`로 그리고 `.foregroundStyle(Color.inkSecondary.opacity(0.3))`. 따로 그리지 않는다.
- 다크 모드: 그림은 한 장으로 두 모드에 쓴다(지금 기리와 같은 방침). 칸 바탕은 `CardBackground`(다크 `#2E2420`)라 진갈색 외곽선이 묻힐 수 있다. 실기기에서 보고 알아보기 어려우면 미리보기와 썸네일 바탕만 두 모드 모두 밝은 고정색(`#FFFDF7`)으로 바꾼다(13번 절). 기리를 다크에서 어떻게 보이게 할지와 같은 판단이라 함께 정한다.

### 8.5 배경 아이템

- 360×360 전체를 채운다(K 미리보기에서만 쓰이고 미리보기 모서리 20pt로 잘린다).
- 기리 뒤 영역(x 20~280, y 40~350)은 밝고(라이트니스 높게) 세부가 적게 그린다. 기리 외곽선 `#4A2219`가 바탕에 묻히지 않게 하기 위해서다. 세부와 물건은 가장자리에 둔다.
- 그림 속 가나(のれん의 すし, ゆ의 노렌, えき의 역명판)는 x −30~60 또는 x 240~330, y 0~150 안에 둔다. 모자와 기리 몸에 가리지 않는 자리다. K는 기본 표정이라 손 아이템은 오른쪽 아래(y 204 이상)에 있어 이 자리를 가리지 않는다.
- 그림 속 가나는 시스템 글꼴이 아니라 경로로 그린다(SVG 안의 글꼴은 기기마다 다르게 그려질 수 있다). 모양은 교과서체에 가까운 KanjiVG 획을 굵게 그리는 방식을 권장한다.

## 11. 저장 상태와 화면이 넘겨받는 값

### 11.1 더 저장할 것

**reward-system.md 7번의 `RewardState`(coins, paid, owned, equipped) 말고 화면 때문에 더 저장하는 값은 없다.**

| 화면 상태 | 저장하지 않는 이유 |
|---|---|
| K에서 고른 슬롯 | 들어올 때마다 3.6 규칙으로 정한다 |
| 입어 보는 중인 아이템 | 화면을 나가면 버린다 |
| 홈의 "살 수 있는 아이템이 있어요", K 슬롯 버튼의 엔 아이콘 | 잔액, 열린 아이템(`paid`), `owned`로 계산 |
| "새로 열린 아이템을 봤는지" (NEW 표시) | 두지 않는다. 살 수 있는지만 알린다 |

### 11.2 세션 완료가 넘겨주는 값 (저장하지 않음)

C1·C2는 "이번에 받은 것"을 보여 줘야 한다. 세션을 완료로 바꾸는 저장(`completeSession`)이 그 순간의 지급 결과를 돌려주고, 완료 화면이 그 값으로 그린다. 앱을 닫으면 사라지며 완료 화면은 다시 나오지 않는다(지금 규칙과 같음).

```swift
struct RewardGrant {
    var coins: Int                 // 이번에 받은 엔. 다시 한 세션이면 0 → 받은 엔 줄을 그리지 않는다
    var milestoneCoins: Int        // 히라가나 완료 600, 그 밖 0
    var unlockedItemIDs: [String]  // 이번에 열린 아이템 (장면 완료 때)
    var grantedItemIDs: [String]   // 16장면 완료로 받은 아이템
    var balance: Int               // 지급 뒤 잔액
}
```

- 앱을 켤 때의 맞추기 지급(reward-system.md 6.2 마지막 줄)은 화면에 따로 알리지 않는다. 홈의 가진 엔이 바뀌어 보인다.

### 11.3 데이터에 더할 것

- 아이템 데이터(`rewards.json`, reward-system.md 7번)에 이름의 글자별 발음 `units`(단어 데이터의 `units`와 같은 꼴: `kana`, `romaji`)를 더한다. 칸과 C2의 발음 표기 줄에 필요하다. planner가 채운다.
- 한국어 이름(`nameKo`)은 안내 줄 1줄에 가나 이름과 함께 들어간다. 375pt에서 "{가나} {한국어}"와 가진 엔(약 90pt)이 한 줄에 들어가려면 한국어 이름은 10자 안팎이 좋다. 지금 목록에서 가장 긴 것은 "머리 옆에 건 축제 가면"(11자), "노렌이 걸린 가게 앞"(10자)이다. 화면 이름은 "축제 가면", "노렌 가게 앞"처럼 짧게 쓴다(14번 절의 11). 데이터를 채우는 일은 planner 몫이다.
