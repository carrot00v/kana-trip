# 발음 소리 시험: VOICEVOX CORE 0.17.1

날짜: 2026-11-15. 발음 소리를 앱 안의 `AVSpeechSynthesizer` 대신 VOICEVOX로 미리 만들어 넣는 방안의 시험이다. 앱 코드(`KanaTrip/`)는 바꾸지 않았다.

- 약관·배포 파일 조사: [docs/research/voicevox-terms.md](../../research/voicevox-terms.md) (약관 확인 날짜 2026-11-15)
- 다운로더가 보여 주고 사용자가 동의한 약관 전문: [terms-2026-11-15.txt](terms-2026-11-15.txt)
- 도구: [tools/gen_voice.py](../../../tools/gen_voice.py), 설정 [tools/voice.json](../../../tools/voice.json)
- 샘플: [samples/](samples/), 수치 원본 [samples/measurements.json](samples/measurements.json)

## 크레딧

```
VOICEVOX:四国めたん
```

四国めたん 약관(SSS LLC)은 앱의 경우 "앱 소개 화면 등"에 크레딧을 적으라고 한다. 앱에 넣는 소리를 이 목소리로 정하면 크레딧 화면이 필요하다.

`compare-hau-*` 파일(雨晴はう)은 **비교용이며, 채택 전에 약관 확인이 필요하다.** 雨晴はう의 권리자 약관 원문은 읽지 않았다. 앱에 넣지 않는다.

## 설치와 재현

Python 3.10 이상이 필요하다. 이 Mac에는 Homebrew `python3.15`만 있었고, abi3 wheel이 문제없이 깔렸다. 의존 패키지는 없다.

```sh
mkdir -p .voicevox/dl && cd .voicevox/dl
curl -fLO https://github.com/VOICEVOX/voicevox_core/releases/download/0.17.1/download-osx-arm64
curl -fLO https://github.com/VOICEVOX/voicevox_core/releases/download/0.17.1/voicevox_core-0.17.1-cp310-abi3-macosx_11_0_arm64.whl
shasum -a 256 *            # 위 표와 대조
chmod +x download-osx-arm64
cd ..
./dl/download-osx-arm64 --exclude c-api --models-pattern 0.vvm -o ./voicevox_core   # 약관 동의 프롬프트: 사람이 직접 답한다
python3 -m venv venv
./venv/bin/pip install --no-index --no-deps ./dl/voicevox_core-0.17.1-cp310-abi3-macosx_11_0_arm64.whl
cd ..
.voicevox/venv/bin/python -I tools/gen_voice.py --metas   # 0.vvm의 목소리·스타일 id
.voicevox/venv/bin/python -I tools/gen_voice.py           # 샘플·preview.wav·measurements.json
```

0.vvm에 든 스타일 id: 四国めたん ノーマル 2 / あまあま 0 / ツンツン 6 / セクシー 4, ずんだもん 3 / 1 / 7 / 5, 春日部つむぎ ノーマル 8, 雨晴はう ノーマル 10. 조사 문서의 대응표와 같다.

## 만든 방식

- 글자는 AquesTalk 풍 가나 입력(`create_audio_query_from_kana`)으로 넣었다. 입력은 `ス'`처럼 가타카나 한 박에 액센트 기호를 붙인 형태다.
  - A: 기본값 그대로다. 앞뒤 무음은 0.1/0.1초다.
  - B: `speed_scale` 0.75.
  - C: 박 하나의 자음+모음을 0.40초가 되게 `vowel_length`를 늘렸다(모음 최소 0.25초, 자음은 그대로). 앞뒤 무음은 0.10/0.15초다.
- 단어는 일반 텍스트(`create_audio_query`)로 넣어 액센트를 엔진이 추정하게 했다. かつ丼은 `かつどん`으로 넣었다. 속도는 기본 1.0과 느림 0.85 두 가지다.
- 출력은 24kHz, 16bit, 모노 wav다. 음량 정규화는 하지 않았다.
- "소리" 열은 10ms 창의 RMS가 -45 dBFS를 넘는 첫 창부터 마지막 창까지의 길이다. RMS는 그 구간의 평균 음량(dBFS)이다.
- 합성은 CPU 스레드 2개로 했다. ComfyUI 그림 생성과 동시에 돌렸다.

## 샘플

파일 이름은 `{목소리}-{로마자}-{A|B|C}.wav`(글자)와 `{목소리}-{로마자}-{normal|slow}.wav`(단어) 형식이다. [samples/preview.wav](samples/preview.wav)(44.3초)는 글자 C안 8개와 단어 느림 8개를 0.6초 간격으로 이었다. 四国めたん 16개 뒤에 雨晴はう(비교용) 16개가 이어진다.

값은 "파일 길이 / 소리 구간 / RMS dBFS"이고, 길이 단위는 초다.

## 수치로 본 결과 (귀로는 듣지 않음)

- **글자는 C안을 추천한다(四国めたん 기준).**
  - 소리 구간이 0.29~0.36초로 가장 고르다. 표준편차가 0.022초로 A(0.051), B(0.063)의 절반 이하다.
  - 가장 짧은 ん도 0.29초다. A에서는 0.13초였다.
  - B는 자음까지 같은 비율로 늘어 박마다 길이 차이가 그대로 남는다(0.23~0.42). C는 자음을 원래 길이로 두고 모음만 맞춘다.
  - 설정은 박 0.40초였지만 잰 소리 구간은 약 0.33초다. 모음 끝이 -45 dBFS 아래로 잦아드는 부분이 빠진 것으로 본다.
- `speed_scale`은 앞뒤 무음에도 걸린다. query의 pre/post 값은 0.1로 그대로인데, B의 앞 무음은 A의 약 1.3배(0.12→0.16초)로 늘었고 파일 길이도 거의 정확히 1/0.75배가 됐다.
- **음량 차이가 있다.**
  - 四国めたん 글자의 RMS는 -21(を)~-37(い B·C) dBFS로, 최대 16dB 차이가 난다.
  - い는 늘리면(B·C) A보다 10dB 작아진다. 단어는 -23~-27 dBFS로 고르다.
  - 앱에 넣기 전에 음량 정규화가 필요하다(이번에는 하지 않음).
- **雨晴はう는 한 박 글자가 불안정하다.**
  - は C는 사실상 무음이다(peak -37 dBFS, 소리 구간 0초). を C는 0.01초, か C는 RMS -42다.
  - へ는 -45 dBFS 이상의 잡음이 파일 전체에 깔려 소리 구간이 파일 길이와 같다.
  - 조사 문서에 적힌 "짧은 문절이 읽히지 않을 수 있다"는 현상에 해당하는 것으로 본다. 단어는 정상 범위(-23~-32)다.
  - 글자용으로는 四国めたん이 낫다.

## 읽기 확인 (audio query의 음소)

- は·へ: `ハ'`, `ヘ'` 입력이 각각 `h+a`, `h+e`로 들어갔다. 조사 읽기(わ, え)로 바뀌지 않았다.
- を: `ヲ'`는 `ParseKanaError: unknown text in accent phrase`로 거부됐다. `オ'`로 대신 만들었고 음소는 `o`다. 문장 속 を(くつを)는 일반 텍스트 입력에서 `o`로 읽혔다.
- ん: `ン'` 한 박이 받아들여졌고 음소는 `N`이다.
- 촉음: きっぷ는 `キップ'`이다. っ는 모음 `cl`, 길이 0.074초(四国めたん), 높이 0인 박 하나로 들어갔다.
- 장음: 이번 단어 8개에는 장음이 없어 확인하지 못했다.
- 무성화: くつを의 く가 `_ク`(음소 `U`, 높이 0)로 무성화됐다. 가나 입력으로 넣은 글자 す·し는 무성화되지 않았다(`u`, `i`).
- 액센트: とんかつ가 `ト'ン/カ'ツ`, 두 액센트 구로 나뉘었다. 한 단어로 들리지 않을 수 있다. 단어 목록을 만들 때 가나 입력(`トンカツ` + 액센트 기호)이나 사용자 사전으로 고쳐야 할 후보다. 맞는 액센트는 귀와 사전으로 확인이 필요하다.

## 시간과 용량

- 모델·사전 로드는 0.6초다. 한 파일 합성은 평균 0.33초, 최대 0.67초(긴 문장)였다(CPU 2스레드, 그림 생성과 동시). 80개 전체를 만드는 데 27초 걸렸고, 최대 메모리는 약 375MB였다.
- 106개(글자 46 + 단어 60으로 가정) 전체를 만들면 합성 약 35초, 실행 전체 1분 안쪽으로 예상한다.
- 용량은 四国めたん 글자 C 8개와 단어 느림 8개로 쟀다.
  - wav는 글자 C 평균 31KB, 단어 느림 평균 41KB다. 106개면 약 3.9MB다.
  - m4a(AAC 48kbps 모노, macOS 기본 `afconvert`로 변환해 잼)는 글자 평균 8.1KB, 단어 평균 9.9KB다. 106개면 약 1.0MB다. 변환한 m4a는 커밋하지 않았다.
  - 실제 단어 60개는 길이가 다르므로 위 값은 추정이다.

- 음량 정규화 방법과 목표값, m4a 비트레이트에 따른 음질.
