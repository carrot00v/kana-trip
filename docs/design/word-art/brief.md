# 단어 그림 작업 파일

학습 단어 그림을 로컬 이미지 모델(ComfyUI, Z-Image Turbo)로 그리기 위한 작업 묶음이다. 어떤 단어를 무엇으로 그리는지는 [word-images.md](../../content/word-images.md)가 기준이고, 이 문서는 만드는 방법과 고른 결과만 적는다.

## 1. 화풍

리워드 아이템과 같다. [item-art/brief.md](../item-art/brief.md) 1번(화풍, 1.1 색, 1.2 그림 속 가나)과 3.1(Z-Image용 프롬프트)을 따른다. 슬롯 자리(targetBox, 쥐는 점)는 따르지 않는다.

- 프롬프트는 `tools/gen_item_art.py`의 `STYLE` + `PALETTE` + `Subject: ` + 단어별 Subject + `OBJECT_RULES`로 조립한다. 공통 문장을 고치면 아이템 그림에도 같이 적용된다.
- `word-kutsuonuide`, `word-oheya`만 `OBJECT_RULES`에서 "no floor"를 뺀다(바닥·다다미가 뜻의 일부).
- 움직일 부분(김, 가쓰오부시 등)은 정지 그림에 그리지 않는다(word-images.md 1번).

## 2. 파일

| 위치 | 내용 |
|---|---|
| `tools/word_art.json` | 단어 목록(이름, 가나, 우선순위, Subject, 복사 원본). word-images.md 2·3번을 옮긴 것. 표가 바뀌면 함께 고친다 |
| `source/candidates/word-{이름}_{시드}.png`, `.json` | 생성 후보(옅은 회색 바탕)와 프롬프트·시드. 커밋하지 않는다(.gitignore) |
| `source/candidates/cut/word-{이름}_{시드}.png` | 바탕을 지운 투명본(`tools/remove_bg.py`) |
| `source/word-{이름}.png`, `.json` | 고른 한 장(투명 PNG 1024×1024). 사람이 후보에서 골라 옮긴다 |

- 이름은 `word-{로마자}` (word-images.md 1번).
- 생성하지 않고 복사하는 단어: `word-tonkatsu`, `word-kitsune`(item-art/source에서), `word-hinoki`(`word-ofuro`를 고른 뒤 그 그림을 복사).
- 이번 배치에서 뺀 것: `word-yu`의 ゆ 합성(노렌 그림만 만든다. 고른 뒤 `tools/place_word_art.py`가 그림의 빈 크림색 원을 찾아 KanjiVG 획으로 합성한다. 좌표를 적지 않으므로 다시 그려도 그대로 된다), `word-okame`(고명 구성 확인 전이라 `word_art.json`에 `hold`. 2026-11-16 docs/research/okame-toppings.md로 hold를 지우고 3차 배치에서 그림, 5.3).

## 3. 생성

```bash
.venv/bin/python tools/gen_word_art.py --priority 1        # 생성 26장 + 복사 2
.venv/bin/python tools/gen_word_art.py --priority 2        # 생성 14장 + 복사 1(word-ofuro를 고른 뒤)
.venv/bin/python tools/gen_word_art.py --only word-sushi word-ika --count 3 --seed 100
.venv/bin/python tools/gen_word_art.py --priority 1 --dry-run   # 프롬프트만 출력
```

- 한 번에 한 장씩. 이 Mac에서 1024px 한 장에 3.5~5분, ComfyUI 큐를 다른 작업과 같이 쓰면 더 걸린다.
- 후보가 이미 `--count`장 있는 단어는 건너뛰므로, 끊기면 같은 명령을 다시 돌린다.
- 한 장에 1800초가 넘으면 그 단어를 건너뛰고 prompt_id를 출력한다. ComfyUI는 그 그림을 끝까지 만들므로 `/history/<prompt_id>`에서 꺼내 `word-{이름}_{시드}.png`로 저장하면 된다.

## 5. 고른 그림

확인할 것: 투명 바탕, 글자·숫자 없음, 금지 색(초록, 분홍빨강)이 넓게 없음, 외곽선 굵기가 기리와 비슷함, 김 등 움직일 부분이 그려져 있지 않음.

비교 시트: `source/contact-sheet.png` (`tools/word_art_sheet.py --priority 1`. 투명본을 푸른 바둑판 위에 놓아 남은 바탕 테가 보인다).

판정 기준: 기리 화풍(굵은 진갈색 외곽선, 평평한 색), word-images.md의 Subject와 맞는지, 글자·얼굴·엉뚱한 사물이 없는지, 바탕 제거가 깨끗한지, 여행자가 현지에서 알아볼 모습인지. 애매하면 다시 그림.

### 5.2 2차 검수 (2026-11-15, developer)

1차에서 다시 그린 17장(Subject 고침)과 우선순위 2 배치, 다시 그린 단어를 같은 기준으로 봤다. PM의 1차 의견은 참고만 하고 그림마다 직접 열어 판정했다.

다듬기: 통과한 후보는 `tools/clean_word_art.py`가 `tools/word_art_clean.json`의 설정대로 다듬어 `source/word-{이름}.png`로 확정한다. 하는 일은 셋이다.

- 색 점 자동 지우기: 채도 0.55·밝기 0.45 이상이고 지름이 그림 변의 4.5% 이하인 둥근 얼룩(빨강·초록·파랑·보라·분홍·노랑, 주황 8~45°는 음식 색이라 뺀다). 둘레 색과 비슷한 조각은 건너뛰고, 외곽선(어두운 픽셀)은 건드리지 않고 가장 가까운 면 색으로 메운다. 파 고리(soba 약 7%)·아오노리(작고 어두움)·와사비 같은 정상 부분은 크기·밝기 조건에서 빠지고, 필요하면 `keep`으로 지킨다.
- 좌표 메우기: 자동 범위를 넘는 큰 얼룩(tako 초록 원 약 9%, tsukune 초록 원·빨간 반달), 소스 색과 가까운 주황빨강 점(takoyaki), 채도 낮은 점(inari)은 `fill`/`paint` 좌표로 메운다.
- 스티커 흰 테 지우기(`rim`): 투명 바탕에서 시작해 밝고 채도 낮은 픽셀만 지운다.

### 5.3 3차 배치: 그림 없던 단어 채우기 (2026-11-16, developer)

사용자 결정("그림 없는 단어도 전부 채워", PLAN.md 단어 그림 행)으로 우선순위 3의 16개와 보류였던 word-okame를 그렸다. 방식은 word-images.md 3.3(A 표지판 빈 판 + 글자 합성, B 부위·구성, C 장면의 물건). 생성·다듬기·배치 절차는 5.2와 같다.

- 생성: `gen_word_art.py --only ... --count 1 --seed 20261116`(17장) 뒤 다시 그림. 이 Mac에서 한 장 3~23분(ComfyUI 큐를 같이 써서 들쭉날쭉).
- **같은 시드는 같은 구도가 된다.** 꼬치 셋(mune, sasami, nankotsu)을 같은 시드로 그렸더니 덩이 세~다섯 개가 붙은 같은 실루엣이 나와 서로 구분되지 않았다. 다시 그릴 때는 단어마다 시드를 달리하고 Subject에서 모양(비스듬한 한 덩이, 사이가 뜬 조각)을 바꿨다. 비슷한 대상 여럿을 그릴 때는 처음부터 시드를 단어마다 다르게 준다.
- 글자 합성(방식 A): 모델에는 글자 없는 빈 판만 그리게 했고(7장 모두 판에 글자·무늬 없이 나옴), `tools/place_word_art.py`의 `KANA_IN_ART`에 판 색(HSV 범위)을 적으면 그 색 칸으로만 된 가장 넓은 사각형을 찾아 가운데에 KanjiVG 획으로 한 줄을 놓는다. 글자 칸은 판 높이·너비의 0.9, 칸 겹침 0.8, 획 굵기 11/109(아이템 간판 9/109보다 굵게). 세로 제비 종이(atari, hazure)는 판이 좁아 겹침 0.74·0.98로 키웠다.
- 탁점(で, ぐ, ず): 앱 획 데이터는 기본 46자뿐이라 `place_item_art.kana_glyph`가 바탕 글자(て, く, す)를 0.86배로 왼쪽 아래에 줄이고 오른쪽 위에 짧은 두 획을 더해 그린다. 湯은 획 데이터가 없어 ぬる湯 팻말에는 ぬる만 넣었다.
- 획 이음매: 꺾이는 점마다 원을 찍어 선 이음매의 밝은 실금을 없앴다(`kana_glyph`, ゆ 노렌과 아이템 간판에도 같이 적용된다. 다시 배치하면 바뀐다).
