### 2.2 크기 규칙

| 항목 | 값 |
|---|---|
| 그림 한 변 S | `min(176, 그림 영역 높이)`. 화면 폭은 늘 넉넉하다(375pt에서 343pt) |
| 그리지 않는 조건 | S < 96pt. 기리(96pt)보다 작은 그림은 무엇인지 알아보기 어렵고, 뜻은 글과 기리 설명이 이미 전한다 |
| 모양 | 정사각, 투명 바탕 그대로. 카드·테두리·그림자 없음. 모서리 자르기 없음 |
| 같은 단어 안 | 확인 전후로 S가 바뀌지 않는다. 그림 영역은 확인 전에도 같은 높이로 계산된다(읽기·뜻 자리 70pt를 확인 전에도 비워 두므로) |

176pt를 고른 이유:

- 375×667pt의 그림 영역(185pt)에 들어가는 가장 큰 8의 배수다. 같은 그림이 기기마다 다른 크기로 보이지 않게 모든 기기에서 176pt로 둔다(giri-companion.md 2.4.1에서 96pt를 고른 것과 같은 이유).
- 그림 안 대상은 둘레 여백 10%라 약 141pt(김이 있는 그림은 127pt, 9.1)로, 기리(96pt)보다 크고 이동 중에도 무엇인지 한눈에 보인다.
- 원본 1024px의 축소본 600px(9.1)에서 @3x 528px로 그린다. 흐려지지 않는다.

- 그림은 엄지 범위(375×667pt y 333.5 아래) 안에 있지만 누르는 대상이 아니다. 주 버튼(603~659)과 20pt 이상 떨어져 있어 버튼을 가리지 않는다.

### 2.4 큰 글자 크기

- W의 내용 영역은 스크롤된다(giri-companion.md 6.2). 그림 영역 높이는 **스크롤 영역의 보이는 높이**에서 그림 위 요소들의 실제 높이를 빼고 32pt를 뺀 값이다. 같은 2.2 규칙(S = min(176, 영역), 96 밑이면 없음)을 쓴다.
- 예: 375×667pt, xxxLarge에서 기리 말풍선 4줄(132pt)과 커진 읽기·뜻 줄로 약 48pt 늘면 그림 영역 약 137pt → S 137pt.
- `accessibility1` 이상: 기리를 숨기고 말풍선이 전체 폭 카드가 되며 대부분 그림 영역이 96pt 밑이 되어 그림이 빠진다. 그래도 들어가면 같은 규칙으로 그린다.
- 그림 크기는 글자 크기를 따르지 않는다(visual-rules.md 8.1의 캐릭터와 같은 장식 취급).

### 2.5 다크 모드

- 그림은 한 장으로 두 모드에 쓴다(기리, 아이템과 같음). 진갈색 외곽선이 다크 바탕(`#1F1714`)에 묻혀도 면 색으로 대상을 알아볼 수 있는지 실기기에서 본다(10번).
- 그림 밖 바탕으로 나가는 Lottie 선(김)만 `Ink` 토큰 색을 따른다(6.2). 라이트는 진갈색, 다크는 크림색 김이 된다.
- 스마트 반전에서 그림이 반전되지 않게 `accessibilityIgnoresInvertColors(true)`를 붙인다.

## 3. 언제 보여 줄지

### 3.1 결정: "읽기 확인" 뒤에만 보인다

| 상태 | 그림 영역 |
|---|---|
| 읽기 전 | 비어 있다. 틀, 실루엣, 흐린 그림, "?" 표시를 두지 않는다 |
| "읽기 확인"을 누른 순간 | 읽기·뜻 줄과 **같은 애니메이션**(`easeInOut` 0.2초, 지금 `revealed`의 `withAnimation`)으로 불투명도 0 → 1. 크기·위치 변화 없음 |
| 확인 0.25초 뒤 | Lottie가 있으면 재생 시작(6.6). 정지 그림은 그대로 |
| "다음" | 화면 내용 전체의 0.2초 페이드(지금 규칙)와 함께 사라진다. 다음 단어는 다시 읽기 전 상태 |

근거:

- **실루엣과 흐린 그림은 뜻을 미리 알려 준다.** 꼬치, 덮밥 그릇, 초롱, 초밥처럼 윤곽만으로 무엇인지 알아보는 그림이 대부분이다. 뜻을 먼저 알면 사용자는 글자를 읽지 않고 뜻에서 발음을 떠올려(たこ = 문어 = tako) 읽기 연습을 건너뛴다. 확인 전에는 글자만 보이는 것이 이 화면의 목적(PLAN.md 3번 "단어 읽기": 소리 내어 읽고 확인)과 맞다.
- **빈 틀(자리 표시)도 두지 않는다.** 그림 없는 단어 16개에서는 틀이 없어 "이 단어는 그림이 있다/없다"가 확인 전부터 보이고, 그 자체가 단서(추상어인지 물건인지)가 된다. 쓰지 않는 사각형이 화면에 하나 더 생기는 것도 피한다(giri-companion.md 1.3과 같은 이유).
- 확인 뒤에 나타나면 그림이 **뜻 글자와 같은 순간에** 붙어 뜻을 두 갈래(글과 그림)로 기억하게 하고, 읽고 나서 받는 작은 보상이 된다. 현장에서 간판을 읽고 나서 그게 무엇인지 아는 순서와도 같다.

### 3.2 움직임 개수 확인 (giri-companion.md 5.3)

확인 순간에 바뀌는 것: 읽기·뜻·그림의 페이드(화면 내용 전환, 하나로 묶음), 기리 표정 바뀜(0.12초), 말풍선 뜨기(0.25초). 기리의 한 번 움직임은 둘 그대로이고, 그림은 읽기·뜻과 한 페이드라 따로 세지 않는다. 그림에 크기 변화(0.96 → 1.0 등)를 더하지 않는 이유가 이것이다. Lottie는 말풍선 뜨기가 끝난 0.25초 뒤에 시작해 동시에 움직이는 것이 셋이 되지 않는다.

## 4. 그림이 없는 단어, 아직 없는 그림

### 4.1 그림이 없는 단어 (우선순위 3, 16개)

- 그림 영역을 비워 둔다. 아무것도 그리지 않는다.
- 그림 영역은 W의 맨 아래 요소라 비어도 그 위의 단어·읽기·뜻·기리 줄은 그림이 있는 단어와 **같은 자리**다. 그래서 "자리 비우기"와 "레이아웃 접기"가 화면에서 같은 모양이 되고, 단어를 넘길 때 기리와 단어가 위아래로 움직이지 않는다.
- 그림 대신 아이콘, 장면 그림, 기리 그림을 넣지 않는다. 뜻은 뜻 줄과 기리 설명이 전한다.
- 이 16개는 지금 W의 모습(그림 영역 없는 화면)과 같다. 375×667pt에서 기리 줄 아래 217pt가 비는 것은 지금도 같다.

### 4.2 아직 생성되지 않은 그림

그림은 몇 시간에 걸쳐 차례로 생성되어 들어온다. 앱은 **에셋이 있는지만 보고** 그린다.

| 순서 | 있는 것 | 그리는 것 |
|---|---|---|
| 1 | Lottie 파일 `word_{art}.lottie.json` | Lottie (정지 그림이 파일 안에 있음, 6.1) |
| 2 | 이미지 에셋 `WordArt-{art}` | 정지 그림 |
| 3 | 둘 다 없음 또는 단어에 `art` 값이 없음 | 아무것도 그리지 않음 (4.1과 같음) |

- "그림 준비 중", 회색 상자, 대체 그림을 보여 주지 않는다. 사용자에게는 "그림이 원래 없는 단어"와 구분되지 않아도 된다. 그림은 확인 뒤에만 나오는 보조 정보라 빠져도 학습 흐름이 끊기지 않는다.
- Lottie 파일을 읽지 못하면(손상, 디코딩 실패) 2번으로 내려간다. 에러를 화면에 내지 않는다.
- 에셋이 새로 들어와도 코드와 단어 데이터를 바꿀 필요가 없게 한다. `art` 값은 44개 단어에 미리 넣어 둔다(9.2).

## 5. 퀴즈와 완료 화면

### 5.1 QD 읽기 고르기: 쓰지 않는다

- 답하기 전: 그림이 뜻을 알려 주고, 뜻에서 발음을 떠올릴 수 있어 답의 단서가 된다(3.1과 같은 이유). 쓰지 않는다.
- 답한 뒤: 뜻 줄(26pt)이 이미 나온다. 375×667pt에서 문제 아래 남는 공간이 67pt뿐이라(scene-flow.md 13.7) 96pt 이상의 그림이 들어가지 않는다. 문항마다 그림이 나왔다 사라지면 2×2 선택지를 이어 누르는 리듬도 흐트러진다.
- 결론: QD에는 단어 그림을 두지 않는다. 그림은 같은 단어를 W에서 이미 보았다.
- QE(뜻 고르기, 지금 쓰지 않음)를 다시 쓰게 되더라도 그림은 답이 되므로 넣지 않는다.

### 5.2 C1, C2: 쓰지 않는다

- C2는 375×667pt에서 이미 523/523pt로 꽉 찼다(scene-flow.md 14번).
- C2의 리워드 묶음에 아이템 썸네일이 있다. 같은 화면에 단어 그림이 나란히 있으면 "배운 단어"와 "받은 아이템"이 섞인다(word-images.md 4.1 규칙 1의 이유와 같다).
- C1에는 자리(약 83pt)가 있지만 목표 단어 묶음은 22pt 글자 한 줄이고, 단어마다 그림을 붙이면 96pt 밑으로 작아진다. C1과 C2의 목표 단어 묶음은 글자만 둔다.

## 6. 움직임 (Lottie)

### 6.1 파일 구조

PLAN.md 3번 "그림 움직임"의 방식(정지 그림을 이미지 자산으로 넣고 움직이는 부분을 벡터 레이어로 얹은 파일 하나)을 단어 그림에도 그대로 쓴다. 움직이는 그림 하나에 파일 하나다.

| 항목 | 값 |
|---|---|
| 파일 | `KanaTrip/Resources/word_{art}.lottie.json` |
| 캔버스 | 600×600 (w, h). 정지 그림 600px(9.1)과 같은 정사각. 화면에서는 S×S로 줄여 그린다(`resizable`, 비율 유지). 정지 그림과 Lottie를 바꿔 끼워도 자리와 크기가 같다 |
| 정지 그림 | 이미지 레이어. PNG를 base64로 넣는다(`"e": 1`). 흔들림 그림은 움직이는 조각과 고정 조각 두 장(6.3.2) |
| 움직이는 부분 | 셰이프 레이어(김, 깜박임, 물결, 가쓰오부시, 동전) 또는 이미지 레이어의 변환(흔들림) |
| 쓰는 기능 | 위치·회전·크기·기울이기·불투명도 키프레임, 경로 키프레임, 부모 연결(`parent`). 표현식, 효과, 마스크, 매트, 트림은 쓰지 않는다(lottie-ios와 lottie-android 공통 기능만, `build_scene_lottie.py`와 같은 원칙) |
| 프레임 | 30fps. 동전만 60fps(한 번 0.35초라 프레임이 모자람) |
| 반복 | 마지막 프레임 = 첫 프레임. 끊김 없이 돈다 |
| 마커 | `still` 하나. 반복 파일은 **프레임 0**을 정지 모습으로 만들어 `still` = 0. 한 번 파일(동전)은 마지막 프레임 |
| 앱용 값 (`"kt"` 키) | `{"loop": true/false, "still": 프레임}`. 재생기는 모르는 키를 무시한다. 장면 Lottie의 `kt.background`는 단어 그림에 없다(투명 바탕) |
| `Ink` 색을 따르는 레이어 | 이름을 `ink`로 둔다. 앱이 `ink.**.Color` 키패스에 지금 모드의 `Ink` 색을 넣는다(6.2 김). 같은 이름 레이어가 여럿이어도 된다 |
| 선 굵기 | 벡터 선의 굵기는 그림 외곽선의 실제 굵기에 맞춘다. 재지 않았으면 캔버스 변의 0.009(176pt에서 1.6pt, 96pt 기리의 외곽선과 같음, giri-companion.md 2.4.4) |
| 만드는 도구 | `build_scene_lottie.py`의 김 함수(경로·위치·불투명도 키프레임, 이음 처리)를 다시 써서 단어용 도구를 만든다. 단어마다의 값(6.3의 표)은 데이터 파일 하나(예: `tools/word_motion.json`)에 둔다. 이름과 형식은 developer가 정한다 |

### 6.2 종류별 정의

좌표와 길이는 캔버스 변에 대한 비율(0~1, 원점은 왼쪽 위)로 적고, 괄호에 S 176pt일 때의 pt를 적었다. 위치(기준점)는 그림이 확정된 뒤 그림 위에서 잰다(6.3).

#### 김 (반복)

| 항목 | 값 |
|---|---|
| 모양 | 위로 오르는 S자 선 1~3줄. 열린 경로, 끝 둥글게(`lc 2`) |
| 레이어 | 줄마다 셰이프 레이어 하나, 이름 `ink`. 정지 그림 위 |
| 색 | `Ink` 토큰(라이트 `#4A2219`, 다크 `#F7EEDF`). 김은 그림 밖 바탕 위로 오르므로 모드를 따라야 다크에서 보인다 |
| 길이 | 줄 하나의 세로 길이 0.12~0.18 (21~32pt). 단어별 값은 6.3 |
| 좌우 굽이 | S자 반폭 0.025 (4.4pt). 굽이가 옮겨 가는 폭 0.6 라디안 (`build_scene_lottie.py`의 `SWAY`) |
| 오름 | 한 주기에 0.05 (8.8pt) |
| 불투명도 | 주기의 0~25%에 0 → 1, 60%까지 1, 100%에 0 (`build_scene_lottie.py`의 곡선) |
| 주기 | **2.6초** (78프레임). 줄마다 주기 ÷ 줄 수만큼 엇갈림 |
| 줄 아래 끝 | 음식 윗면(그릇이면 국물·밥 위, 찻잔이면 차 표면)의 가운데. 줄 아래 40%까지는 음식 위에 겹쳐도 된다 |
| 줄 위 끝 | 캔버스 위 끝에서 0.03 이상 아래. 모자라면 9.1의 "김 그림" 배치를 다시 본다 |
| 정지 모습 (프레임 0) | 모든 줄이 불투명도 0.5 이상으로 보이는 위상. `build_scene_lottie.py`의 `still_frame` 값만큼 위상을 앞으로 옮겨 프레임 0에 둔다 |

#### 흔들림 (반복)

매달린 방식에 따라 두 가지다. 둘 다 정지 그림을 움직이는 조각과 고정 조각으로 나눠 이미지 레이어 두 장으로 넣는다(초롱은 그림 전체가 움직이는 조각 하나).

| 항목 | 매달림 (점에 매달린 것: 초롱) | 드리움 (줄에 걸린 것: 노렌, 제비 종이) |
|---|---|---|
| 변환 | 회전 | 아래 조각을 기준점 둘레로 회전(구현, 아래 참고). 원래 정의는 가로 기울이기(`sk`, 축 0°) |
| 기준점(`a`) | 끈 위 끝 | 걸린 줄(봉, 줄)의 높이, 조각 가로 가운데 |
| 진폭 | ±3° (초롱 아래 끝에서 약 ±0.03, 5pt) | 노렌 ±2° (천 아래 끝 약 ±0.017, 3pt), 제비 종이 ±5° (종이 끝 약 ±0.02, 3.5pt) |
| 곡선 | 0 → +A → 0 → −A → 0, 구간마다 `easeInOut` | 같음 |
| 주기 | **3.0초** (90프레임) | 3.0초 |
| 정지 모습 (프레임 0) | 기울지 않은 모습 = 원래 그림 | 같음 |
| 조각 나누기 | 없음(그림 전체) | 가로선 하나로 위(고정)와 아래(움직임)를 나눈다. 자르는 선은 기준점보다 0.02 위. 움직이는 조각을 고정 조각 **아래**에 두어 기울어도 틈이 보이지 않게 한다 |

- 기울이기가 lottie-ios와 lottie-android에서 다르게 그려지면 같은 각도의 회전으로 바꾼다.
  - 2026-11-15 확인: lottie-ios 4.6.1(iPhone 17 시뮬레이터, iOS 26.5)에서 이미지 레이어의 기울이기 키프레임이 그려지지 않았다(0.7초 간격 두 장의 픽셀 차이 0). 같은 파일을 회전으로 바꾸자 움직였다. 그래서 드리움은 회전으로 만든다(`tools/word_motion.json`의 `kinds.sway.drapeTransform` = `rotate`). 위 끝 양옆이 조금 오르내리므로 아래 조각을 자르는 선보다 0.02 위까지 남겨 고정 조각 밑에 겹친다(`overlap`).
- word-yu의 ゆ(KanjiVG 획 합성)는 노렌 천과 함께 ±2° 기운다. 그림 안 글자는 확인 뒤에만 보이고 위 단어 블록이 읽기의 기준이라 받아들인다.

#### 깜박임 (반복, 초롱 불빛)

| 항목 | 값 |
|---|---|
| 모양 | 초롱 몸통 안의 타원 하나, 면만(외곽선 없음). 가로 반지름 0.22, 세로 반지름 0.26 (몸통 안에 들어가게 그림에서 잰다) |
| 색 | 노랑 `#F6B92B`(item-art/brief.md 1.1), 그라데이션 없음 |
| 불투명도 | 0.15 → 0.35 → 0.20 → 0.35 → 0.15, 구간 0.75초씩 `easeInOut`. 한 바퀴 3.0초(흔들림과 같은 주기) |
| 레이어 | 셰이프 레이어 하나, 초롱 이미지 레이어를 부모로 둔다(`parent`). 흔들림을 따라 같이 움직인다 |
| 정지 모습 | 불투명도 0.15 |

#### 동전 떨어짐 (한 번)

| 항목 | 값 |
|---|---|
| 모양 | 은색 동전 하나, 비스듬히 본 타원. 가로 0.12, 세로 0.05 (21 × 9pt). 면 `#EFE3CC`, 외곽선 `#4A2219`(굵기 6.1의 선 굵기), 숫자·무늬 없음 |
| 움직임 | 접시 위 놓일 자리에서 0.30(53pt) 위에서 시작. 0~0.20초 아래로(`easeIn`), 0.20~0.28초 0.03 튀어 오름(`easeOut`), 0.28~0.35초 제자리(`easeIn`). 0~0.05초 불투명도 0 → 1 |
| 길이 | **0.35초**, 60fps 21프레임. 반복하지 않는다(`kt.loop` false) |

0.35초는 앱의 모든 한 번 움직임 상한(giri-companion.md 5.4)과 같다.

#### 가쓰오부시 (반복, 다코야키)

| 항목 | 값 |
|---|---|
| 모양 | 다코야키 위에 얹힌 얇은 조각 4개. 모서리 둥근 불규칙 사각형, 0.07 × 0.04 안팎 |
| 색 | 면 분홍 `#F5A7A0`, 외곽선 `#4A2219`(6.1의 선 굵기). 작은 면적이라 brief.md 1.1의 넓은 면 금지에 걸리지 않는다 |
| 움직임 | 조각마다 아래 가운데를 기준점으로 회전 ±10°와 세로 크기 1.0 ↔ 0.8(말리는 모양)을 함께. 크기는 가장 기울 때(¼, ¾ 주기) 0.8, 곧게 설 때 1.0 |
| 주기 | **1.3초**(김 2.6초의 절반, 한 파일 안에서 두 번 돌아 김과 같이 이어진다). 이웃한 조각은 반대 방향으로 기울고, 기우는 폭을 조각마다 1.0·0.8·0.9·0.7배로 달리한다 |

- 처음 정의(조각마다 4분의 1 주기씩 엇갈림)로는 어느 프레임에서도 두 조각이 ±10°로 기울어 있어 프레임 0이 기울지 않은 모습이 될 수 없었다. 그래서 엇갈림을 반대 방향(반 주기와 같음)으로 바꿔 프레임 0에 네 조각이 모두 0°, 크기 1.0이 되게 했다(2026-11-15, PM 지시). 같은 움직임만 되풀이되어 보이지 않게 기우는 폭을 조각마다 달리했다.

#### 김 레이어를 여러 그림에 같이 쓸 때 바꾸는 값

모양·주기·불투명도 곡선·오름·좌우 굽이는 모든 그림에 같다(6.2). 그림마다 바꾸는 값은 아래 다섯 개뿐이다.

| 값 | 뜻 |
|---|---|
| 기준점 (x, y) | 김 묶음의 가운데 줄 아래 끝. 음식 윗면 가운데 |
| 줄 수 | 1~3 |
| 줄 사이 | 이웃한 줄의 아래 끝 사이 가로 거리. 묶음 폭 = 줄 사이 × (줄 수 − 1) |
| 길이 | 줄 하나의 세로 길이 |
| 굵기 배수 | 6.1의 선 굵기에 곱하는 값. 기본 1.0 |

| 파일 | 줄 수 | 줄 사이 | 길이 | 굵기 배수 | 기준점 (잼) | 이유 |
|---|---|---|---|---|---|---|
| word-gohan | 2 | 0.10 (18pt) | 0.13 | 1.0 | 밥 봉우리 위 | 작은 공기라 줄을 줄임 |
| word-udon, word-soba, word-kitsune, word-wakame, word-tanuki, word-okame | 3 | 0.12 (21pt) | 0.16 | 1.0 | 국물 면 가운데 | 넓은 면기 |
| word-katsudon | 3 | 0.12 | 0.16 | 1.0 | 돈가스 위 가운데 | 장면 진입 김 카드와 같은 3줄 |
| word-yakisoba | 2 | 0.12 | 0.13 | 1.0 | 면 더미 위 | 납작한 종이 접시라 짧게 |
| word-takoyaki | 2 | 0.14 (25pt) | 0.12 | 1.0 | 다코야키 줄 위 가운데 | 가쓰오부시가 주인공이라 김은 짧게 |
| word-houjicha | 2 | 0.08 (14pt) | 0.12 | 0.8 | 찻잔 차 표면 가운데 | 찻잔이 작아 가늘게 (word-images.md 5번 "한두 줄") |

- 표의 줄 사이·길이는 그림이 확정되기 전의 시작값이다. 그림 위에 겹쳐 보고 묶음 폭이 그릇·탕 폭의 60%를 넘으면 줄 사이를 줄인다.
- 다른 움직임(흔들림의 기준점과 자르는 선, 깜박임 타원, 동전의 놓일 자리, 물결 가운데, 가쓰오부시 4조각 자리)도 같은 데이터 파일에 단어별로 적는다.

### 6.4 한 화면에 반복 움직임 하나: W에서는 기리가 숨쉬지 않는다

결정: **W 화면에서는 기리의 숨쉬기를 늘 끈다.** 그림이 있든 없든, 확인 전이든 뒤든 같다. W의 반복 움직임 자리는 단어 그림의 Lottie가 쓴다.

| 검토한 방식 | 결과 |
|---|---|
| W에서 늘 끈다 | **채택** |
| 확인 전에는 숨쉬고, 움직이는 그림이 나오면 끈다 | 뺌. 확인할 때 숨쉬기가 멈추는 순간 기리가 줄어드는 것이 보이고, 그 순간 이미 표정 바뀜과 말풍선 뜨기가 있어 움직임이 셋이 된다 |
| 움직이는 그림이 있는 단어에서만 끈다 | 뺌. 같은 화면에서 단어를 넘길 때마다 기리가 숨쉬다 멈췄다 해 규칙이 보이지 않는다(18/44 단어) |

근거:

- giri-companion.md 5.3의 우선순위("장면 그림이 있으면 장면 그림. 기리는 숨쉬지 않는다")를 화면 단위로 그대로 쓴 것이다. S도 화면 단위(장면마다 고정)로 정했다.
- 읽기 전에는 사용자가 글자에 집중하는 때라 반복 움직임이 없는 쪽이 낫다. 기리의 생동감은 확인 때의 표정 바뀜과 말풍선이 맡는다.
- 숨쉬지 않는 화면은 이미 L2, QC, 움직이는 S가 있다. W를 더해도 기리가 굳어 보이는 화면이 새로 생기는 것은 아니다.

### 6.5 움직임 줄이기

| 대상 | 동작 줄이기가 켜졌을 때 |
|---|---|
| 그림 등장 | 페이드 없이 확인 순간에 바로 보인다(읽기·뜻과 같다) |
| 반복 Lottie | 재생하지 않고 마커 `still`(프레임 0)에 멈춘다 |
| 김 | 모든 줄이 보이는 모습으로 멈춘다. 김을 빼면 온천이 연못으로, 덮밥이 식은 그릇으로 보이므로(word-images.md 5번) 김은 정보로 남긴다 |
| 흔들림, 깜박임, 가쓰오부시 | 기울지 않은 원래 모습, 불빛은 가장 옅은 모습 |
| 물결 | 테두리 하나가 중간 크기로 보이는 모습 |
| 동전 | 떨어지지 않고 접시 위에 놓인 마지막 모습(4번째 동전이 처음부터 있음) |

- 지금 `SteamingSceneArt`의 `.paused(at: .marker("still"))`와 같은 방식이다.
- 동작 줄이기가 재생 도중 켜지면 그 자리에서 `still`로 옮긴다.

### 6.6 재생 규칙

- 확인 전: Lottie 뷰는 불투명도 0이고 `still`에 멈춰 있다(보이지 않는 동안 돌리지 않는다).
- 확인 0.25초 뒤: 반복 파일은 0 → 1 반복 재생, 동전 파일은 한 번 재생. 0.25초는 말풍선 뜨기가 끝나는 때다(3.2).
- "다음"을 누르면 내용 페이드와 함께 뷰가 사라지고 재생도 멈춘다. 다음 단어의 그림은 새로 만든다(단어 `text`를 뷰 id로).
- 앱이 백그라운드로 가면 Lottie가 알아서 멈춘다. 돌아오면 이어서 돈다.
- 김 색: 모드가 바뀌면 `ink.**.Color` 값을 다시 넣는다.
- 그림은 누를 수 없다. 탭·길게 누르기에 반응하지 않는다(발음 소리도 내지 않는다. 소리는 읽기 줄에서).

## 7. 장면 진입의 김 카드와의 관계

지금 돈카츠집·온천의 S 맨 위에 김이 움직이는 장면 그림 카드(180pt)가 있다(`SteamingSceneArt`, 2026-11-14 main 시제품을 옮겨 둔 것).

추천: **S의 김 카드를 빼고, 그림 움직임은 W의 단어 그림으로 모은다.** PM 확인 전까지는 지금 그대로 둔다.

| 이유 | 내용 |
|---|---|
| 같은 대상이 겹친다 | 돈카츠집 카드는 가츠동, 온천 카드는 나무 탕이다. 둘 다 W의 word-katsudon, word-onsen·word-ofuro에서 김과 함께 다시 나온다 |
| 8장면 중 2장면만 있다 | 나머지 6장면 S에는 카드가 없어 S의 모양이 장면마다 다르다. 6장면 카드를 더 만들려면 장면 그림마다 움직임을 따로 설계해야 한다 |
| S의 목록 자리 | 375×667pt에서 S 목록이 보이는 높이는 375pt다(giri-companion.md 3.3). 카드(180pt + 섹션 간격)가 그 절반을 써서, 할 차례인 단계 행이 첫 화면에서 밀려난다 |
| 기리 숨쉬기 | 카드가 없으면 S의 기리가 숨쉬기를 되찾는다. 지금은 두 장면에서만 기리가 숨쉬지 않는다 |

- 빼도 되는 것: 홈 장면 행의 장면 그림(52pt, 정지)은 그대로 둔다. 장면의 얼굴은 그 그림이 맡는다.
- 남길 경우: S와 W는 다른 화면이라 규칙끼리 부딪히지 않는다. S는 지금처럼 카드가 있는 장면만 기리 숨쉬기를 끈다.
- 도구: `build_scene_lottie.py`의 김 함수는 단어용 도구가 다시 쓴다(6.1). 카드를 빼도 도구는 남긴다.

## 8. 접근성

| 대상 | 처리 |
|---|---|
| 단어 그림(정지, Lottie 모두) | `accessibilityHidden(true)`. 장식으로 본다 |
| 근거 | 확인할 때 "{읽기}, {뜻}. {기리 설명}" 알림 하나(giri-companion.md 6.1)가 뜻을 읽는다. 그림 레이블("오징어 초밥 그림")을 더하면 같은 뜻을 두 번 듣고, 그림 없는 단어와 읽는 순서가 달라진다 |
| 읽는 순서 | 그대로: 상단 바 → 단어 → (확인 후) 읽기, 뜻 → 기리 말풍선 → 주 버튼 |
| 스마트 반전 | `accessibilityIgnoresInvertColors(true)` (2.5) |
| 큰 글자 크기 | 2.4. 그림은 글자 크기를 따르지 않고, 자리가 모자라면 빠진다 |
| 동작 줄이기 | 6.5 |
| 색만으로 구분 | 그림은 판정을 싣지 않는다. 그림에 `Correct`, `Wrong`을 쓰지 않는다 |

## 9. 에셋과 데이터 (developer)

### 9.1 정지 그림

| 항목 | 값 |
|---|---|
| 원본 | `docs/design/word-art/source/word-{art}.png` (1024×1024, 투명) |

| 배치 맞추기 (원본 → 600px) | 바탕 지우기에서 남은 떨어진 조각(스티커 테두리 부스러기, 옅은 점)을 지우고 대상의 경계 상자(투명이 아닌 픽셀)를 잰 뒤, **보통 그림**: 긴 변을 캔버스의 0.80으로, 가로·세로 가운데. **김 그림**(6.3의 김이 있는 14개): 긴 변을 0.72로, 가로 가운데, 아래 끝을 0.90에 맞춘다. 김이 오를 위 공간(약 0.18)을 남기기 위해서다 |
| 이유 | 생성 그림마다 여백이 달라 그대로 쓰면 단어마다 대상 크기가 들쭉날쭉하다. 김 그림이 보통 그림보다 10% 작은 것은 받아들인다 |
| Lottie 안의 그림 | 위와 같은 600px PNG를 그대로 넣는다(흔들림 그림은 나눈 두 장) |

### 9.2 단어 데이터

- `hiragana_scenes.json`의 단어에 선택 필드 하나를 더한다(이름은 developer가 정함, 이 문서에서는 `art`). 값은 `tools/word_art.json`의 `name`(예: `tonkatsu`, `kutsuonuide`).
- 44개 단어에 미리 넣고, 그림 없는 16개는 비운다. 읽기(`reading`)에서 계산하지 않는 이유: `kutsu o nuide kudasai` → `kutsuonuide`처럼 파일 이름이 읽기와 다르다.
- 그림이 있는지는 데이터가 아니라 에셋으로 판단한다(4.2).
