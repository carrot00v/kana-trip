- 기준 문서: `PLAN.md` 3번, `.claude/agents/designer.md`, `KanaTrip/Writing/WritingCanvas.swift`, `tools/make_onigiri_svg.py`(캐릭터 색 값)

SwiftUI 기본 컴포넌트, 시스템 글꼴, SF Symbols를 쓴다. 색은 시스템 색 대신 에셋 카탈로그의 Color Set(1.1)을 쓰고, 라이트·다크 값은 Color Set에 함께 넣는다. 외부 글꼴과 외부 패키지는 쓰지 않는다. 그림은 캐릭터 SVG 두 장만 쓴다(7.2).

## 1. 색

### 1.1 색 토큰

캐릭터 팔레트(`tools/make_onigiri_svg.py` 맨 위)에서 뽑았다. 모두 에셋 카탈로그의 Color Set으로 넣고, Appearances를 "Any, Dark"로 두어 두 값을 함께 적는다. 코드에서는 `Color("Ink")`처럼 이름으로 부른다.

| 토큰 (Color Set 이름) | 라이트 | 다크 | 역할 | 쓰는 곳 |
|---|---|---|---|---|
| `AppBackground` | `#FDF5E6` | `#1F1714` | 화면 배경 | 모든 화면의 바탕, 홈과 장면 진입의 목록 바탕 |
| `CardBackground` | `#FFFDF7` | `#2E2420` | 카드·캔버스 배경 | 캔버스, 획 데이터 글자의 바탕, 사지선다 선택지, 단어 카드, 목록 행 |
| `Ink` | `#4A2219` | `#F7EEDF` | 본문 | 글자, 제목, 판정 문구, 캔버스의 완성된 획, 획 데이터로 그린 글자 |
| `InkSecondary` | `#7A5A4C` | `#BCA697` | 보조 | 발음, 설명 줄, 안내 문구, 잠긴 행, 안 배운 글자 |
| `Outline` | `#4A2219` | `#8C7366` | 외곽선 | 카드와 선택지의 테두리(3번 절) |
| `AccentColor` | `#4A2219` | `#F7EEDF` | 강조 | 주 버튼 바탕, 보조 버튼 글자, 진행 막대, 할 차례인 세션의 번호 원, 지금 글자 |
| `AccentForeground` | `#FFFDF7` | `#1F1714` | 강조색 위 글자 | 주 버튼의 글자 |
| `Highlight` | `#F6B92B` | `#F6B92B` | 힌트·강조 노랑(바탕) | 시작점 번호 원의 바탕, 쓰기 포인트 상자의 옅은 바탕, 지금 글자의 형광펜 바탕 |
| `HighlightStrong` | `#A86A00` | `#F6B92B` | 힌트(선·아이콘) | 고리 점선 원, `lightbulb.fill` 아이콘, 틀린 글자 점 |
| `OnHighlight` | `#4A2219` | `#4A2219` | 노랑 위 글자 | 시작점 번호 원의 숫자 |
| `Correct` | `#2E7D4A` | `#6BC98A` | 맞음 | 맞음 아이콘, 정답 선택지 테두리, 완료 아이콘, "읽을 수 있어요"의 체크 |
| `Wrong` | `#B8233F` | `#FF6B7A` | 틀림 | 틀림 아이콘, 오답 선택지 테두리, 틀린 획, 빼먹은 고리 원 |

- `AccentColor`는 이름을 Xcode 기본값 그대로 둔다. 빌드 설정 `ASSETCATALOG_COMPILER_GLOBAL_ACCENT_COLOR_NAME = AccentColor`를 넣거나 앱 루트에 `.tint(Color("AccentColor"))`를 붙여 `ProgressView`, 버튼, 메뉴의 체크 표시가 모두 이 색을 따르게 한다. 지금 프로젝트에는 에셋 카탈로그가 없으므로 `KanaTrip/Assets.xcassets`를 새로 만든다.
- 강조색을 본문과 같은 진갈색으로 둔 이유: 레퍼런스의 주인공 색이 진갈색이고, 남은 유채색(빨강, 초록, 노랑)은 판정과 힌트에 이미 쓰인다. 강조색을 따로 만들면 다섯 번째 색이 생긴다. 강조색과 본문 색이 같아서 생기는 구분 문제(지금 글자, 쓰는 중인 선)는 2.5와 5.2에서 모양과 진하기로 푼다.
- 다크 모드의 배경은 검정이 아니라 진갈색 계열(`#1F1714`)로 둔다. 크림 바탕의 따뜻한 느낌을 다크에서도 이어 가기 위해서다. 시스템 배경(순수 검정)은 쓰지 않는다.

### 1.2 캐릭터 색과 판정 색을 섞지 않기

- 캐릭터의 두건 빨강 `#E2533F`, 볼 `#F5A7A0`, 김 `#34402F`, 밥알 결 `#EFE3CC`는 Color Set으로 만들지 않는다. SVG 안에만 있다. 화면의 어떤 글자, 버튼, 아이콘, 선에도 두건 빨강을 쓰지 않는다. 그래서 화면에서 빨강이 보이면 언제나 "틀림"이다.
- 틀림 빨강 `Wrong`은 두건 빨강과 색상과 밝기를 모두 다르게 했다. 두건 빨강은 주황 쪽 빨강(색상 약 7°, 밝기 L 0.227)이고, `Wrong`은 자주 쪽 진홍(색상 약 349°, 밝기 L 0.118)이다. 두 색의 대비는 약 1.6:1이다.
- 두건 빨강은 흰 글자를 올리면 대비가 3.8:1이라 버튼 바탕으로도 쓸 수 없다. 주 버튼을 빨강으로 하지 않은 또 하나의 이유다.
- 캐릭터는 판정이 나오는 화면(L2, Q1, Q2)에 넣지 않는다(7.2). 빨간 두건이 판정 줄 근처에 보이지 않게 한다.

### 1.3 색을 쓰는 규칙

- `Correct`, `Wrong`, `HighlightStrong`은 아이콘, 테두리, 선, 점에만 쓴다. 글자에는 쓰지 않는다. 새 값은 글자로도 4.5:1을 넘지만(1.4), 판정 문구는 본문 색으로 쓰고 앞의 아이콘에만 색을 주는 규칙을 그대로 둔다. 문구의 색이 바뀌면 색에 기대 읽게 되기 때문이다.
- 색 위에 올리는 글자: 주 버튼의 글자는 `AccentForeground`. `.borderedProminent`는 다크 모드에서도 글자를 흰색으로 그리는데, 다크의 강조색이 크림색이라 흰 글자가 보이지 않는다. 그래서 주 버튼에는 `.foregroundStyle(Color("AccentForeground"))`를 꼭 붙인다. 시작점 번호 원의 숫자는 라이트·다크 모두 `OnHighlight`(진갈색)다.
- 옅은 바탕: 쓰기 포인트 상자는 `Highlight`를 라이트 0.18, 다크 0.16 불투명도로 `CardBackground` 위에 깐다. 지금 글자의 형광펜 바탕은 `Highlight` 0.45(2.5).
- 흐리게: 답한 뒤의 나머지 선택지와 비활성 버튼은 불투명도 0.4. 잠긴 행은 불투명도를 낮추지 않고 글자를 `InkSecondary`로 바꾼다.
- `Color.primary`, `Color.secondary`, `Color(.systemBackground)` 같은 시스템 색은 쓰지 않는다. 앱 루트에 `.foregroundStyle(Color("Ink"), Color("InkSecondary"))`를 붙이면 그 아래의 `.foregroundStyle(.primary)`, `.foregroundStyle(.secondary)`가 각각 두 토큰으로 풀린다. 캔버스처럼 `GraphicsContext`로 직접 그리는 곳은 이 방식이 적용되지 않으므로 토큰 색을 직접 넘긴다.
- 목록(`List`)은 `.scrollContentBackground(.hidden)`과 `.background(Color("AppBackground"))`로 바탕을 바꾸고, 행마다 `.listRowBackground(Color("CardBackground"))`를 준다.
- 내비게이션 바의 제목 색은 앱 시작 때 `UINavigationBarAppearance`로 한 번 정한다. 제목과 큰 제목 모두 `Ink`, 둥근 굵은 글꼴(2.1). 바 배경은 `AppBackground`이고 그림자 선은 없앤다.

### 1.4 대비

WCAG 2 상대 휘도로 계산했다. 기준은 글자 4.5:1(큰 글자 3:1), 아이콘·테두리·선 같은 글자 아닌 표시 3:1이다. 앱의 17pt 굵은 글자(버튼, 머리글)는 WCAG의 "큰 글자"(18pt 이상 또는 14pt 굵게를 CSS 픽셀로 환산한 값)에 들지 않는다고 보고 4.5:1을 적용했다.

### 1.5 라이트·다크에서 달라지는 것

- 다크에서는 강조색이 크림색이 된다. 주 버튼은 크림 바탕에 진갈색 글자, 진행 막대와 할 차례 번호 원도 크림색이다.
- 캔버스의 완성된 획은 `Ink`라서 라이트에서는 진갈색, 다크에서는 크림색 선이 된다.
- 시작점 번호 원은 두 모드 모두 노랑 바탕에 진갈색 숫자다.
- `HighlightStrong`은 라이트에서 크림 바탕에 보이도록 어두운 호박색(`#A86A00`), 다크에서는 노랑 그대로다.
- 캐릭터 SVG는 한 장으로 두 모드에 쓴다(7.2). 다크에서 진갈색 외곽선이 바탕에 묻히는지는 9번에서 확인한다.

## 2. 글자

### 2.1 한글과 로마자

시스템 글꼴과 텍스트 스타일을 쓴다. 고정 크기를 쓰지 않으므로 Dynamic Type을 따른다.

둥근 느낌은 시스템 글꼴의 둥근 디자인으로 낸다. 앱 루트에 `.fontDesign(.rounded)`를 한 번 붙인다. 외부 글꼴은 쓰지 않는다.

- 효과가 있는 글자: 로마자(발음, 사지선다 선택지, 단어 읽기의 발음 표기)와 숫자(진행 숫자, "2/3", 획 수). SF Pro Rounded로 그려진다.
- 효과가 없는 글자: 한글은 시스템 한글 글꼴에 둥근 디자인이 없어 그대로 그려진다. 가나도 그대로다(2.2). 한 줄에 둥근 로마자와 보통 한글이 섞이는 자리("su", "따라 쓰기 1/2")가 어색하지 않은지 9번에서 확인한다.
- 내비게이션 바의 제목은 `UIFont.systemFont(...).fontDescriptor.withDesign(.rounded)`로 같은 둥근 디자인을 준다(1.3).

| 단계 | 텍스트 스타일 | 기본 크기 | 쓰는 곳 |
|---|---|---|---|
| 큰 제목 | `.largeTitle` 굵게 | 34pt | 홈과 장면 진입의 내비게이션 제목 |
| 제목 | `.title2` 굵게 | 22pt | 완료 화면 제목, 사지선다 선택지의 로마자, 단어의 읽기 |
| 머리글 | `.headline` | 17pt | 세션 행 이름, 장면 행 이름, 버튼 글자, 질문 문구 |
| 본문 | `.body` | 17pt | 뜻, 완료 화면 요약 |
| 설명 | `.subheadline` | 15pt | 쓰기 포인트 문구, 판정 문구, 세션 행 설명, 어디서 보는지, 단어 위 발음 표기 |
| 작은 글자 | `.footnote` | 13pt | 진행 숫자, "따라 쓰기 1/2", 획 수 |

- 숫자가 바뀌는 자리(진행 숫자, 횟수)는 `.monospacedDigit()`으로 폭이 흔들리지 않게 한다. 둥근 디자인에서도 그대로 쓸 수 있다.
- 굵기는 보통과 굵게 두 가지만 쓴다.
- 로마자가 주인공인 자리(기억으로 쓰기의 발음, 글자 소개의 발음)는 `.system(size: 48, design: .rounded)`과 `.title` 28pt를 쓴다. 발음 48pt는 고정 크기다(2.4).

| 장면 완료의 목표 단어 | 시스템 글꼴, 굵게 | 22pt | C2 장면 완료 |
| 못 읽는 글자가 있는 단어 | 시스템 글꼴 | 17pt | 장면 진입의 못 읽는 단어 줄 |
| 목록 속 글자 | 시스템 글꼴 `.title3` | 20pt | 홈의 장면 행, 장면 완료의 다음 장면 글자 |

시스템 글꼴로 쓰는 가나는 시스템 일본어 글꼴(고딕체)을 그대로 쓴다. 레퍼런스의 둥근 굵은 가나와 비슷한 시스템 내장 글꼴로 Hiragino Maru Gothic ProN(마루 고딕)이 있지만 쓰지 않는다. 굵기가 W4 하나뿐이라 2.5의 "배운 글자는 굵게" 구분이 사라지고, 획 끝이 둥글게 뭉개져 교과서체에서 더 멀어진다. 색만 `Ink`, `InkSecondary`로 바꾼다.

### 2.3 획 데이터로 그리는 글자

배우거나 묻는 글자는 글꼴이 아니라 `Kana.strokes`를 선으로 그린다. 이번 개정에서 바꾼 것은 색뿐이다. 모양, 굵기, 반지름은 그대로다.

- 이유: 외부 글꼴을 쓸 수 없고, 시스템 일본어 글꼴은 고딕체다. 캔버스의 기준 획(KanjiVG)은 교과서체에 가깝다. 글꼴로 보여 주고 다른 모양을 쓰게 하면 "본 대로 썼는데 틀림"이 생긴다.
- 그리는 규칙: 정사각형 바탕(`CardBackground`, 모서리 반지름 20pt, 외곽선 없음) 위에 109 좌표계를 변 길이에 맞춰 늘린다. 선은 `Ink`, 굵기는 좌표계 기준 5(캔버스의 완성된 획과 같음), 끝과 이음은 둥글게.
- L1에서는 획마다 시작점 번호 원(`Highlight` 바탕, `OnHighlight` 숫자)을, 고리가 있는 획에는 `HighlightStrong` 점선 원을 함께 그린다(5번 절과 같은 모양). Q1에서는 둘 다 그리지 않는다.

시스템 글꼴로 쓰는 작은 가나(단어, 글자 줄, 목록)에는 일본어 로캘을 지정한다. 한국어 기기에서도 일본어 글꼴로 그려지고 VoiceOver가 일본어로 읽게 하기 위해서다.

### 2.4 Dynamic Type을 따르지 않는 것

| 대상 | 이유 |
|---|---|
| 획 데이터로 그린 글자, 캔버스 안의 모든 표시 | 캔버스 크기에 비례한다 |
| 단어 읽기의 가나(56pt)와 그 위 발음 표기 | 글자와 표기의 세로 줄 맞춤이 깨진다. 이미 충분히 크다 |
| 글자 줄의 가나(34pt), 기억으로 쓰기의 발음(48pt) | 이미 충분히 크고, 커지면 캔버스 자리를 밀어낸다 |
| 목표 단어의 가나(28pt, 22pt, 17pt) | 한 줄에 놓는 폭 계산이 깨진다. 옆의 뜻과 상태 문구는 텍스트 스타일을 따른다 |
| 캐릭터 그림(7.2) | 장식이라 글자 크기와 상관없다. 큰 글자 크기에서 자리가 모자라면 숨긴다(8.1) |

### 2.5 단어 속 글자의 진하기

장면 진입의 목표 단어 카드와 L1의 단어 카드에서, 단어의 글자를 하나씩 다른 모양으로 그린다. 어느 글자가 어느 상태인지는 scene-flow.md 5.1과 6.2에 있다.

| 글자 상태 | 색 | 굵기 | 그 밖 | 쓰는 곳 |
|---|---|---|---|---|
| 배운 글자 | `Ink` | 굵게(`.bold`) | 없음 | 장면 진입, L1 |
| 안 배운 글자 | `InkSecondary` | 보통 | 없음 | 장면 진입, L1 |
| 지금 글자 | `AccentColor` | 굵게(`.bold`) | 글자 뒤에 형광펜 바탕(`Highlight` 0.45, 글자 칸 크기, 모서리 4pt). 글자 아래 2pt 띄우고 밑줄(`AccentColor`, 굵기 2pt, 글자 폭) | L1만 |

- 강조색이 본문 색과 같아졌으므로, 지금 글자와 배운 글자는 색이 아니라 형광펜 바탕과 밑줄로 구분한다. 두 가지 모양 표시가 붙으므로 색 차이가 없어도 구분된다.
- 안 배운 글자는 불투명도를 낮추지 않고 보조 색을 쓴다. 잠긴 행과 같은 방식이다(1.3).
- 색과 굵기를 함께 바꾼다. 장면 진입에서는 단어마다 "배운 글자 2 / 4" 또는 "읽을 수 있어요"가 함께 나오고, L1의 지금 글자에는 형광펜 바탕과 밑줄이 붙는다(8.3).
- 굵기는 시스템 일본어 글꼴의 굵은 모양을 쓴다. 글꼴을 따로 넣지 않는다.
- 단어 읽기(W)의 글자에는 이 규칙을 쓰지 않는다. 거기서는 모든 글자가 `Ink`이고, 안 배운 글자와 탁음 글자, 붙여 쓴 한자는 위의 발음 표기로 구분한다.
- 붙여 쓴 한자(かつ丼의 丼 등, PLAN.md 3번 "단어의 표기")는 가르치지 않으므로 늘 "안 배운 글자" 모양이고, "배운 글자 n / m"의 m에 세지 않는다. 단어 읽기에서는 늘 발음 표기가 붙고, 발음 소리가 켜져 있어도 한자 한 글자만 따로 읽어 주지 않는다.

## 3. 간격, 배치, 모양

| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| 아주 좁게 | 4pt | 아이콘과 글자 사이, 단어의 글자 사이 |
| 좁게 | 8pt | 세션 화면의 영역 사이, 아래 버튼 영역의 아래 여백 |
| 보통 | 12pt | 버튼 사이, 선택지 사이, 상자의 안쪽 여백, 아래 버튼 영역의 위 여백 |
| 화면 여백 | 16pt | 캔버스·버튼·상자·선택지의 좌우 여백 |
| 글 여백 | 20pt | 상자 밖에 놓인 글(질문, 글자 정보 줄)의 좌우 여백 |
| 넓게 | 24pt | 완료 화면의 묶음 사이 |

- 배치의 기준선: 화면을 위아래 절반으로 나눴을 때 누르거나 쓰는 대상은 모두 아래 절반에 둔다. 예외는 닫기 버튼과 홈의 메뉴 버튼 둘뿐이다. 둘 다 세션 중에 자주 쓰는 조작이 아니다.
- 세션 화면의 주 버튼은 항상 같은 자리(아래 안전 영역 위 8pt, 높이 56pt)다.
- 쓰기 화면(L2, Q2)은 스크롤하지 않는다. 캔버스에서 획을 긋는 동작과 스크롤이 겹치기 때문이다. 그 밖의 세션 화면도 한 화면에 들어가게 하되, 큰 글자 크기에서는 내용 영역만 스크롤한다(8.1).

### 모서리와 외곽선

레퍼런스의 굵은 진갈색 외곽선은 캐릭터에서는 360 좌표계의 6(120pt로 그리면 2pt)이다. UI에서는 "손에 잡히는 물건"처럼 보여야 하는 카드에만 같은 2pt 외곽선을 두고, 목록과 버튼은 시스템 모양을 따른다. 캔버스와 획 데이터 글자의 바탕에는 외곽선을 두지 않는다.

| 요소 | 모서리 반지름 | 외곽선 | 비고 |
|---|---|---|---|
| 사지선다 선택지 | 16pt | `Outline` 2pt | 답한 뒤 정답·오답 칸은 외곽선을 `Correct`·`Wrong` 3pt로 바꾼다(6.1). 굵기도 달라져 색만으로 구분하지 않는다 |
| 단어 카드(L1) | 12pt | `Outline` 2pt | |
| 캔버스, 획 데이터 글자의 바탕 | 20pt | 없음 | 5번 절의 모양을 바꾸지 않는다. 바탕과 경계는 `CardBackground`와 `AppBackground`의 차이로만 보인다(9번에서 확인) |
| 쓰기 포인트 상자 | 12pt | 없음 | 노랑 옅은 바탕이 경계를 만든다. 안내문이라 물건처럼 보이지 않게 한다 |
| 주 버튼 | 16pt (`.buttonBorderShape(.roundedRectangle(radius: 16))`) | 없음 | 바탕이 강조색(진갈색)이라 외곽선과 같은 색이다 |
| 보조 버튼 | 16pt | 없음 | `.bordered` 기본 모양(강조색을 옅게 깐 바탕) |
| 목록 행(홈, 장면 진입) | `insetGrouped` 기본값 | 없음 | 시스템 목록을 그대로 쓴다. 바탕 색만 바꾼다(1.3) |

- 외곽선은 `.overlay(RoundedRectangle(cornerRadius: r).strokeBorder(Color("Outline"), lineWidth: 2))`로 그린다. 테두리가 안쪽으로 그려지므로 칸 크기는 바뀌지 않는다.
- 그림자, 기울임, 손그림처럼 흔들리는 테두리는 넣지 않는다. 손그림 느낌은 캐릭터가 맡는다.

## 4. 버튼과 터치 영역

### 4.1 버튼 종류

| 종류 | SwiftUI | 크기 | 쓰는 곳 |
|---|---|---|---|
| 주 버튼 | `.borderedProminent`, `.controlSize(.large)`, 글자 `AccentForeground` | 높이 56pt, 폭은 좌우 여백 16pt를 뺀 전부 | 화면마다 하나. 다음, 시작, 써 보기, 읽기 확인 |
| 보조 버튼 | `.bordered`, `.controlSize(.large)` | 높이 56pt, 폭 112pt | 주 버튼 왼쪽. 다시 쓰기, 가이드 보기 |
| 글자 버튼 | `.plain` + 강조색 글자 | 높이 44pt, 폭은 글자 + 좌우 16pt | 세션 완료의 "여기까지 하기" |
| 아이콘 버튼 | `.plain` | 44×44pt | 닫기(`xmark`), 홈 메뉴(`ellipsis.circle`) |
| 선택지 | `CardBackground` 바탕 + `Outline` 2pt의 `Button` | 높이 72pt, 2열 | 사지선다 |

- 한 화면에 주 버튼은 하나다.
- 보조 버튼을 주 버튼의 왼쪽에 두는 이유: 오른손 엄지에 가까운 오른쪽에 가장 자주 누르는 버튼을 둔다. 왼손 사용자를 위한 좌우 바꿈은 넣지 않는다.
- 버튼 문구는 한 줄, 동사로 끝나는 짧은 말로 쓴다("다음", "써 보기", "퀴즈 시작").
- 비활성 버튼은 `disabled`로 두고 자리를 비우지 않는다. 완성 전의 "다음"처럼 곧 누르게 될 버튼이 미리 보여야 한다.
- 글자 버튼은 강조색이 본문 색과 같아져 색만으로는 누를 수 있는 글자인지 드러나지 않는다. 그래서 "여기까지 하기"는 굵게 쓰고, 주 버튼 바로 아래 가운데에 두어 자리로도 알린다(scene-flow.md 11번).

### 4.2 터치 영역

- 누르는 대상은 모두 44×44pt 이상. 보이는 모양이 그보다 작으면(스피커 아이콘이 붙은 글자 등) `contentShape`로 영역을 넓힌다.
- 서로 다른 누르는 대상 사이는 8pt 이상 띄운다. 이동 중 흔들림으로 옆 대상을 누르는 일을 줄인다.
- 캔버스와 아래 버튼 사이는 12pt. 획을 아래로 길게 빼다가 버튼을 누르지 않도록, 획을 긋는 중(손가락이 캔버스에서 시작해 아직 떼지 않은 동안)에는 버튼이 반응하지 않아야 한다. 드래그가 캔버스에서 시작됐으면 캔버스 밖으로 나가도 캔버스가 계속 받는다(`DragGesture`의 기본 동작).
- 목록 행은 행 전체가 누르는 영역이다.
- 캐릭터 그림은 누를 수 없다.

## 5. 쓰기 캔버스

스파이크의 `WritingCanvas`를 기준으로 하고, 바꾸는 곳은 "스파이크와의 차이" 열에 적었다. 굵기와 반지름은 109 좌표계의 값이고, 화면에서는 `캔버스 변 ÷ 109`를 곱한다. 캔버스 변이 370pt면 배율은 약 3.4, 343pt면 약 3.1이다.

이번 개정(2026-11-13)에서는 색만 토큰으로 바꿨다. 크기, 자리, 굵기, 반지름, 점선 간격, 그리는 순서, 시간은 그대로다. 판정과 연결된 표시이기 때문이다.

### 5.1 크기와 자리

- 정사각형. 변은 `min(화면 폭 − 32, 남는 높이)`. 가장 작은 값의 기준은 300pt다(scene-flow.md 3번).
- 화면 아래쪽, 버튼 영역 바로 위에 둔다. 좌우 가운데 정렬.
- 바탕은 `CardBackground`, 모서리 반지름 20pt. 테두리 선은 없다.

### 5.2 선과 표시

| 요소 | 색 | 굵기·크기(좌표계) | 화면 굵기(변 370pt) | 언제 보이나 | 스파이크와의 차이 |
|---|---|---|---|---|---|
| 십자 점선 | `InkSecondary`, 불투명도 0.25 | 화면 1pt 고정, 점선 5-5 | 1pt | 항상 | 회색 → `InkSecondary` |
| 가이드 획 | `Ink`, 불투명도 0.22 | 7 | 약 24pt | 따라 쓰기, 가이드가 켜진 기억으로 쓰기 | 회색 → `Ink` |
| 완성된 획 | `Ink` | 5 | 약 17pt | 맞게 쓴 획. 사용자가 그은 선이 아니라 기준 획 모양으로 그린다 | `.primary` → `Ink` |
| 쓰는 중인 선 | `Ink`, 불투명도 0.6 | 5 | 약 17pt | 손가락을 대고 있는 동안 | `.blue` → `Ink` 0.6 |
| 틀린 획 | `Wrong`, 불투명도 0.7 | 5 | 약 17pt | 틀린 직후 0.9초 | `.red` → `Wrong` |
| 시작점 번호 원 | `Highlight` 바탕, `OnHighlight` 숫자 | 반지름 5.5, 숫자 8 굵게 | 지름 약 37pt | 가이드가 보일 때, 지금 쓸 획의 시작점 하나 | 주황 → `Highlight`, 숫자 흰색 → `OnHighlight` |
| 고리 점선 원 | `HighlightStrong` | 화면 2pt 고정, 점선 5-4 | 2pt | 가이드가 보일 때, 지금 쓸 획에 고리가 있으면 | 주황 → `HighlightStrong` |
| 빼먹은 고리 원 | `Wrong` | 화면 2pt 고정, 점선 5-4 | 2pt | 고리를 빼먹은 직후 0.9초. 가이드가 꺼져 있어도 보인다 | `.red` → `Wrong` |

그리는 순서(아래에서 위): 십자 점선 → 가이드 획 → 완성된 획 → 시작점 번호 원 → 고리 점선 원 → 빼먹은 고리 원 → 틀린 획 → 쓰는 중인 선.

쓰는 중인 선을 강조색이 아니라 `Ink` 0.6으로 둔 이유: 강조색이 본문 색과 같아져, 그대로 두면 쓰는 중인 선과 완성된 획이 같은 색이 된다. 0.6으로 옅게 그리다가 맞으면 진한 기준 획 모양으로 바뀌고, 틀리면 빨강으로 바뀐다. 파랑을 새로 들이지 않고 셋을 구분한다.

### 5.3 색만으로 구분하지 않기

캔버스의 선은 색 말고도 한 가지씩 더 다르다.

| 구분 | 색 밖의 차이 |
|---|---|
| 가이드 획과 완성된 획 | 가이드가 더 굵고 옅다. 완성된 획은 가늘고 진하다 |
| 쓰는 중인 선과 완성된 획 | 쓰는 중인 선은 옅고(0.6) 손가락이 간 대로 흔들린다. 손을 떼고 맞으면 기준 획 모양의 진한 선으로 바뀐다 |
| 맞은 획과 틀린 획 | 맞은 획은 기준 획 모양으로 남고, 틀린 획은 0.9초 뒤 사라진다. 판정 줄에 아이콘 모양(`checkmark`, `xmark`)과 문구가 함께 나오고 햅틱이 다르다 |
| 고리 안내와 빼먹은 고리 | 빼먹은 고리는 "점선 자리에서 고리를 만들어야 해요" 문구와 함께 나온다 |

### 5.4 동작

- 획 하나를 긋고 손가락을 떼면 바로 판정한다. 확인 버튼은 없다.
- 틀린 획의 표시 시간은 0.9초(스파이크 값). 그동안 새 획을 그으면 표시를 바로 지운다.
- 글자를 완성한 뒤에는 캔버스가 입력을 받지 않는다.
- 캔버스 안에는 버튼을 넣지 않는다.
- 스파이크의 글자 고르기 줄, 가이드 토글, 판정 감도 슬라이더는 정식 화면에 넣지 않는다. 감도는 고정값으로 쓴다(값은 PLAN.md 8번의 미정 항목).

## 6. 피드백

### 6.1 한 번의 피드백은 네 가지를 함께 쓴다

| 일 | 아이콘 (모양) | 색 | 문구 | 햅틱 (`sensoryFeedback`) |
|---|---|---|---|---|
| 획 맞음 | `checkmark.circle.fill` | `Correct` | 좋아요 | `.impact(weight: .light)` |
| 획 틀림 | `xmark.circle.fill` | `Wrong` | 판정별 문구 | `.error` |
| 글자 완성 | `checkmark.seal.fill` | `Correct` | 완성, … | `.success` |
| 사지선다 정답 | `checkmark.circle.fill` | `Correct` | 맞아요 | `.success` |
| 사지선다 오답 | `xmark.circle.fill` | `Wrong` | 정답은 to예요 | `.error` |
| 가이드 켜짐 | `lightbulb.fill` | `HighlightStrong` | 가이드를 보고 따라 쓰세요 | 없음 |
| 단어 읽기 확인 | 없음 | 없음 | 읽기와 뜻이 나타남 | `.impact(weight: .light)` |
| 세션 완료, 장면 완료 | 웃는 캐릭터 + `checkmark.circle.fill` 배지(7.2) | `Correct` (배지) | … 완료 | `.success` |

- 스파이크는 획이 맞을 때마다 `.success`를 냈다. 정식 화면에서는 획에는 가벼운 진동, 글자 완성에만 `.success`를 써서 둘을 구분한다.
- 소리 효과는 넣지 않는다. 이동 중에 쓰는 앱이고, 소리는 발음 재생에만 쓴다(기본 꺼짐).
- 판정 줄의 아이콘은 문구 왼쪽에 4pt 띄워 놓는다. 크기는 문구와 같은 텍스트 스타일. 문구는 `Ink`.
- 사지선다의 답한 뒤 모양: 고른 칸과 정답 칸의 외곽선이 `Outline` 2pt에서 `Correct` 또는 `Wrong` 3pt로 바뀌고, 칸 오른쪽 위에 같은 색의 `checkmark.circle.fill` 또는 `xmark.circle.fill`(20pt)이 붙는다.

### 6.2 움직임

- 내용이 바뀔 때 0.2초 페이드. 선택지 테두리와 버튼 활성 변화는 0.15초.
- 축하 효과는 세션 완료(C1)와 장면 완료(C2) 화면의 캐릭터 하나로만 한다.
  - 화면이 나타날 때 웃는 캐릭터가 한 번 커지며 나온다: 크기 0.85 → 1.0, 불투명도 0 → 1, `.spring(response: 0.35, dampingFraction: 0.7)`. 반복하지 않는다.
  - 반짝임은 웃는 표정 SVG에 이미 그려진 노랑 선 세 개뿐이다. 따로 움직이지 않는다.
  - 색종이, 터지는 입자, 화면 흔들림, 반복 애니메이션, 소리는 넣지 않는다.
  - 학습 화면(L1, L2, Q1, Q2, W)의 피드백에는 움직임을 더하지 않는다. 글자 완성도 6.1의 아이콘, 문구, 햅틱만 쓴다.
- "동작 줄이기"가 켜져 있으면 모든 전환을 없앤다. 캐릭터는 처음부터 제 크기로 보이고 커지는 움직임이 없다. 틀린 획의 0.9초 표시는 정보라서 그대로 둔다.

### 6.3 문구의 말투

- "~해요", "~예요"로 끝낸다. 지시할 때만 "~하세요"를 쓴다("따라 쓰세요").
- 한 줄, 15자 안팎. 판정 문구는 가장 긴 것("점선 자리에서 고리를 만들어야 해요")이 375pt 폭에서 한 줄에 들어간다.
- 틀렸을 때는 무엇이 달랐는지만 말한다. "틀렸어요", "실패" 같은 평가하는 말은 쓰지 않는다.
- 느낌표, 이모지, 물결표를 쓰지 않는다. 캐릭터가 나와도 캐릭터의 말풍선이나 대사는 넣지 않는다.
- 글자를 가리킬 때는 가나를 그대로 쓴다("と, か는 다음 장면 퀴즈에 다시 나와요").
- 같은 것은 같은 낱말로 부른다: 획, 고리, 가이드, 따라 쓰기, 기억으로 쓰기, 발음, 장면. 화면 문구에서는 "세션"이라는 말 대신 "배우기", "퀴즈", "단어 읽기"라는 이름을 쓴다(VoiceOver 레이블은 예외).

### 7.2 캐릭터

캐릭터는 `docs/design/character/`의 오니기리 두 장이다. 기본 표정(`onigiri-default.svg`)과 웃는 표정(`onigiri-happy.svg`). 둘 다 360×360 정사각형이다.

에셋: SVG를 그대로 Image Set(`OnigiriDefault`, `OnigiriHappy`)에 넣고 Scales는 Single Scale, "Preserve Vector Data"를 켜고 Render As는 Original Image로 둔다. 다크 모드용 별도 그림은 두지 않는다.

둘 자리:

| 화면 | 표정 | 크기 | 자리 | 이유 |
|---|---|---|---|---|
| H 홈 | 기본 | 64×64pt | "히라가나" 섹션 머리글의 오른쪽 끝, 머리글 글자와 아래 끝을 맞춘다. 머리글 높이가 64pt + 위아래 4pt로 늘어난다 | 앱을 켤 때마다 보는 자리. 화면 위쪽의 보기만 하는 정보 영역이라 엄지 조작과 겹치지 않는다. 목록 안이라 스크롤하면 함께 올라간다 |
| C1 세션 완료 | 웃는 | 120×120pt | 지금의 `checkmark.circle.fill` 64pt 자리. 캐릭터 아래 끝을 내용 영역 높이의 위에서 3분의 1 지점에 둔다. 캐릭터 오른쪽 아래에 `checkmark.circle.fill`(32pt, `Correct`, 바깥에 `AppBackground` 3pt 테두리)를 겹친다. 배지 중심은 캐릭터 사각형의 오른쪽 아래 꼭짓점에서 안쪽으로 16pt | 세션 하나를 끝낸 순간을 알리는 자리. 체크 배지가 "완료"라는 뜻을 모양으로 지킨다 |
| C2 장면 완료 | 웃는 | 120×120pt | 지금의 장면 아이콘 64pt 자리. 배지는 C1과 같다. 장면 아이콘(`fork.knife`)은 이 화면에서 빼고 장면 이름은 제목이 전한다 | 장면 완료는 가장 큰 성취라 캐릭터가 가장 어울린다. 두 그림을 겹치면 작은 화면에서 어지럽다 |

- 375×667pt에서 C2의 세로 합계는 바뀌지 않는다. 캐릭터가 64pt에서 120pt로 56pt 커지는 만큼 위 여백이 126pt(571 ÷ 3 − 64)에서 70pt(571 ÷ 3 − 120)로 줄어 합계 530pt(사용 가능 571)다. C1도 같은 방식이다.
- 120pt를 고른 이유: 캐릭터 외곽선이 360 좌표계의 6이라 120pt에서 정확히 2pt가 된다. UI 카드의 외곽선 굵기(3번 절)와 같다. 64pt에서는 약 1.1pt로 가늘어지지만 홈의 작은 장식이라 괜찮다.
- 다시 한 세션의 C1(주 버튼이 "장면으로 돌아가기")에도 같은 캐릭터를 둔다. 퀴즈에 틀린 글자가 있었어도 웃는 표정을 쓴다. 세션을 끝낸 것을 알리는 화면이고, 표정으로 결과를 평가하지 않는다(6.3).

두지 않는 자리:

| 화면 | 이유 |
|---|---|
| S 장면 진입 | 375×667pt에서 이미 113pt가 넘친다(scene-flow.md 5.4). 목표 단어 카드가 이 화면의 주인공이다 |
| L1 글자 소개 | 획 데이터 글자 200pt와 단어 카드가 이미 화면을 채운다(6.3의 여유 29pt). 배울 글자 옆에 그림이 있으면 시선이 나뉜다 |
| L2, Q2 쓰기 | 캔버스 크기가 최우선이다. 판정 줄 근처에 빨간 두건이 보이면 틀림 빨강과 섞인다(1.2) |
| Q1 사지선다 | 판정 화면이다. 캐릭터의 표정이 정답·오답을 암시하는 것처럼 읽힐 수 있다 |
| W 단어 읽기 | 단어가 화면의 내용이다. 스스로 확인하는 화면이라 반응하는 그림이 어울리지 않는다 |
| 빈 상태 | 지금 설계에는 빈 화면이 없다. 장면 2의 내용이 없는 빌드의 "준비 중이에요"(scene-flow.md 15번 권장안 6)는 시스템 알림이라 그림을 넣지 않는다. 뒤에 빈 화면이 생기면 기본 표정 96pt를 쓴다 |

- 캐릭터는 장식이다. VoiceOver에서는 읽지 않는다(`accessibilityHidden(true)`).
- 화면마다 캐릭터는 하나만 둔다. 캐릭터를 버튼, 판정 표시, 진행 표시로 쓰지 않는다.
- 캐릭터에 말풍선과 대사를 붙이지 않는다(6.3).

## 8. 접근성

### 8.1 Dynamic Type

- 2.1의 글자는 모두 텍스트 스타일을 써서 설정을 따른다.
- 홈, 장면 진입, L1, Q1, W, 완료 화면: 모든 크기를 지원한다. 내용이 넘치면 내용 영역이 세로로 스크롤되고, 아래 주 버튼은 고정된 채 남는다. 사지선다 선택지는 접근성 크기에서 2열을 1열 4행으로 바꾼다.
- 쓰기 화면(L2, Q2): 스크롤할 수 없으므로 `accessibility1` 크기까지만 따른다(`.dynamicTypeSize(...DynamicTypeSize.accessibility1)`). 그보다 크게 설정해도 이 화면의 글자는 `accessibility1` 크기에서 멈춘다. 캔버스 크기를 지키는 것이 우선이다. 쓰기 포인트 문구는 직전 화면(L1)에서 전체 크기로 읽을 수 있다.
- 버튼 문구는 줄바꿈하지 않고 `minimumScaleFactor(0.8)`까지 줄인다.
- 캐릭터: 접근성 글자 크기(`accessibility1` 이상)에서는 홈의 캐릭터를 숨긴다. 완료 화면의 캐릭터는 80pt로 줄인다. 글자가 들어갈 자리를 먼저 지킨다.

### 8.2 VoiceOver

| 대상 | 레이블 | 비고 |
|---|---|---|
| 가나 글자(모든 화면) | 글자 그대로, 일본어로 읽게 언어 지정 | 사지선다의 묻는 글자는 예외. 아래 참고 |
| 사지선다의 묻는 글자 | "문제 글자" | 일본어로 읽으면 답이 된다. 답한 뒤에는 글자를 일본어로 읽게 바꾼다 |
| 획 데이터로 그린 글자(L1) | "す, su, 2획" | 하나의 요소로 묶는다 |
| 장면 행 | "1번 밥집 간판, 새 글자 す し と ん か つ, 세션 3개 중 0개 완료" / 잠긴 행은 "2번 역, 잠김" | 행 전체를 하나로 |
| 세션 행 | "1 배우기, 할 차례" / "퀴즈, 잠김, 배우기를 끝내면 열려요" / "배우기, 완료, 다시 하기" | |
| 목표 단어 행(장면 진입) | "とんかつ, 돈가스, 글자 4개 중 2개 배움" / "とんかつ, 돈가스, 읽을 수 있어요" | 행 전체를 하나로. 글자별 진하기는 읽지 않는다 |
| 못 읽는 단어 줄(장면 진입) | "아직 못 읽는 글자가 있는 단어, そば, うどん, とんこつ" | 줄 전체를 하나로 |
| 단어 카드(L1) | "밥집 간판 단어, すし의 す, 초밥" | 카드 전체를 하나로. 장면 아이콘은 읽지 않는다 |
| 진행 막대와 숫자 | "진행, 6개 중 2개" | 하나로 묶는다 |
| 닫기 버튼 | "닫기" | 힌트 "진행은 저장돼요" |
| 홈 메뉴 | "더 보기" | |
| 쓰기 포인트 상자 | "쓰기 포인트, " + 문구 | 전구 아이콘은 읽지 않는다 |
| 캔버스 | "쓰기 칸. す, 2획 중 1번째 획" | 직접 터치 허용(`accessibilityDirectTouch`). 획을 그을 때마다 값이 바뀐다 |
| 선택지 | "ka" 등 로마자 | 답한 뒤: "to, 정답", "ka, 내가 고른 답, 오답" |
| 단어의 글자 | 발음 표기가 있으면 "こ, ko" | 단어 전체도 하나의 요소로 읽을 수 있게 한다 |
| 색 아이콘 | 읽지 않음 | 뜻은 옆의 문구가 전한다 |
| 캐릭터 그림, 완료 화면의 체크 배지 | 읽지 않음 | 완료는 제목 문구("배우기 완료")가 전한다 |

- 판정 문구가 바뀌면 알림으로 읽어 준다(`AccessibilityNotification.Announcement`). 화면을 보지 않아도 "좋아요", "방향이 반대예요"를 들을 수 있어야 한다.
- 화면 내용이 바뀌면(다음 글자, 다음 문항) 초점을 질문 또는 글자 정보 줄로 옮긴다.
- 캔버스의 직접 터치는 VoiceOver 사용자가 획을 그을 수 있게 하는 최소한의 지원이다. 가이드를 볼 수 없는 사용자를 위한 쓰기 대체 수단은 이 단계의 범위에 넣지 않았다.

### 8.3 색만으로 구분하지 않기

| 구분해야 하는 것 | 색 | 색 밖의 표시 |
|---|---|---|
| 맞음과 틀림(판정 줄) | `Correct`, `Wrong` | 아이콘 모양(`checkmark`, `xmark`)과 문구 |
| 정답 선택지와 오답 선택지 | `Correct`, `Wrong` 테두리 | 테두리 굵기(2pt → 3pt), 칸 안의 아이콘 모양, 판정 줄 문구 "정답은 to예요" |
| 열린 장면, 잠긴 장면, 끝낸 장면 | `AccentColor`, `InkSecondary`, `Correct` | 아이콘 모양(장면 아이콘, 자물쇠, 체크), 오른쪽 글자("0/3", 없음, "완료") |
| 세션의 할 차례, 잠김, 완료 | `AccentColor`, `InkSecondary`, `Correct` | 아이콘 모양(번호, 자물쇠, 체크)과 설명 줄 문구 |
| 캔버스의 선 | 5.3 참고 | 5.3 참고 |
| 퀴즈에서 틀린 글자(세션 완료) | `HighlightStrong` 점 | 요약 문구에 글자를 적는다 |
| 단어 속 배운 글자와 안 배운 글자 | `Ink`, `InkSecondary` | 굵기(굵게, 보통), 단어 옆의 "배운 글자 2 / 4" 또는 `checkmark` + "읽을 수 있어요" |
| 단어 속 지금 글자와 배운 글자(L1) | 둘 다 `Ink` 계열 | 지금 글자에만 형광펜 바탕과 밑줄 |
| 발음 소리 켜짐 | 없음 | 스피커 아이콘이 보이는지, 메뉴의 체크 표시 |
| 틀림 빨강과 캐릭터의 두건 빨강 | `Wrong`, 두건 `#E2533F` | 두건 빨강은 UI에 쓰지 않고, 캐릭터는 판정 화면에 나오지 않는다(1.2, 7.2) |

### 8.4 그 밖의 설정

- 동작 줄이기: 6.2.
- 대비 증가: Color Set의 "High Contrast" 칸에 두 토큰의 진한 값을 더 넣는다. `InkSecondary` 라이트 `#5C3D31`(크림 바탕에서 8.9:1), 다크 `#D9C7B8`(10.8:1). `Outline` 다크 `#BCA697`(다크 바탕에서 7.6:1). 나머지 토큰은 그대로 둔다. 가이드 획의 불투명도는 0.22에서 0.4로 올린다.
- 굵은 텍스트: 시스템 글꼴이 알아서 따른다. 획 데이터로 그린 글자와 캔버스의 선 굵기는 바꾸지 않는다(기준 획과 굵기가 달라지면 안 된다). 카드 외곽선 2pt도 바꾸지 않는다.
- 햅틱은 시스템 설정을 따른다. 앱 안에 따로 끄는 설정을 두지 않는다.

## 9. 실기기에서 확인하지 않은 값

이 문서의 수치는 코드와 화면 크기에서 계산한 것이고, 기기에서 눈으로 보지 않았다. 구현 뒤에 아래를 확인하고 필요하면 값을 고친다.

| 값 | 확인할 것 |
|---|---|
| 가이드 획의 불투명도 0.22 (`Ink`) | 밝은 야외와 다크 모드에서 가이드가 보이는지. 완성된 획과 헷갈리지 않는지 |
| 시작점 번호 원의 지름(약 37pt) | よ, こ처럼 획의 시작점이 가까운 글자에서 번호 원이 가이드를 너무 가리지 않는지 |
| 틀린 획 표시 0.9초 | 흔들리는 환경에서 무엇이 틀렸는지 알아볼 시간이 되는지 |
| 캔버스 최소 변 300pt | 엄지로 고리를 그릴 수 있는 크기인지. 장면 1에서는 す, 뒤 장면에서는 よ(8 료칸)처럼 고리가 작은 글자 |
| 375×667pt 화면의 세로 배치 | 쓰기 포인트 문구가 3줄인 글자(う, そ. 각각 6 이자카야, 5 축제)에서 캔버스가 얼마나 줄어드는지. 장면 1의 6자는 2줄 이하로 추정 |
| 시스템 글꼴의 가나 모양 | 장면 1의 す(고리), か(3획의 점) 등이 획 데이터의 모양과 눈에 띄게 다르지 않은지 |
| 아래 버튼과 캔버스 사이 12pt | 획을 아래로 빼다가 버튼을 누르는 일이 생기는지 |
| 단어 속 배운 글자와 안 배운 글자의 차이(`Ink`·굵게, `InkSecondary`·보통) | 28pt와 17pt에서 두 상태가 한눈에 구분되는지. 밝은 야외와 다크 모드 모두. 시스템 일본어 글꼴이 굵은 모양으로 그려지는지 |
| 장면 진입의 세로 배치(scene-flow.md 5.4) | 섹션 머리글 28pt, 섹션 간격 16pt, 세션 행 72pt가 실제로 그 높이인지. 375×667pt에서 2번째 세션 행이 걸쳐 보이는지(목표 단어 3개 기준) |
| 장면 진입의 세션 행 설명 줄(scene-flow.md 5.5) | "밥집 간판에서 보는 단어 6개를 읽어요"가 375pt 폭에서 한 줄에 들어가는지. 둥근 디자인은 한글 폭을 바꾸지 않지만 숫자 "6" 폭이 조금 다르다 |
| L1의 세로 배치(scene-flow.md 6.3) | 375×667pt에서 쓰기 포인트가 3줄인 글자(そ, う)가 스크롤 없이 들어가는지. 장면 1에서는 と, ん, か 초안이 실제로 2줄인지 |
| 캔버스와 화면 바탕의 경계 (`CardBackground` / `AppBackground`, 1.07:1, 외곽선 없음) | 밝은 야외에서 캔버스의 네 변이 보이는지. 엄지가 캔버스 밖에서 획을 시작하는 일이 생기는지. 보이지 않으면 캔버스에 `Outline` 2pt를 더할지 다시 본다(이 경우 5번 절의 모양을 바꾸므로 판정 영역과 겹치지 않는지 함께 본다) |
| 쓰는 중인 선(`Ink` 0.6)과 완성된 획(`Ink`) | 흔들리는 환경에서 손을 뗀 뒤 "맞아서 진해졌다"는 변화가 눈에 들어오는지. 따라 쓰기에서 가이드 획(0.22) 위에 그었을 때 쓰는 중인 선이 가이드와 구분되는지 |
| 시작점 번호 원(`Highlight` 노랑, 라이트에서 바탕과 1.7:1) | 크림 캔버스 위에서 노랑 원의 위치가 바로 보이는지. 숫자만 떠 보이지 않는지 |
| 지금 글자의 형광펜 바탕(`Highlight` 0.45) | 28pt 단어에서 지금 글자와 배운 글자가 바로 구분되는지. 라이트·다크 모두 |
| 크림 바탕(`#FDF5E6`) | 밝은 야외에서 흰 바탕보다 글자가 덜 또렷해 보이지 않는지. 화면 밝기 자동 조절이 낮을 때 누렇게 보이지 않는지 |
| 다크 모드 배경(`#1F1714`)과 캐릭터 | 캐릭터의 진갈색 외곽선과 그림자 타원(`#E8D4BE`)이 진갈색 바탕에서 어색하지 않은지. 외곽선이 바탕에 묻혀도 흰 밥 모양으로 알아볼 수 있는지. 어색하면 다크용 캐릭터 그림을 따로 만들지 정한다(지금은 SVG 한 장으로 두 모드에 쓴다) |
| 둥근 로마자와 보통 한글이 한 줄에 섞인 모양 | "su", "따라 쓰기 1/2", "밥집 간판 · 배우기 시작"에서 글꼴 차이가 어색하지 않은지 |
| 홈의 캐릭터 64pt와 늘어난 섹션 머리글 | 375×667pt에서 장면 행이 몇 개 보이는지(머리글이 약 44pt 늘어난다) |
| 완료 화면의 캐릭터 120pt와 등장 움직임(0.85 → 1.0, spring 0.35초) | 이동 중에 과하게 느껴지지 않는지. 성공 햅틱과 타이밍이 맞는지 |
| 카드 외곽선 2pt (선택지, 단어 카드) | 외곽선이 있는 단어 카드와 외곽선이 없는 획 데이터 글자 바탕이 L1에 함께 있을 때 어색하지 않은지 |
